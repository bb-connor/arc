## Code and dependency boundary

The production source contains no unsafe code, build script, filesystem or
network access, environment inspection, process execution, cryptographic
primitive or signature-verification implementation. It derives DER encoders
and decoders over `der`, `cms` and `cmpv2` types. The only production logic is
the type and field selection that defines the wire schema.

The request fixture parses an OpenSSL timestamp request and validates its
version, SHA-256 identifier, imprint and nonce. The response fixture parses an
OpenSSL timestamp response, CMS signed data and embedded `TstInfo`, then checks
status, version, policy, imprint, serial number, generation time, accuracy,
ordering, nonce, TSA name and extensions.

With current selected dependencies, the response fixture reaches and validates
all fields through the decoded TSA distinguished name, then fails its string
presentation assertion. Current `x509-cert` prints
`CN=Test TSA,O=Test,ST=Some-State,C=US`; the retained test expects the reverse
ordering and the long state attribute label. This is display behavior over an
already decoded name, not a DER, timestamp or signature failure. The exact
failure and selected-graph validation are retained under
`output/process-security-20260915/`.

A validation copy changes only that expected display string and removes one
needless borrow inside the test module. Both original tests then pass on the
selected graph, and strict Clippy passes for all targets with warnings denied.
The retained diff proves the production portion is unchanged.

## Limits callers must enforce

This crate parses and constructs data. It does not authenticate CMS content,
verify a timestamp signature or certificate chain, compare the response policy,
message imprint or nonce to a request, enforce algorithm policy, establish TSA
trust or determine freshness. A successfully decoded `TimeStampResp` is not a
trusted timestamp.

The `Accuracy` fields use integer types but do not enforce the RFC range of 1
through 999 for milliseconds and microseconds. Collection and integer size
constraints described by the RFC are not all represented by constructors.
Callers must reject semantically invalid values. These limits are explicit at
the Chio verification boundary and are not supplied by this data-model crate.
