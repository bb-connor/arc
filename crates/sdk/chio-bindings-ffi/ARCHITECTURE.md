# chio-bindings-ffi architecture

## Responsibility and boundary

This crate owns ABI adaptation for deterministic invariant helpers. Fourteen
exported C symbols provide version/build information, buffer release,
canonicalization, hashing, Ed25519 signing/verification, capability evidence,
receipt evidence, and manifest evidence. `ChioFfiBuffer` and `ChioFfiResult` use
`repr(C)` with pointer/length and numeric status/error fields.

The foreign caller owns input memory. Returned buffers transfer a Rust
allocation to the caller for later release through this library. There are no
callbacks, asynchronous handles, session objects, or retained borrowed inputs.
The same exports are available to Rust through the manifest's `rlib` output.

## Structure

All implementation and unit tests are in `src/lib.rs`. `cbindgen.toml` selects
exported symbols for `include/chio/chio_ffi.h`. The checked-in header is consumed
by the C++ SDK and regenerated by its validation script; Cargo has no header
build script. `tests/abi/chio-bindings-ffi.symbols` records the exported names.

`read_c_str` and `read_bytes` centralize input conversion. `run_ffi` maps helper
errors through `ffi_error_code_from_helper_code` and catches unwinding panics.
`ok_string` and `err_string` both allocate result data through a boxed byte slice.
`json` serializes structured helper results and build information.

## Data and control flow

A string entrypoint checks for null, constructs a `CStr`, and validates UTF-8.
The returned `&str` borrows caller memory for the rest of the synchronous call.
The byte-hashing entrypoint copies the supplied range into a `Vec<u8>` before
hashing. A zero length yields an empty vector without dereferencing the pointer.

Wrapped operations call `chio_binding_helpers`, then return either raw text or
serialized report JSON. Hashes and canonical JSON are raw UTF-8; wrapped
signature verification emits `true` only on success and an error result for any
refusal. Signing takes a registered schema id and returns
schema/canonical/public-key/signature JSON.
Receipt, capability, and manifest verification return their report objects.

Capability depth `CHIO_FFI_NO_MAX_DELEGATION_DEPTH` (`u32::MAX`) becomes `None`.
The trusted receipt entrypoint decodes `trusted_signers_json` as `Vec<String>`
and supplies it to `verify_receipt_json_with_trusted_signer_hex`.
`chio_ffi_build_info` returns crate/version, ABI 1, an architecture/OS label,
and an empty features array.

## Pointer ownership and threading

Null checks establish only the null-argument error case. The caller must ensure
C strings have a readable terminator in valid allocated memory and remain
unchanged until the call returns. Byte ranges must satisfy `from_raw_parts`
requirements, including a valid range length and absence of concurrent mutation.
Interior NUL bytes end a C-string input early; raw byte hashing accepts them.
The exported Rust functions have safe `extern "C"` signatures despite these
caller obligations; the implementation dereferences pointers in unsafe blocks.

`ChioFfiBuffer::from_bytes` transfers a boxed slice with `Box::into_raw`.
`chio_buffer_free` reconstructs that slice with `Box::from_raw` using the original
pointer and length. Foreign allocations, length changes, double release, and
access after release violate the ownership contract. Null or zero-length buffers
are ignored by the free function. Output bytes are length-delimited UTF-8 with no
added terminator; the caller may copy them before release.

Independent calls have no shared application state in this crate. Callers must
synchronize any shared input/output memory and ensure one owner releases each
buffer. No handle registry or lock mediates foreign memory access.

## Trust and errors

Statuses are OK 0, ERROR 1, PANIC 2, and NULL_ARGUMENT 3. Helper errors map to
named `CHIO_FFI_ERROR_*` integers; strict receipt JSON rejection maps to
`CHIO_FFI_ERROR_UNTRUSTED_INPUT` (29); an unregistered schema id, a signature
algorithm that differs from the key's, and a rejected signature map to
`CHIO_FFI_ERROR_UNREGISTERED_SCHEMA_ID` (30),
`CHIO_FFI_ERROR_SIGNATURE_ALGORITHM_MISMATCH` (31) and
`CHIO_FFI_ERROR_SIGNATURE_REJECTED` (32). Boundary UTF-8/null/panic failures use
INTERNAL (255). Error messages are allocated data with the same release rule.

`run_ffi` wraps fallible helper execution and serialization. Input reads precede
it. Hash functions call `ok_string` directly; deallocation also has no unwind
wrapper. `catch_unwind` handles unwinding Rust panics in its closure, while
undefined behavior, invalid pointers, allocation aborts, and aborting panics
cannot be converted into a defined error result.

Verification status OK means a report was computed. The receipt entrypoint
without trusted signers always reports `signer_trusted`, `ok`, and `authorized`
as false. Capability evidence has no issuer trust, request scope, revocation,
or durable admission inputs. Generic JSON canonicalization follows the helper's
Serde decoding behavior; strict duplicate rejection is specific to receipt JSON.

## Dependencies and verification

`chio-binding-helpers` supplies cryptographic and artifact semantics. `serde`
and `serde_json` encode reports/build metadata and decode trusted signer lists.
The manifest declares no features and disables publication.

Run `cargo test -p chio-bindings-ffi` for canonicalization, hashing, signing,
trusted-receipt, null/UTF-8/JSON/hex errors, error-code mapping, buffer mutation
and release, and symbol-snapshot tests. `scripts/check-chio-cpp.sh` also regenerates
and compares the header, checks compiled exported symbols, and builds the C++
consumer tests. Those checks require the script's C/C++ and cbindgen toolchain.
