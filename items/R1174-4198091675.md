**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Define a refusal for tracking enabled during execution**

When integrity tracking becomes required after `CheckOnlyDispatch` but before release, this branch mandates withholding because the no-write path cannot record the output join. However, `KnowledgeIntegrity` can still succeed when the current state satisfies the requirement, and the closed `OutputWithheld` reason set has no value for a missing join, so no typed refusal exists to trigger the receipt handling below. Define the refusal and its disposition explicitly (for example, map this transition to `InsufficientIntegrity`), otherwise an implementation must either emit a nonconforming receipt or risk releasing bytes without the required join.
