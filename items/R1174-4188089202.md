**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Preserve the parent cause across nested client responses**

When call X is waiting for a sampling or elicitation response, the client's response arrives as a new inbound envelope with its own sequence. This rule installs that new sequence as the cause while processing the message, but A1 routes X's eventual terminal response only when its cause still equals X's original slot sequence; no rule records and restores that parent cause for the nested continuation. The terminal response can therefore miss X's slot and leave the slot-owned request lock held indefinitely. Nested client responses must resume their parent call under the parent's captured cause rather than the response POST's sequence.
