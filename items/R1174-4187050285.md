**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Include StoreUnavailable in the cross-spec result set**

This authoritative cross-spec summary omits `StoreUnavailable`, even though spec 10's `CrossingResult` defines it for retry exhaustion, a poisoned owner, and a failed recovery fence, and spec 9 M19 relies on receiving that distinct event to retain the exact member and its holds. An implementation following this four-result contract must either map a storage outage to `Refused(Unavailable)` (which is reserved for an ineligible fused form) or retry indefinitely, bypassing M19's recovery behavior. Add `StoreUnavailable` to the result set here.
