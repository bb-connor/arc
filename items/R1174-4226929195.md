**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Distinguish check-only retries from durable replay**

When a check-only read executes but its release is refused by a stop, this sentence promises that retrying the same id returns the previously withheld output through a bound durable result. The check-only path instead writes no operation row and retains no output custody (spec 9 M11 and spec 10 X16), so the bytes were dropped and the reusable retry performs a fresh read whose value may have changed. Limit the durable-result replay promise to durable operations and describe check-only `AfterResume` as safe re-evaluation, otherwise clients or implementations can mistake a new observation for the original result.
