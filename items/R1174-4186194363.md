**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Key cooldown observations by the full stop epoch**

Fresh evidence after adding chain generations is that the cooldown table is still keyed only by `(scope_key, epoch)`. Because rollover resets `epoch`, a later generation can produce a stop with the same numeric epoch as an older incident; the insert can then collide with, or the resume check can read, the old `first_observed_at`, allowing `SamePrincipalAfter` to satisfy its cooldown immediately instead of waiting from the new stop. Include `chain_generation` in this row's key and in every lookup and comparison so an old observation can never authorize a new resume.
