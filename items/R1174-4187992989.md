**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Journal the termination before attempting its fence**

Fresh evidence after the prior fix is that this fsynced entry is created only inside the `If this persist fails` branch, so it cannot exist until after SQLite has already returned the failed terminal transition. A host crash in that interval leaves neither the terminal fence nor the pending file, allowing boot to restore the still-valid resume record and serve a session that was already terminated. Write and fsync `pending_terminal` before attempting the SQLite transition, then remove it only after that transition commits.
