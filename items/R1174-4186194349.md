**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Rotate the release key after proving non-acceptance**

Fresh evidence after the external-release reconciliation fix is the retry state after a definitive non-release: both a cached rejection under `IdempotentPerKey` and a successful `FenceByKey` fence return the hold to `Frozen`, but this rule requires every later authorization to reuse the same fixed `hold_release_key`. The idempotent rail will keep returning the original rejection, while the fenced rail must reject every later request carrying that key, so the hold can never be released even with new valid authority. After durably proving that the old request cannot execute, advance a per-hold attempt generation and derive a new key for the replacement release.
