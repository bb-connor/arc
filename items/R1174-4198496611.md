<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Rebasing invalidates observed end** When a second GET stream attaches, this rule replaces the persisted end event ID. A client that already received the end on an existing stream can then have its acknowledgement rejected because it carries the old ID. The spec says existing streams *may* receive the new end, but does not guarantee it. If the new stream disconnects before delivering it, the client has no valid ID to acknowledge, and the ended subscription continues to consume capacity. Preserve an acknowledgement path for an end already delivered to another stream.
