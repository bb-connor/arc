**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Align check-only retry advice with the refusal reason**

For a check-only release refused as `Revoked`, `AuthoritySpaceClosed`, or `InsufficientIntegrity`, this sentence still unconditionally returns `retry: AfterResume`. Spec 9 M11/M20 now classifies those exact refusals as terminal with `retry: Never`, because resuming cannot clear them, so the two normative specs prescribe incompatible receipts and clients following X16 may retry indefinitely after an unrelated resume. Make X16 use the same reason-specific retry mapping.
