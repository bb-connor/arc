1. **P1: Tenant comparison rejects valid local receipts.**  
   **File:** `2026-10-04-opaque-adapter-context-design.md:466`  
   **Claim:** Receipt `tenant_id` must equal the submission record’s `authenticated_tenant_id: String`.  
   **Evidence:** Both branches derive local namespaces using `"local-system"` (`chio-kernel/src/admission_operation/identity.rs:130-136`), but deliberately omit that tenant from receipts. See `chio-kernel/src/kernel/admission_coordinator/terminal.rs:2141-2143` on main and `:1522-1524` on integration. The proposed comparison therefore rejects valid local calls and replays. Specify the existing projection: `None` for local-system, otherwise `Some(tenant)`.

2. **P1: Pending approval assumes a nonexistent signed decision.**  
   **File:** `2026-10-04-opaque-adapter-context-design.md:483`  
   **Claim:** A signed `PendingApproval` decision leaves the submission unbound; line 462 also requires the response verdict to match the signed decision.  
   **Evidence:** `spec/PROTOCOL.md` §6.1 permits only `Allow`, `Deny`, `Cancelled`, and `Incomplete`. On both branches, `chio-kernel/src/kernel/responses/pending_responses.rs:37-67` signs a `Deny` with `threshold_approval.state = "approval_required"` while returning the separate `PendingApproval` verdict. The specified checks either reject this valid response or bind its denial permanently through line 484’s fallback. Define the projection from the existing signed metadata.

3. **P1: The same refused read receives contradictory identity dispositions.**  
   **File:** `2026-10-04-pure-admission-machine-design.md:603`  
   **Claim:** A check-only read refused at release by closure, revocation, or insufficient integrity is `Terminal`.  
   **Evidence:** M20, lines 715 and 729, explicitly assigns those exact cases `Reusable`, independently of `retry: Never`. Following line 603 makes the adapter permanently bind the submission under opaque-context line 476, preventing the later authorized retry M20 expressly permits. Keep `retry: Never`, but use `Reusable`.

4. **P1: The failure table permits an unsigned running head.**  
   **File:** `2026-10-04-durable-stop-epoch-design.md:917`  
   **Claim:** Signing failure for any rollover leaves its record committed and enforced with pending evidence.  
   **Evidence:** S38 at line 718 requires a rollover restating `Running` to sign inside its transaction and roll back if signing fails. Only stopped rollovers use commit-first signing at line 719. Following the table violates the signed-running-chain invariant at lines 731-734. Distinguish running and stopped rollovers in the failure table.

5. **P2: The overload receipt decision is stale.**  
   **File:** `2026-10-04-pure-admission-machine-design.md:1047`  
   **Claim:** This draft retains pre-admission overload errors without receipts and leaves signing undecided.  
   **Evidence:** M10 at line 570 already requires a signed overload denial, M20 at line 712 assigns `Reusable`, and line 1022 requires conformance coverage. Update the open decision to match those rules.

6. **P2: MCP-session guidance names an undeclared remedy class.**  
   **File:** `2026-10-04-integrity-gated-admission-design.md:666`  
   **Claim:** Integrity denials use remedy class `"run as a mediated process"`.  
   **Evidence:** I19’s closed enum at line 545 contains only `IntegrityEndorsement` and `QuarantinedContinuation`; lines 557-559 prescribe their requirement-based selection. The stated class cannot be encoded under that contract. Keep the phrase as guidance and specify the declared wire classes.
