**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Serialize notification POSTs with active request slots**

The temporal-correlation assumption does not hold for notification POSTs: the inspected handler at `crates/protocol/chio-mcp-remote/src/remote_mcp/http_service.rs:390-399` calls `session.send(message)` even when `try_lock_owned()` shows another request stream owns the lock. If that notification causes the server to emit a sampling or elicitation request, A1 routes it into the unrelated active request's `server_requests` queue merely because the slot exists. Serialize these POSTs too, or attach explicit causal slot identity to writer events instead of assigning every request emitted during the slot to it.
