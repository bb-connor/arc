**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Match retry advice to the actual release refusal**

When a check-only release is refused for `AuthoritySpaceClosed`, `Revoked`, or `InsufficientIntegrity`, this common no-row branch still returns `retry: AfterResume`, even though no stop need exist and a resume cannot clear any of those conditions. The `OutputWithheld` shape in spec 8 also permits only `KernelStopped` or `StoreUnavailable` as its reason, so the typed refusal promised here cannot be represented. Define reason-specific retry dispositions for these release failures, or make permanent failures terminal, rather than directing clients to wait for an unrelated resume.
