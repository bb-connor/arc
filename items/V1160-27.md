## Brief

**Finding.** Third-party external-guard responses are decoded with strict I-JSON canonicalization, so valid provider responses carrying ordinary floats are rejected

**Where.** `crates/guards/chio-external-guards/src/external/input.rs:16` (introduced by 377ee5b77)

**Scenario.** input::response (used by http_egress::response_json for Bedrock, Azure, Vertex, Snyk, Safe Browsing and VirusTotal, and directly for the VirusTotal 404 body) runs decode_external over the whole provider document. decode_external canonicalizes through StrictJson, which rejects any integer-valued float token (0.0, 1.0, 100.0), any integer above 2^53-1, and any fractional token that is not the shortest f64 rendering. The check also covers fields the guard never reads. These are unsigned third-party documents, the same class as the already-resolved A2A and api-protect cases that moved to document semantics. Plausible concrete cases:
- A VirusTotal /files/{hash} report from VT's Python backend that contains `"entropy": 0.0`, `"chi2": -1.0` for an empty PE section, or a TrID `"probability": 100.0`.
- A Vertex generateContent `avgLogprobs` double printed by protobuf SimpleDtoa as a 17-digit non-shortest value such as -0.13893578706140669.
Each yields InvalidResponse, which is retryable and counts toward the circuit breaker. With the default Deny verdict, benign hashes or prompts are denied and the breaker opens. With CircuitOpenVerdict::Allow configured, it opens and the guard is skipped.

**Evidence at fd8bfdc.** external/input.rs:14-17 `pub(super) fn response<T>(bytes) { UntrustedJsonText::from_wire(bytes, MAX_JSON_BYTES).and_then(|input| input.decode_external()) .map_err(ExternalGuardError::InvalidResponse) }`; http_egress.rs:88 `super::input::response(response.body())`; virustotal.rs:310 `http_egress::response_json(GUARD_NAME, resp)?`; canonical.rs visit_f64 rejects `is_integer_valued_f64(v)`; reject_if_over_precise_fractional rejects tokens whose significant digits differ from ryu shortest; chio-guards external/mod.rs is_retryable now includes `Self::InvalidResponse(_)`.
