**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Count successful outcomes as terminal receipts**

This set excludes successful `Allow` receipts because spec 9 explicitly emits `identity_disposition` only when the decision is neither `Allow` nor `PendingApproval` (`2026-10-04-pure-admission-machine-design.md`, lines 397-413). Consequently, the claimed per-replay-identity uniqueness property can still hold when an `Allow` receipt and a second terminal receipt both exist, weakening the exact-once proof and permitting contradictory audit outcomes. Include allow and other terminal outcomes directly, as the adapter-binding predicate already does, rather than relying solely on `identity_disposition = Terminal`.
