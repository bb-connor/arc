**Finding.** json_ingress::validate skips media types like application/json+x that axum's Json extractor still accepts, bypassing the duplicate-key and lossless-number checks

**Where.** `crates/platform/chio-control-plane/src/trust_control/json_ingress.rs:320` (introduced by 323316a99)

**Scenario.** A caller sends Content-Type: application/json+x to a contract route; public routes such as /v1/public/passport/challenges/verify have no auth step. is_json is false (the type is neither exactly application/json nor ends with +json), so validate passes the request straight to the handler without the original-byte duplicate-key and number checks. axum's Json extractor parses the MIME subtype as json with suffix x and accepts it. Duplicate keys inside Value or map members (receipt action.parameters, metadata) then resolve last-wins, and float spellings that Mode::Signed should reject reach typed decode. Impact is defense in depth: typed structs still reject duplicate struct fields, and signatures cover canonical bytes.

**Evidence at fd8bfdc.** json_ingress.rs:320-329 `lower == "application/json" || (lower.starts_with("application/") && lower.ends_with("+json"))`; :332 `return next.run(request).await;` when not JSON; mime 0.3 subtype() ends at the last '+' (application/json+x -> subtype json, suffix x); ingress_tests.rs:256 tests only application/vnd.chio+json.
