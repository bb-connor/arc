**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Persist terminal check-only refusals before burning the ID**

When a check-only release is refused for closure, revocation, or insufficient integrity, this marks the receipt `Terminal` even though this class explicitly has no operation row, tombstone, or custody record. A caller can resubmit the same replay key, and the kernel has no durable identity owner from which to replay or reject it, so it can issue multiple terminal receipts or later allow the same ID after policy changes, contradicting T14's one-terminal-receipt invariant. Either retain a terminal tombstone for these refusals or leave the identity reusable with reason-specific retry guidance.
