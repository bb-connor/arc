**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Persist the selection digest in recovery state**

`security_binding_digest` exists only in the signed deny-receipt block, while the native planner fact described here carries only `{ class, resolver_classes }` and explicitly never reads that receipt; the successor record likewise stores only the fault class. Capture step 3 therefore has no source for the original digest it is required to compare, so an implementation must either skip the check and permit a changed trusted selection or deny every such continuation. Carry the opaque digest in the native observation and predecessor record so missing binding evidence fails closed.
