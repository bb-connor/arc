**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Deny mismatched worker records instead of downgrading them**

When `worker_profile` names a launch record that differs from the runner's per-attempt record, rule 2 and the failure table require denial, but this rule groups a mismatched record with an absent or unavailable record and continues as an unverified `direct` worker. An implementation following this branch can admit ordinary worker calls despite inconsistent trusted launch evidence, rather than enforcing the specified mismatch check. Keep absence or lookup failure as an unverified claim if intended, but make an attribution or record mismatch deny.
