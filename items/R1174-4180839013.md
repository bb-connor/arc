**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Persist influence joins before check-only output release**

When `!mode.covers(ReadOnly)` selects this check-only path while integrity tracking is enabled, the release performs no authority write and only appends to `receipts.db`, so it has nowhere to commit spec 11's required output-influence join. An external read result can therefore enter the mediated context without tainting it, allowing a subsequent consequential call to pass against stale trusted state. Make such calls use an authority-writing outcome commit, or have the release atomically write the influence observation before delivering bytes.
