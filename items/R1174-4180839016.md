**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Define an integrity-specific fault payload**

An `InsufficientIntegrity` denial cannot satisfy both this definition and spec 2's closed fault schema: `AuthorityFaultV2` requires capability, subject, tool, parameter, and principal-path fields and projects a `Capability` fact, while I19 says this block contains only the requirement, surface, and remedy classes and I20 projects an `Integrity` fact. Merely adding a fifth enum variant therefore leaves no unambiguous serializable or planner representation, so integrity denials will either remain plain denies or violate the stated disclosure contract. Define a tagged integrity payload (or update spec 2's struct, classifier, and projection rules) before adding the class.
