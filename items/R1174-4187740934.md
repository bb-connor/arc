**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Classify AfterStoreRecovery receipts in M20**

When a post-effect check-only read encounters `StoreUnavailable`, this row now emits `Withheld { retry: AfterStoreRecovery }` as `Reusable`, but M20's supposedly exhaustive disposition table still classifies only `Withheld { retry: AfterResume }` and cites M19 for it. An implementation following M20 can therefore fall through to its “every other non-allow receipt is Terminal” rule, binding the request ID and preventing the retry that this row promises after store recovery. Add the new variant to M20's reusable row.
