<a href="#"><img alt="P1" src="https://greptile-static-assets.s3.amazonaws.com/badges/p1.svg?v=9" align="top"></a> **Abandoned reservation blocks other scopes**

If a resolver reserves a successor in scope A but never creates its workflow, the link remains `Reserved` with no owner. This new rule rejects a later authorized resolver in scope B as `Conflict`, while the only specified way to retire a link is to cancel an `Open` workflow. The abandoned reservation can therefore block a valid authority remedy in scope B indefinitely.
