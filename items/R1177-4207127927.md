**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Bind error codes to valid recovery metadata**

The error schema validates `code`, `retry`, and `operation_ref` independently, so it accepts contradictory responses such as `invalid_request` with `retry: "reconcile_original"`, or `outcome_unknown` with a null operation reference. Those combinations violate the protocol's recovery table and can either direct a client to reconcile a request that was never dispatched or leave a possibly dispatched operation impossible to recover; define per-code error variants or add semantic validation and negative fixtures that enforce the permitted retry class and operation-reference presence.
