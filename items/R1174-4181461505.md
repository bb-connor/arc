**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Allow a new receipt after retryable denials**

When the first attempt receives a temporary `KernelStopped` denial, this permanently binds the submission record to that denial receipt, but specs 3 and 8 require the same request ID and binding to remain retryable after resume. The successful retry necessarily produces a different receipt, so it fails `ReceiptAlreadyBound` and can never be lowered. Bind only terminal receipts, or explicitly allow a later receipt after a retryable denial while continuing to require the same sealed binding.
