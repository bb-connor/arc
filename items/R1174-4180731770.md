**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Bind the kernel response before constructing the verdict**

The separate kernel-response pairing remains unbound: on the inspected baseline, `verdict_result_from_response(invocation, response)` accepts those values independently, and this rule has the host compute the digest from whichever invocation it passes. If concurrent response B is accidentally paired with invocation A, the host stamps A's digest onto B's allow/deny decision and `lower_bound` recomputes the same digest, so the mismatch passes. Derive or verify the binding from the kernel response's signed request identity before constructing `VerdictResult`, rather than adding it afterward in the bridge.
