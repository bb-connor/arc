**Finding.** Proxy control-credential scan does O(header_bytes x token_len) constant-time work on every unauthenticated proxied request

**Where.** `crates/products/chio-api-protect/src/proxy/control.rs:109` (introduced by cca2117f8)

**Scenario.** With a sidecar control token configured (required for mediation), proxy_handler calls check_proxy_control_credential before anything else on every upstream proxy route, with no authentication and no rate limit in front of it. An attacker sends requests whose header values total just under MAX_CONTROL_HEADER_SCAN_BYTES (64 KiB). For every header value the code slides a window of the token length across every byte offset and runs a full subtle ct_eq (one black_box per byte) at each offset. With the maximum 512-byte token that is about 64K x 512 = 33.5M constant-time byte comparisons per request (about 2.8M for a 43-byte token). Each 64 KiB request therefore buys tens of milliseconds of CPU for the largest tokens and a few milliseconds for typical ones, far more than ordinary request handling costs. A modest request rate saturates the sidecar's cores and denies service to legitimate proxied and mediated traffic. The size budget bounds bytes, not the quadratic comparison work.

**Evidence at fd8bfdc.** control.rs:7 `const MAX_CONTROL_HEADER_SCAN_BYTES: usize = 64 * 1024;` control.rs:6 `const MAX_CONTROL_TOKEN_BYTES: usize = 512;` control.rs:109-116 `for value in headers.values() { for candidate in value.as_bytes().windows(secret.len()) { contained |= candidate.ct_eq(secret); } }`. router.rs:144-148 `if let Err(error) = check_proxy_control_credential(request.headers(), state.sidecar_control_token.as_deref()) { return error.into_response(); }` runs first in proxy_handler for every caller.
