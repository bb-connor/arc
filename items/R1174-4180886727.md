**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Recheck revocation before releasing tool output**

For an ordinary tool call whose capability is revoked after the effect executes but before its result is released, this `Revocation = no` entry allows `OutputRelease` to commit and disclose the bytes. That contradicts the existing release behavior documented in spec 4 and spec 9 M11's explicit post-effect `Revoked` transition to `DeniedAfterDelivery`; enable the revocation check here so the output remains mediated at the final trust-boundary crossing.
