**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Compensate hooks acquired before the fused intent**

When X10 is used for an operation-owned runtime hook, the hook acquires its reservation against `Prepared` before the fused transaction begins. If the remaining intent is then refused by closure, revocation, integrity, or a reservation conflict, M10 writes a `CompensatedBeforeDispatch` deny tombstone without emitting `Compensate`; the savepoint cannot roll back the already acquired external hook reservation, so repeated refusals can strand runtime capacity while the durable state claims compensation completed. Either keep this case on the slow path or explicitly release the hook before terminalizing.
