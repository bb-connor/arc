**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Refuse reservations after the origin is no longer eligible**

When the root or an earlier successor has already captured, or the predecessor has been cancelled, this allocation rule still appends a new `Reserved` link whenever no link is currently `Reserved` or `Open`. Creation or capture can only reject it later, leaving a useless reservation that occupies the sole active slot until an operator retires it; this also contradicts the conformance case requiring a captured predecessor or successor to refuse reservation. Check the predecessor lifecycle and the absence of any prior capture before appending a new link, while retaining exact readback for an already allocated attempt.
