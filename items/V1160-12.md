## Brief

**Finding.** Executor rotation stranding audit is bypassed by clear-then-set, leaving committed governed responses unresumable in-process

**Where.** `crates/kernel/chio-kernel/src/kernel/active_response_policy.rs:286` (introduced by b39b13127)

**Scenario.** Non-atomic setup path (no publish_governed_security_runtime). Executor A (generation 1) is installed and a governed active response reaches DispatchCommitted with its approval Committed, but the executor effect has not completed (crash or executor error). The operator rotates: deactivate_governed_active_response_plans(), clear_active_response_executor_authority() (sets active_response_executor = None), then set_active_response_executor_authority(B, generation 2). Because no executor is installed at that moment, the count_unresolved_by_authority audit that set_ performs for in-place rotation is skipped, and the in-memory generation floor becomes 2. enable_governed_active_response_plans() then runs recover_nonterminal_active_response_operations_progress with B's authority id. A's operation is refused as belonging to a different executor authority, so enable fails. resume_dispatch_committed_active_response requires the installed executor to equal A and refuses. A cannot be reinstalled because generation 1 <= floor 2. Result: active response cannot be re-enabled and the committed dispatch cannot be resumed until the process restarts and A is installed again. The design states rotation must not strand incomplete operations; clear-then-set defeats that check. Fail-closed, with no bypass, but committed effects stay unrecoverable in-process.

**Evidence at fd8bfdc.** active_response_policy.rs:286 `if let Some(installed) = self.active_response_executor.as_ref() { ... count_unresolved_by_authority(... installed.identity.authority_id()) ... if incomplete != 0 { return Err(... "would strand") } }` (audit only when an executor is currently installed); active_response_policy.rs:332-338 `clear_active_response_executor_authority` sets `self.active_response_executor = None` without any unresolved-operation audit; active_response_policy.rs:315-321 the generation floor must strictly increase and is never lowered; admission_cleanup.rs:745-749 `recover_active_response_item` refuses `belongs to a different executor authority`; active_response_committed_recovery.rs:403-410 resume requires `installed.identity == expected_executor`. The cold-restart gate `count_unresolved(kind)` (admission_cleanup.rs:59) is used only by `prepare_current_admission_authority_replacement` in the atomic publication path, not by set_active_response_executor_authority.
