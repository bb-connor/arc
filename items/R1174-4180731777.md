**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Cancel nested requests when their POST stream disappears**

When a tool is blocked waiting for a server-to-client sampling or elicitation response and the HTTP client disconnects, the POST stream drops the `server_requests` receiver while the session-owned completion task waits only for the terminal response. An ordinary disconnect does not cancel the session, and A2 defines local failure only for queue overflow, so the nested request can remain blocked indefinitely, leaving the credential call pending and the active slot unable to complete. Treat receiver loss like overflow by failing queued and future server requests locally, allowing the tool call and completion task to terminalize.
