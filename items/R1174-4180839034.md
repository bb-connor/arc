**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Do not compensate while the intent commit is still in flight**

If a driver future is dropped after it has enqueued an `IntentCommit` but before `DispatchCommitAcknowledged` arrives, this rule classifies the operation as pre-dispatch and immediately compensates it. Spec 10's writer owns and continues queued members independently of the reply waiter, so that intent can still commit afterward, leaving `DispatchCommitted` with driver-local reservations or quota already released under `PreDispatchNoEffect`. Track whether the crossing was submitted and treat this window as `CommitUnconfirmed` (or read it back) rather than compensating solely because acknowledgement was not observed.
