**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Include the subscription ID in end notifications**

When two subscriptions share a subject, or an end marker is rebased after restore, the client cannot use the promised logical identity `(subscription_id, reason)`: the specified `SubscriptionEnded` kind contains only `reason`, and the wire notification is only `{seq, subject, kind}`. Thus the persisted ID never reaches the client, so it cannot identify which duplicate subscription ended or deduplicate a rebased end as claimed. Carry `subscription_id` in the delivered end notification, or define an identity that is actually present on the wire.
