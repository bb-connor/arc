**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Decode unsigned A2A envelopes with document semantics**

For otherwise-valid JSON-RPC requests containing an ordinary noncanonical decimal spelling such as `0.50` or `1e-05` anywhere in their params, `decode_signed()` rejects the entire unsigned transport envelope because its number-token validation requires signed/canonical representation. This prevents interoperable A2A peers from dispatching valid JSON data; the bounded ingress should use the duplicate-aware document decoder while retaining strict decoding only for embedded signed authority objects.
