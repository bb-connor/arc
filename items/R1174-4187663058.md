**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Use a store-recovery retry condition for unavailable checks**

When a post-effect check-only read gets `StoreUnavailable` while the kernel is not stopped, this row returns `Withheld { retry: AfterResume }`, but no resume transition will ever occur and the read has no durable operation for `StoreRecoveryDriver` to re-feed. The only defined `OutputWithheld` form also gives `AfterResume` stop-specific semantics, so the client receives no valid condition under which to retry this otherwise reusable request. Add a store-recovery/transient retry disposition rather than reusing the stop-only value.
