**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Authenticate the v2 binding fields before stamping the verdict**

`delegation_permit_sha256` and `model_context_sha256` are supplied by the host in `InvocationBinding`, but none of these receipt checks authenticates either value, and rule 7 explicitly keeps the resulting binding digest out of the receipt. If a response produced under context or permit A is paired with the same invocation identity under B, every listed signed-field check passes and the constructor stamps B's digest onto both the verdict and result, so `lower_bound` accepts the mismatch and can release the output into the wrong model context or attribute it to the wrong sealed selection. Bind these optional digests into signed kernel evidence, or verify them against another authenticated field before constructing the outcome.
