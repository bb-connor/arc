**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Claim an issuance request before approving it**

When two authenticated approval requests reach the same pending row concurrently, both can pass this check and enter `execute_federated_issue`; after one consumes the challenge, the losing request can mark the row denied at lines 1713-1715 before the winner finishes issuing. The winner then fails its approved transition and returns 409 after issuance-side effects have occurred, leaving the inbox recorded as denied and the capability response unavailable. Atomically transition the row from pending to a processing state before consuming the challenge or issuing authority, and allow only that claimant to finalize it.
