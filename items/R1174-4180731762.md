**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Persist outstanding stop intents per scope**

When durable stop writes for multiple scopes are pending, this single logical two-slot record can represent only one `{scope, intended_epoch, ...}` intent. For example, after tenant A's stop returns `latch_only` under `SQLITE_FULL`, a stop for tenant B must either overwrite A's only crash-safe intent or be blocked indefinitely; if it overwrites and the process crashes, A reloads with a running durable head and no process latch. Store a keyed set or journal of outstanding intents and remove each entry only after that same scope's matching transition is anchored.
