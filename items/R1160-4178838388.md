**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Use the kernel authority clock for worker authentication**

When the kernel's configured authority clock is ahead of the host wall clock, this authenticates a bearer credential after the kernel considers its capability or credential expired because `now()` reads `SystemTime` rather than `self.runtime.authority_clock()`. Operations such as `Inspect` and `BlobRead` do not subsequently pass through kernel admission, so the stale credential can continue reading process state; the inverse skew also rejects otherwise-valid credentials. Credential issuance and every authentication check should use the same fallible authority clock as capability admission so clock disagreement fails closed.
