**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Rebase restored end notifications onto the new generation**

When a process crashes after persisting an `Ended` marker but before emitting it, `end_event_id` belongs to the previous incarnation, while A17 has already advanced the restored session to a new `g << 32` sequence range. Re-queueing that old id unchanged contradicts the monotonic restore scheme and can place it below the restored replay window; combined with H5a's rule that replay past `end_event_id` removes the marker, a client cursor from a later old-incarnation notification can make the unseen end appear acknowledged. Preserve a logical end identity for deduplication, but assign and durably record a transport event id in the restored generation before serving the session.
