**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Apply the selector check to endorsed calls**

The new endorsement branch checks only that the endorsed action belongs to `authorized_actions`; it does not require the bound inputs to produce that action through I22a's selector. Thus, when a tainted call has a valid endorsement and an action contract, it can execute a different authorized action than the typed return selects, even though this paragraph says the endorsement replaces only the level condition. Require the same `action_ok` input binding and selector check on the endorsement branch, while allowing the endorsement to bypass only `satisfies(state, requirement)`.
