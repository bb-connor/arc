**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Reconcile an external hold release before retrying it**

The new transient `Releasing` state still resolves an unknown release by treating absence of a local release entry as failure. For an external rail, however, `ReleaseHold` first prepares locally and then performs an external call, so a crash after the rail accepts the release but before the local completion transaction leaves exactly that absence; projection returns to `Frozen`, and a later `ReleaseAuthorized` can submit the release again. Preserve a durable submitted/unknown settlement state and require an idempotency key or authoritative rail query before deciding `Frozen` versus `Released`.
