**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Bound workspace storage and task output before execution**

For a sealed task that writes indefinitely or emits unbounded output, this step requires effective CPU, memory, and PID limits but never requires a task-scoped writable-storage quota, aggregate output cap, or refusal when either control is unavailable. Rootless container writable layers still consume host storage, so such a task can exhaust the filesystem used by owner state and receipts; the later ENOSPC recovery exercise detects the resulting outage rather than preventing the guest from causing it. Add independently observed storage/output limits and pressure negatives to the mandatory admission gate.
