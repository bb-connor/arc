**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Accept backend-neutral launch references for split-domain servers**

For a `split_domain` execution server running under the permitted Firecracker backend, rule 5.1.6 says the receipt carries only `confinement_launch`, but this verification predicate requires every execution-server call to have a verified `native_launch`. Such a deployment can satisfy S1-S5 yet can never produce `Verified(split_domain)`, so integrity admission starts it at `unknown` and denies gated calls. Make this predicate accept the backend-appropriate verified reference (`native_launch` or `confinement_launch`) rather than requiring the Linux-only field.
