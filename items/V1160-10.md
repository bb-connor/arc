**Finding.** chio-process: a host crash before dispatch commit (or a strict-nonce preflight outliving its 30s TTL) permanently denies the logical operation key although no effect ran

**Where.** `crates/kernel/chio-process/src/lib.rs:377` (introduced by fab96cb0c)

**Scenario.** ProcessRuntime derives the kernel request_id deterministically from (namespace, process, operation_key) and only moves to a new request identity when the kernel reports OutcomeUnknownAfterDispatch for a read-only tool (lib.rs:266-296, 533-549). Case 1 (any kernel in DurableAdmissionMode::All, which ProcessRegistry::open requires): a worker invokes key K; the kernel begins the durable operation (state Prepared) and runs guards, runtime admission, budget or payment authorization; the host is killed (deploy, OOM) before DispatchCommitted. On restart the worker retries K exactly as the protocol requires. The first evaluation runs reconcile_durable_admission_startup (async_evaluation_core.rs:355), whose recovery compensates every pre-dispatch state (recovery/operation.rs:51-58) to CompensatedBeforeDispatch. begin_durable_tool_admission_for_transport then sees an ExactReplay in a terminal state outside its allowed list and returns Err("request replay is retained in state CompensatedBeforeDispatch") (admission_coordinator.rs:789-801), which the evaluator turns into a signed Deny. outcome_unknown() is false, so invoke_with_recovery returns that Deny, and every later retry of K does the same. Case 2 (strict execution nonce): the first evaluation of K returns the preflight nonce, which is retained in process_call_nonces (lib.rs:509-526). If the host dies before the execution request commits dispatch and restarts more than DEFAULT_EXECUTION_NONCE_TTL_SECS (30s) later, the retained nonce is re-presented. route_durable_nonce_admission refuses it as expired while the operation is Prepared (admission_coordinator/execution_nonce.rs:172-178), or issue_durable_execution_nonce answers 'retained execution nonce expired; retry with a fresh request' (execution_nonce.rs:405-412). Startup recovery then compensates the Prepared operation and Case 1 applies. chio-process has no fresh request identity it can use for K. Result: a never-executed logical effect is permanently refused with a signed policy-style Deny that the worker cannot tell apart from a real authorization denial, and its tree_calls slot stays consumed. It fails closed, with no security bypass.
