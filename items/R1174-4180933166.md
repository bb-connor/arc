**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Handle errors that leave the batch transaction open**

X21 defines recovery only when `sqlite3_get_autocommit()` says the entire transaction is gone. If a non-refusal member error leaves the transaction active, there is no rule to roll back that member's savepoint or the batch, reply to its members, or poison the owner; continuing could commit part of a failed member, while stopping leaves the writer and queued stop requests wedged. Define the active-transaction branch explicitly and ensure no later member executes against an unrecovered savepoint.
