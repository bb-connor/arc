**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Reject cancelled tasks with unconfirmed stop state**

The shared task schema permits `state: "cancelled"` together with a running or unknown guest, unconfirmed admission stop, an unknown outcome, and required reconciliation. That contradicts the state contract, where `cancelled` is terminal only after admissions stop, the guest is absent, and every dispatched outcome is accounted for; accepting the contradictory projection can make clients show a false safe/cancelled status after a lost cancellation reply. Add a conditional semantic/schema check and a negative fixture for this combination.
