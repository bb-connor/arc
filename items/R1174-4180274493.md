**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Propagate failures from the discharge step**

`discharge` returns `()`, but rule 9 requires it to call the currently fallible `SecurityDispatchOutcomeHandle::record_released`, and `SecurityRelease` is explicitly a `PostEffectError` step. When that recorder fails after the receipt append, this API provides no way to route the error through `fail` or the post-receipt reconciliation path, forcing an implementation to discard the error or leave the security lifecycle inconsistent. Define an explicit fallible post-receipt outcome for `discharge` and its reconciliation behavior.
