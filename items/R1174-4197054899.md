**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Allow abandoned reservations to be retired**

When a reservation commits in scope A but `CreateWorkflow` never runs (for example, capability minting fails or that sibling scope is decommissioned), a later valid attempt in scope B always receives `Conflict`. O5 can retire only an `Open` link through `CancelWorkflow`, while this `Reserved` link has no owner or workflow to cancel, so it can never leave the sole reserved-or-open slot. This permanently prevents moving the authority remedy to another sibling scope; define an authenticated abandonment/expiry transition for `Reserved` links or another safe way to retire the stale reservation.
