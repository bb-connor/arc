**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Match the response verdict to the signed decision**

The constructor verifies the receipt signature and request identity but never requires `response.verdict` or its terminal state to agree with the receipt's signed decision. If the response envelope is corrupted or internally mis-paired so that a signed deny is presented as `Allow`, the later content check does not establish that the kernel authorized release, especially on the caller-executed path where `result_sha256` may be absent and the executor supplies the result. Compare the response verdict and terminal semantics with the signed receipt before constructing any `BoundOutcome`; a mismatch must deny.
