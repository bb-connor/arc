**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Give check-only crossings a true after-commit order**

The check-only tuple does not actually guarantee the claimed placement after the observed commit. For example, if commit sequence `N` belongs to batch member ordinal 4, the first check observing it gets `(N, 0)`, which sorts before the written crossing's `(N, 4)` under the defined tuple; ordinals can also collide because the two ordinal domains are unrelated. This can misclassify check-only crossings in the stop/fence ordering properties, so add an explicit before/after discriminator or use one unified ordinal space.
