## Brief

Found by the planner-side cross-vendor review of PR #1160 at fd8bfdc947bb (security reviewer): P2, plausible. The owner deferred it to after the #1160 merge (2026-10-09); fix it on integration/beta-next.

**Finding.** KeyringAuthoritySigningBackend reports a construction-time (possibly rotated-out) key when the router lock is poisoned instead of failing closed

**Where.** `crates/security/chio-keyring/src/router.rs:631` (introduced by 8741a02eb)

**Scenario.** KeyringAuthoritySigningBackend captures `fallback_public_key = router.active_public_key()?` once at construction. After a witnessed rotation (for example one performed because the original key was compromised), the router's active key changes but the fallback does not. If the router RwLock is ever poisoned (a panic while a write guard is held in stage_pending, activate_rotation_with_fence, or StagedPendingBackend::drop, all of which call into store and backend code), SigningBackend::public_key() and algorithm() silently return the original construction-time key via unwrap_or_else instead of surfacing an error. Signing itself fails closed (sign_bytes_* go through the poisoned router), but any consumer that treats `authority_backend.public_key()` as the current authority identity (issuer field, trust anchor, readiness or status reporting) is handed the stale, rotated-out key. Confirmation needed: a caller in trust-control or kernel composition that uses this backend's public_key() for a verification or trust decision; I did not find one in the files examined, so impact is unproven.

**Evidence at fd8bfdc.** router.rs:595 `fallback_public_key: PublicKey,`; router.rs:614 `let fallback_public_key = router.active_public_key()?;`; router.rs:624-628 `fn algorithm(&self) -> SigningAlgorithm { self.router.active_public_key().map(|key| key.algorithm()).unwrap_or_else(|_| self.fallback_public_key.algorithm()) }`; router.rs:631-634 `fn public_key(&self) -> PublicKey { self.router.active_public_key().unwrap_or_else(|_| self.fallback_public_key.clone()) }`; router.rs:484-485 `pub fn active_public_key(&self) -> Result<PublicKey> { Ok(self.read_state()?.active.public_key()) }` (errors only on poisoning); activate_rotation_with_fence replaces `router.active` under the write lock (router.rs ~576-578).
