**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Handle outcome-commit failures after dispatch**

After a tool returns, an `OutcomeCommit` can be refused by a stop, closure fence, reservation conflict, or version conflict while the machine is in `Finalizing`. M8 handles only pre-dispatch `CommitFailed` events, and no later rule defines this post-effect case, so M2 treats it as illegal and emits only `Retain`; after the refusal clears, nothing schedules another commit, terminal acknowledgement, or latch. Define reason-specific post-effect transitions that retry or reproject safely, or latch on unrecoverable persistence failure, so M11 is actually reachable.
