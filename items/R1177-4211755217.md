**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Block option parsing for untrusted helper arguments**

When a repository-controlled filename, URL, or label begins with `-` or uses tool-specific pathspec syntax, placing it in a literal argv still allows the invoked CLI to interpret it as an option; avoiding shell interpolation alone does not prevent this. None of Q14/Q17's listed negatives requires an option-looking operand, so an archive, Git, export, or opener helper can disclose unintended files or invoke dangerous option behavior while satisfying the documented rule. Require a verified `--` terminator or descriptor/stdin-based operand API for each helper and add leading-dash/pathspec negative cases.
