**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Bound retained submission records before sealing requests**

For a long-lived provider bridge receiving many distinct request IDs, every request is inserted into `SubmissionTable` before evaluation, and the retention rule requires durable records to survive for replay, with no table capacity, namespace quota, expiry, or garbage-collection rule. Sequential traffic, including permanently denied calls, can therefore grow the in-memory table and its persisted provider-correlation state without bound until the host exhausts memory or storage. Define a bounded admission quota and fail before evaluation when full, together with a replay-safe retention and reclamation policy.
