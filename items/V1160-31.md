**Finding.** PrepaidFinal payment journals settled before the upgrade can never be reconciled because reconcile now requires authorized_amount_units, which migration leaves NULL and a trigger forbids setting

**Where.** `crates/platform/chio-store-sqlite/src/admission_operation_store/participant.rs:537` (introduced by de519d777)

**Scenario.** A PrepaidFinal journal reached Settled on the previous schema but its budget reconcile/terminal projection had not yet committed when the store was upgraded. The payment_journal migration keeps authorized_amount_units = NULL for legacy rows and a trigger rejects later updates of that column. validate_payment_reconcile_binding previously used journal.amount_units for (PrepaidFinal, Settled, None) and now requires journal.authorized_amount_units, so every begin_payment_settlement retry fails with 'prepayment reconciliation requires its exact original debit'; the hold's exposure is never reconciled (budget capacity leak) and the admission operation can never terminate. Plausible: depends on whether upgrades with operations in flight between settle and reconcile are supported and whether another path completes them; the authors' migration test treats the NULL as intentional.

**Evidence at fd8bfdc.** participant.rs:533-541 '(PrepaidFinal, Settled, None) => journal.authorized_amount_units.ok_or_else(|| ... "prepayment reconciliation requires its exact original debit")'; origin/main used '=> journal.amount_units'; budget_store/composite_schema/payment/tests.rs:83 'legacy.authorized_amount_units, None' and :104-110 'UPDATE payment_journal SET authorized_amount_units=10 ...' is rejected.
