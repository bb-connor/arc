**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Recheck integrity on check-only release**

When an integrity floor or its installed policy changes after `CheckOnlyDispatch` but before result release, this second crossing checks only stop, closure, and revocation, even though the section 4.2 `OutputRelease` row requires an integrity check and X16 defines `InsufficientIntegrity` as a post-effect refusal. An implementation following X13a can therefore release output using the stale integrity decision from dispatch. Include `KnowledgeIntegrity` in this release recheck and withhold the result on failure.
