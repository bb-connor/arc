**Finding.** Terminal raw-payload compaction can wedge forever at one cursor: a verification-byte deferral after only unsupported/retained rows errors instead of committing progress

**Where.** `crates/platform/chio-store-sqlite/src/tool_outcome_store/payload_compaction.rs:322` (introduced by de519d777)

**Scenario.** Digest order after the cursor holds blob A then blob B, both past cutoff and owned by completed terminal operations. A's payload is read (inspected_payload_bytes += S_A) and classified Unsupported (no compacted-value replay support or unsupported owner profile), so nothing is compacted and the loop continues. B passes the payload-size check, but qualified_replay_owners adds B's owner verification bytes V_B and returns ByteDeferred because S_A + S_B + V_B > max_payload_bytes. Since page.compacted == 0 the page returns Err(Unavailable) and rolls back instead of returning next_digest = A. The control-plane maintenance loop keeps its cursor on Err and retries the identical page forever, so no blob after A is ever compacted and terminal raw-payload storage grows without bound (e.g. default 16 MiB cap, 9 MiB unsupported A, 1 MiB B with ~7 MiB of resolved output plus evaluation). The payload-size branch correctly keys on inspected_payload_bytes == 0; the ByteDeferred branch keys on compacted == 0.

**Evidence at fd8bfdc.** payload_compaction.rs:291-298 'page.inspected_payload_bytes = page.inspected_payload_bytes.saturating_add(size); ... if !raw.supports_compacted_value_replay() { page.retained_unsupported += 1; last_inspected = Some(digest); continue; }'; payload_compaction.rs:321-326 'ReplayOwners::ByteDeferred => { if page.compacted == 0 { return Err(ToolOutcomeStoreError::Unavailable(...)) } page.byte_budget_exhausted = true; break; }'; payload_compaction/eligibility.rs:56-63 total includes inspected_payload_bytes; chio-control-plane durable_admission/payload_maintenance.rs:452 'cursor = page.next_digest.clone();' only on Ok, Err arm leaves cursor unchanged.
