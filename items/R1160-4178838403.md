**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Clear stale ACP context when capability checking errors**

When a capability context already exists for a `(session_id, toolCallId)` and a later request reuses that ID but the checker returns an infrastructure error, this branch returns without the cleanup performed by `CapabilityGate::Block`. A subsequent `session/update` for that ID can then retrieve the earlier authorization context and attribute or sign the update as cryptographically enforced even though the current check failed; clear the request context before propagating every `CapabilityGate::Error`.
