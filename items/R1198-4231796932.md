**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Give non-PR runs unique concurrency groups**

For `push`, `schedule`, and `workflow_dispatch` events, this expression protects only the currently running job; the group remains keyed by `github.ref`. GitHub documents that a new run still cancels and replaces any existing pending run in the same concurrency group even when `cancel-in-progress` is false ([GitHub Actions concurrency documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)). Thus, if one main run is active and another is pending, a third run cancels the pending one, contrary to the intended guarantee that non-PR runs are never canceled. The same ref-keyed issue remains in the edited blocks of `chio-live-treaty-buyer-closure.yml`, `chio-treaty-bound-provenance.yml`, and `verdict-matrix.yml`; use `github.run_id` as the non-PR fallback in all four.
