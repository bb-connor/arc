**Finding.** Caller sibling-share snapshot fully decodes and verifies every non-terminal (and outcome-unknown) admission operation on each delegated dispatch

**Where.** `crates/platform/chio-store-sqlite/src/admission_operation_store/caller_budget.rs:24` (introduced by 7e54c14a6)

**Scenario.** ChioKernel::admit_capability_budget_for_dispatch calls load_durable_caller_budget_shares for every dispatch whose capability has a delegation chain, while holding budget_registry and the durable mutation lock. The store selects every row with terminal = 0 OR state = 'outcome_unknown_after_dispatch' (no parent filter in SQL) and, per row, runs load_by_operation_id_tx_with_history (operation JSON decode up to 256 KiB, latest-commit check, execution nonce reservation and issuance verification, caller dispatch context, native capture attachment, runtime/approval/DPoP participant checks, terminal projection checks) plus a retained-request decode, then discards rows for other parents. outcome_unknown_after_dispatch operations accumulate permanently, and there is no cap on in-flight operations. With N such rows every delegated dispatch costs O(N) heavy verification (aggregate O(N^2)) and serializes all admissions behind the locks; the output limit (16384) bounds only the result, not the work.
