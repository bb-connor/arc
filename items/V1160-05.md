**Finding.** New PR-triggered qualification lanes pull mutable container tags and unhashed PyPI dependencies

**Where.** `.github/workflows/process-workers.yml:343` (introduced by dd6734f74)

**Scenario.** A Docker Hub tag (python:3.11-slim, postgres:17.11) gets repointed, or a PyPI release in the unpinned chio-sdk-python[dev] extras is compromised. The new lanes then run that content in pull_request and push-to-main jobs. build_worker_image.py records whatever digest it pulled (trust on first use) instead of checking a committed digest, so the evidence artifacts these lanes keep ('qualification', 'receipts') describe an unauthenticated base. Impact is limited: these jobs hold only contents: read and no secrets, and no privileged job consumes their artifacts.

**Evidence at fd8bfdc.** process-workers.yml:343 and :627: 'docker --host unix:///var/run/docker.sock pull python:3.11-slim'. postgres-job-swarm.yml:82: 'docker pull postgres:17.11'. sdk-parity.yml:175: 'python -m pip install --disable-pip-version-check -e 'sdks/python/chio-sdk-python[dev]'' (no lock or hashes). examples/mini-swe-recovery/build_worker_image.py:21-23 reads RepoDigests from the pulled image rather than comparing against a pinned value.
