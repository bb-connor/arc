**<sub><sub>![P1 Badge](https://img.shields.io/badge/P1-orange?style=flat)</sub></sub>  Enforce the selected Keychain item attributes**

On macOS, these convenience APIs identify an item only by service and account and neither request nor verify the device-only Data Protection Keychain attributes required by the selected profile. An existing legacy, synchronizable, wrong-access-group, or weaker-accessibility item can therefore be accepted as the organization key, and newly created items are not proven to be non-migratable; this directly bypasses the refusal cases required in `docs/superpowers/plans/2026-10-07-macos-integration/IMPLEMENTATION.md:111-124`. Use an explicit Security framework query that sets `kSecUseDataProtectionKeychain`, disables synchronization, selects device-local accessibility and access control, then inspect those attributes on every read before signing.
