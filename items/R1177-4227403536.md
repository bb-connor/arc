**<sub><sub>![P2 Badge](https://img.shields.io/badge/P2-yellow?style=flat)</sub></sub>  Make key initialization create-only**

When two `chio key init` processes target the same previously absent reference, both can pass this read, generate different identities, and then write because the read and write are not atomic. For file references the later atomic rename replaces the first seed, while OS backends can overwrite or create an ambiguous duplicate; one caller can consequently publish a DID for a key that is no longer stored. Use a backend-level create-if-absent operation and return the winning stored key.
