\section{Implementation and evidence}
\label{sec:evaluation}
The Rust implementation connects the work contract to Chio's existing
delegation allocator, swarm-authority verifier, bilateral treaty admission,
native continuation custody, receipt exporter and funded settlement adapter.
The composed profile adds explicit binding checks at their handoffs. It uses
the existing capability and escrow mechanisms.

The evaluation has two source epochs: current native qualification for the
composed execution, and retained funded-model and comparison experiments at
their recorded revisions. The artifact binds each to its source inventory,
commands and outputs. All observed executions use author-controlled
infrastructure; the composed run uses separate receiver keys and stores on
one host, in-process treaty co-signers, a private development chain and mock
tokens.

\subsection{A program that grows after its first result}
The executable begins with a declared envelope of 300 units and a graph
containing a planning root, a survey task and an unstarted intermediary task.
The survey inventories an OpenAPI document's authentication declarations and
identifies an operation without required authentication. That actual result
triggers selection of an enrolled specialist. Only then are its task,
capability, sealed selection, funded agreement and 100-unit deposit created.
The checked graph grows from three nodes to four.

The intermediary invokes the specialist. A separately implemented Python
checker accepts the bound result, and escrow records the specialist's claim
as \textsf{Payable}. Before the intermediary's own return is captured, its
process is killed with SIGKILL. Its funding later refunds while its native
effect remains unknown. Parent and verifier rail signing are disabled.
The specialist's collector withdraws the original earned claim, then repeats
collection without another invocation or transfer.

Each receiver records one tool invocation and one native claim episode
containing its treaty and swarm continuation resources. Operation, allocation,
hold, authorization and physical claim identities remain unchanged through
reopen and collection. Starting from 2,000 total mock units, final balances are
buyer 900, intermediary 1,000, specialist 100 and escrow zero. Survey proceeds
accrue to the intermediary, which separately funds the specialist.

The first collection report retains an unavailable remote co-signer diagnostic.
A later open has no unfinished local operation to reconcile. Both reports
retain the same execution and payment identities. The observed result is
local completion and payment; final bilateral receipt delivery remains a
separate boundary.

\subsection{Adversarial and recovery checks}
The rejection cases use authenticated adversarial inputs. A validly re-signed
graph that changes an issued continuation is rejected. A sealed allocation
cannot select another invocation. Missing treaty evidence, a foreign
capability and a signed route to another receiver fail before funding
observation or native work. A deliberate removal of the receiver-route check
makes its regression fail for reaching funding observation.

Native tests also recover recorded tool output after process loss, allow
independent sibling progress, preserve original unfinished work through graph
extension, and reject a fresh request using a consumed continuation. Concurrent
graph extensions yield one committed successor. These cases exercise the
specific boundaries used in the preservation argument.

Current qualification completes 21 commands on an unchanged source inventory,
including the composed execution and four existing earned-child crash and
transaction-recovery cases. Six opt-in chain regressions are run explicitly
in addition to the default standalone suite. Appendix~\ref{app:evidence}
gives counts and source boundaries; the companion retains the command output
and the initial failed runs.

\subsection{What the comparisons establish}
The financial state machine is also implemented using ordinary SQL transactions.
It matches every compared state and balance along the retained representative
traces. A competent conventional implementation therefore has the same tested
monetary conservation and earned-child behavior.

The pinned upstream ERC-8183 implementation also pays a separately funded child
after parent refund and rejects overcommitment of the available reserve.
It additionally supports partial settlement, beyond this paper's fixed-price
profile. Chio's explicit \textsf{Payable} state preserves recorded acceptance
until a later withdrawal. These are lifecycle choices within expressive
settlement systems, not evidence of an exclusive economic primitive.

The composed experiment establishes the implemented connection between evolving
authority, native execution and an earned obligation. The authentication
inventory is deliberately easy to check: it measures protocol behavior rather
than an economic advantage in outsourcing that work.
