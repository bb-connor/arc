# External trial handoff

This is a ready-to-review experiment protocol, not evidence that the trial ran.
No participants have been contacted or enrolled by this work.
The user confirmed on 2026-10-02 that no partner is available yet. The
[operator handoff](trial/README.md), [trial manifest](trial/manifest.template.json),
[attempt record](trial/attempt.template.json) and [analysis contract](trial/ANALYSIS.md)
are prepared for recruitment and preregistration. Blank fields are deliberately
unfilled operator decisions, not invented trial observations.

## Decision to be tested

Does the public work contract let independently implemented and administered
participants exchange useful checked artifacts with less new integration and
recovery code than a competent ordinary composition at equivalent guarantees?
An outside run of the same binary is a reproducibility result. It is not an
independent provider implementation or a proof of lower integration effort.

The broader preregistration remains `docs/market/open-agent-work/06-independent-trial.md`.
Do not revise its thresholds after observing scored outcomes. Before execution,
record all deviations, exact source pins, implementations, operators, task split,
asset/finality profile, checker policy, fees and time budgets in a signed or
versioned trial manifest.

## Required roles and material

- Three separately administered core work operators, an additional newcomer,
  and a verifier independent of the exchange parties, as the original design
  requires. Record who can access each role's secrets and stores. The
  cross-border phase requires at least two actual jurisdictions.
- At least two independently written provider implementations authored from
  the public profile. Record shared libraries, decision-code dependencies and
  supplied assistance. Running our Rust binary under a new account is not a
  second implementation.
- Buyer-selected held-out useful source-repair work, an acceptance suite fixed
  before candidate outputs, and a separate buyer usefulness judgment.
- The same settlement rail, checker, models, budgets, hardware class and fault
  schedule for Chio and the competent ordinary baseline. The baseline may use
  OAuth or capabilities, extra signed fields, a durable workflow engine, escrow
  and a transactional database. Include pinned ERC-8183 as a commercial baseline.
- Dedicated development funds only unless operators separately approve a real
  deployment. Record transaction fees and locked-capital duration even for
  simulated amounts; do not interpret those amounts as commercial profit.

## Required executions

1. Valid output and payment, preserving the exact original identities.
2. Available invalid output and rejection/refund.
3. Missing custody and verifier outage, with no invented rejection or acceptance.
4. Duplicate submission, reordered response and response loss after durable decision.
5. Separate child acceptance followed by parent death/refund and child collection.
6. Competing obligations against the same backing, including a dishonest payer's
   forked local journal. The agreed funding authority, not the payer, decides.
7. Stale or reorganized settlement observations and disagreement between observers.
8. New partner onboarding from the published profile, with all assistance recorded.

For every run retain command, source/dependency hashes, selected trust inputs,
public signed artifacts, final native identities, rail events and terminal exit
status. Do not export private keys, private host requests or customer data.
Retain every attempted task and failure. Measure wall-clock integration hours,
new/changed semantic code, verification cost, production cost, capital duration,
operator interventions and usefulness; disclose learning and ordering effects.

## Acceptance boundary

An independent reviewer must be able to reconstruct who authorized execution,
which exact input/output/predicate was accepted, which allocation backed the
obligation, and which original terminal state resulted. Trial participation
and analysis do not imply public activation or a legal/financial endorsement.

The present native prototype remains an experimental W0 profile with fixed
mock-unit assumptions. Before this full trial, the integration record must
qualify actual off-host observers and endpoint configuration under the selected
profile. Do not present a same-host fixture as that missing capability.
