# Cross-Paper Consistency, the Paper Family, and Spec Alignment

Finder XREF, adversarially verified (all 23 findings survived, three adjusted in detail). The two papers describe the same artifact and claim the same gap, and disagree on almost every checkable detail. A program committee receiving both would not see salami-slicing; it would see one system paper and one shorter paper that refute each other.

## The six-paper family

- `reversible-action` is the "polity-layer construction" and "parent" that P2 and the other siblings cite. At HEAD it is a planning artifact: its Lean file does not elaborate against the proof root after the 2026-07-12 refactor, its headline theorem is `sorry`, and its header and body disagree on that theorem's name. (XREF-10, XREF-19, FORM-14)
- `sensor-grounded-admission` has a Lean file that elaborates cleanly but lives outside the proof root, is not built by `lake build`, and is not in the theorem inventory; its proof manifest declares a module path the file does not have. It cites a theorem name as a citation for an assumption the theorem does not mention. (XREF-19, XREF-22)
- `delegated-emergency-authority` states decidability without the finite-domain boundary P1 adopted. (XREF-22)
- The family cites the parent under three different titles, none of which is P1's HEAD title, and two family papers name the same cycle of the same venue. (XREF verifier note 2, XREF-23)
- The polity theorems the family leans on (`treaty_admission_iff_predicate_intersection`, `amendment_admissible_iff_backward_refinement`, `essential_preserved_chain`) exist in the proof root and are cited by no surviving paper; P1 deliberately dropped the polity triple, amendment refinement, and sovereignty claims in its July revision. (XREF-10)

## Where the normative spec is stale against the code

`spec/CHIO_BILATERAL_COSIGN_INVOCATION.md` (2026-05-04) diverges from the verifier in four places: it accepts two predicate URIs where the code accepts one; it says n-of-m envelopes carry n signatures where the code always requires exactly two; it lists two codes the code never emits (`consistency.anchor_unverified`, `consistency.quorum_underpopulated`) and omits three the code emits (`ladder.manifest_missing`, `ladder.manifest_stale`, `governance.unknown_action_class`); and its 17-step order is not the code's order. The `PredicateTypeUnrecognised` doc comment still describes two URIs one line above code that accepts one. `spec/CHIO_LADDER.md` section 6.3 rule 4 describes a fallback to the other side's default unmapped mode that the runtime does not implement; the runtime and `PROTOCOL.md` fail closed, and P1 matches the code. (XREF-11, XREF-12)

## Recommendation

P1 survives. Retire P2 as a paper. Merge into P1, after rewriting each against the code: the build-provenance versus admission-provenance framing sentence; the SCITT and COSE-receipt contrast paragraph; a corrected error-oracle discussion built on the real code-versus-message split (`VerifierError::code` versus `Display`); and the attack-by-construction table redone over `TreatyBindingRef` with the real codes. Add a glossary to P1 mapping each term to its code symbol and schema id (XREF-18). Update the spec to the shipped behavior and have the surviving paper cite the spec section and version. Write a family README under `docs/papers/` that names which theorems live in the proof root, which are paper-local, and which papers are retired.
