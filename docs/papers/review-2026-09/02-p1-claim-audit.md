# Paper 1 Claim Audit: Receiver-Owned Bilateral Admission

Paper: `docs/papers/programmable-sovereignty/` at HEAD `fe5657020c`. Finders IMPL1 (implementation and evidence pointers) and BENCH1 (measurement and reproducibility), each adversarially verified; plus the lead reviewer's own gate runs and a full benchmark reproduction on this host. Raw findings with verifier verdicts are in the appendix and in `findings.json`.

## Verdict

P1 is a real paper about a real path. Every manifest-listed source file, corpus, script, and result file still matches its recorded hash at HEAD; all nine named symbols exist and do what the paper says in the main; the 20-case negative matrix and the 50-fixture replay corpus pass at HEAD; the Lean theorems carry exactly the axioms the paper states. The paper's discipline (claim ledger, assumptions table, symbol-level manifest) is above the field's norm. It is nevertheless not submittable as it stands, for five reasons that are all fixable and all evidence-level rather than idea-level.

1. **The measurement record is two runs spliced together.** The committed PDFs and the claim ledger print numbers from a 26 July 2026 run on this Linux Neoverse-N1 host (11.124 ms p50 pre-dispatch denial). The retained result files, and therefore the inline TeX macros the sources now compile, come from a later MacBook Pro run (4.115 ms p50) whose environment file records Darwin, while the prose still describes the Linux server. The root cause is one commit, `0c01448309` ("bench(paper): refresh foundational merge evidence", 2026-08-01), which replaced the Linux run (producer commit `96ba1806ae`, whose numbers are exactly the ledger's and exactly the section 6 environment prose) with the laptop run (producer `3dfd241e67`) and truncated the environment record, while the ledger, section 6, and the abstract were never updated. The artifact gate never cross-checks prose against results, and at HEAD it fails anyway on `Cargo.lock` and `rust-toolchain.toml` drift. The lead reviewer re-ran the paper's own benchmark script on this host and obtained 10.4 ms p50 / 17.0 ms p99, which agrees with the July Linux numbers and not with the files the paper now compiles from. (BENCH1-01, BENCH1-02, BENCH1-03, BENCH1-04, IMPL1-05, IMPL1-06)
2. **The headline "full pre-dispatch treaty denial path" is an early exit.** The timed fixture signs a unanimous-deny policy summary. In `admission_hook/dsse.rs` the hook returns `chio_treaty_policy_denied` immediately after decoding the statement and checking the policy summary, before the treaty binding comparisons and before the call to `verify_chio_bilateral_dsse_envelope`. The timed body therefore never verifies an Ed25519 signature, never checks binding references, never produces an admission report, and never consumes the continuation. The number is a real kernel-through-SQLite measurement of a denial, but the abstract's description of what it includes is wrong, and it is a lower bound, not an upper bound, on the hook work an admitted call performs. The verifier raised this to a blocker because it is a false statement about what the headline benchmark measures, at the pinned commit as well as at HEAD. (BENCH1-09, BENCH1-10, BENCH1 verifier note 1)
3. **The statistics do not support the words used.** With 20 and 30 samples the reported p99 is literally the largest sample; component samples are Criterion batch means of unequal size, not per-invocation latencies; no mean, variance, or confidence interval is reported although Criterion produced them; run-to-run swings of 46 percent are visible in the retained July log. (BENCH1-07, BENCH1-08)
4. **Two implementation descriptions are misattributed.** Section 5 presents `verify_chio_bilateral_invocation` (peer pins, live manifests, revocation epoch, receipt store) as the receiver's pre-dispatch verifier; its only production caller is the offline buyer-package verifier. The pre-dispatch hook uses `verify_chio_bilateral_dsse_envelope` plus its own binding checks and never consults a peer pin set, ladder-manifest freshness, revocation oracle, or lease registry. Likewise "envelope cases call the strict verifier; store and policy cases call the admission hook" is false for six of the twenty matrix cases (three call pure validators, three call a partial verifier the code itself documents as non-conformant). (IMPL1-02, IMPL1-03)
5. **The fifth ladder mode is misnamed.** The paper says "quorum-required"; the spec of record and the federation crate say `maintenance`; runtime-core accepts `quorum_required` as an undocumented alias; the Lean model has only `quorumRequired`. The paper misnames a proof-linked constant, and the repository has a four-way naming split to resolve. (IMPL1-01, FORM-11, XREF-07)

Smaller precision defects (all confirmed): the continuation lifecycle is consume-at-admission and release-on-pre-dispatch-denial, with no separate reserve step (IMPL1-08); the request-metadata denylist does not contain a revocation-record key and unknown keys are ignored rather than denied (IMPL1-07); the admission-report digest in `VerifiedFederationTreatyMaterial` is substituted with the local value rather than compared (IMPL1-10); budget admission runs after the treaty hook, not before (IMPL1-12, HARN-07); the deny benchmark's runtime admission store is in-memory and only the receipt store is SQLite (IMPL1-11, BENCH1-10); `BilateralCoSigningError::code` is cited for failures that belong to `VerifierError::code` (IMPL1-09); no test pairs the real hook with a tool-invocation counter, only the benchmark does (IMPL1-13); the JSON admission store lets any admission release any consumed continuation, unlike the SQLite store (IMPL1 verifier note 4); four of the six envelope matrix cases exercise the compatibility signature-slice verifier rather than the strict cosign-invocation verifier, and only PS-TH-09 reaches `verify_chio_bilateral_dsse_envelope` (IMPL1 verifier note 3); the artifact check script runs the manifest check before the Lean rebuild, so at HEAD the README's Lean-archive rebuild never executes (IMPL1 verifier note 5); the production canonicalizer emits u64 and i64 magnitudes above 2^53-1 as exact integers rather than as doubles, a divergence from a strict RFC 8785 reading that the assumptions table should name (CRIT-03).

## What is true and strong at HEAD (and can be claimed)

- The hook parses only identifiers and hashes from the request context and resolves every artifact from `RuntimeAdmissionStores`; a fixed denylist of eleven trust-shaped keys inside the treaty context is rejected explicitly. Request metadata cannot install a trust root. (IMPL1-07)
- A continuation is consumed during admission by a single store operation (`INSERT OR IGNORE` on a `PRIMARY KEY continuation_id` table in SQLite), replay is denied, and release happens only on pre-dispatch denial or abort; when release fails the kernel retains the reservation fail-closed and records it in the denial receipt. (IMPL1-08, HARN-06, HARN-09)
- `VerifiedFederationTreatyMaterial` recomputes the request, participants, tool, and action hash at receipt construction; forged runtime treaty metadata cannot reach dispatch or the cosigner, and missing pins or stores deny pre-dispatch (kernel tests `federation_cosign.rs`, `chio_runtime.rs`, `durable_admission.rs`). (HARN-13)
- Budget admission runs after the treaty hook, so a treaty denial never charges the capability budget. This is stronger than the paper's ordering sentence. (HARN-07)
- The bounded predicate library limits (64 KiB, 1 KiB atom strings, depth 32, 1,024 nodes) and the differential suite (nine atoms enumerated, 1,024 proptest cases per property) are exactly as described. (IMPL1-14)
- The Lean theorems `finite_refinement_sound` and `finite_refinement_exact` exist, are `sorry`-free, depend only on `propext` and `Quot.sound`, and the paper's notation transcribes them faithfully. (IMPL1-18, FORM-09, FORM-17)
