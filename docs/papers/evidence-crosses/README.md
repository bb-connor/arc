# Evidence Crosses, Authority Does Not

Receiver-Owned Admission of Agent Tool Calls Within and Across Organizations.

## What this paper is

The foundational Chio paper. It states one rule and builds everything on it:
authority is minted and verified only inside the kernel that dispatches, against
roots that kernel activated itself, and nothing carried in a request can add a
root; only signed, content-addressed evidence crosses an organization boundary.

Its named primitive is the receipt, in two forms. Locally a receipt is the
kernel-signed, content-addressed record of one admission decision, written
durably before the caller sees a result and, when the exercised grant carries a
monetary cap, carrying what the call cost and who paid. Across an organization
boundary the same object is co-signed: a statement whose single subject is the
digest of a receipt the receiving kernel already holds, signed by exactly two
keys the receiver pinned before the request arrived, binding the agreement, the
request hash, and a single-use continuation. A cross-organization call is the
same admission operation with the peer kernel's receipt and co-signature
supplied as evidence, never as authority. The envelope is a pointer, not a
bearer credential.

The worked example carried through the paper is a buyer agent at one company
asking a vendor agent at another to stage a refund. Every digest, key
fingerprint, and byte count printed in the paper was read out of
`examples/chio-3vendor/fixtures/buyer-auditor-proof-package.json` (workflow
`wf-chio-refund-001`, skill `refund-underwriting`) and recomputed before it was
printed; digests are abridged to their first and last eight hex characters
everywhere. The normative wire contract is
`spec/CHIO_BILATERAL_COSIGN_INVOCATION.md`.

Sections, in order: the rule and the placement argument; threat model and
trusted base with the assumption table, once; the receipt; admission; cross-
organization admission as the same operation; security, with four definitions,
an executed substitution corpus over the fifteen binding fields, and revocation;
what is mechanized; evaluation; limitations.

## Build

```
make macros       # regenerate derived-macros.tex from the artifacts it reads
make build        # macros, then pdflatex, bibtex, pdflatex, pdflatex
make check        # check-log, check-bibtex, check-pages, check-words, check-macros
make words        # body word count over sections/
make clean
```

Gates:

- `make check-log` fails on an undefined control sequence, an undefined
  reference or citation, a TeX error, or an em dash (U+2014) anywhere in the
  source. It reports overfull boxes over 10pt as a note.
- `make check-bibtex` fails on any BibTeX error or warning and on a cited key
  with no entry.
- `make check-pages` fails if `paper.pdf` exceeds 10 pages, references included.
- `make check-words` fails if the body prose exceeds the word budget in the
  Makefile. The goal is under 5,000 words; the gate is set at the current
  budget so the text cannot grow without a paragraph paying for it.
- `make check-macros` fails if any derived count has drifted from the artifact
  it was read from.

Requires `pdflatex`, `bibtex`, `pdfinfo`, `detex`, and `python3` (TeX Live plus
poppler-utils), with `tikz`, `booktabs`, `longtable`, `listings`, `natbib`, and
`microtype`.

## Where every number comes from

No number in this paper is typed by hand. Timings come from macro files written
by the run that produced them, read by relative path and never copied here.
Counts come from `derived-macros.tex`, regenerated by `tools/derive-macros.py`
from the artifact each count is read from; the comment on each macro names that
artifact, and `make check-macros` fails if the file is stale.

| Input | Written by | Supplies |
| --- | --- | --- |
| `../programmable-sovereignty/bench/results/bilateral-admission-inline.tex` | `bench/run-bilateral-admission.sh` | host and toolchain description, the local cost decomposition of Table 4, sustained throughput, offline package verification, the in-process negative corpus size |
| `../programmable-sovereignty/bench/results/replay-corpus-inline.tex` | `bench/run-replay-corpus.sh` | bilateral and generic replay case counts |
| `../programmable-sovereignty/bench/results/federated-pair-inline.tex` | the cross-process federation experiment | admitted and denied latencies across two kernel processes, co-signing connection count, revoke-to-deny and cut-link-to-deny latencies |
| `derived-macros.tex` | `tools/derive-macros.py` | every count and configuration constant, plus the order statistics, poll counts, and disclosure counts read out of `federated-pair.json` |

The substitution table of Section 6 is the corpus
`crates/kernel/chio-runtime-core/tests/runtime_treaty_binding_substitution.rs`,
run by `cargo test -p chio-runtime-core --test
runtime_treaty_binding_substitution`. Its case count comes from that file and
its evidence identifier from the behavioral-test entry in
`../programmable-sovereignty/supplementary/artifact-manifest.json` that runs it,
both through `tools/derive-macros.py`, so neither can be typed wrong. The
generator also derives the denial experiment's share of the absorbed freshness
denials by subtracting the other two buckets from the reported total, and fails
if the three do not reconcile.

Three statements in the text are checks against those numbers rather than
restatements of them, and must be re-read after a re-run: that both revocation
medians sit under the bounds instantiated at one call and the median call
latency; that every observation, both maxima included, sits under the bounds
instantiated at the run's largest poll count and the admitted p99; and that the
durable receipt append dominates envelope verification (the ratio is computed in
the document).

Two caveats travel with the retained cross-process run and are stated in
Section 8: its environment record marks the worktree modified, because the
benchmark that ran before it had already written its result files, and its
request hop uses a transport defined for that experiment rather than a shipped
lane.

`local-macros.tex` holds the one value that is a word rather than a count.
