\section{Security}
\label{sec:security}

Four properties carry the protocol, each stated over the adversary of
Section~\ref{sec:threat} and reduced to an assumption in
Table~\ref{tab:assumptions}. All four are about the inbound statement, the
evidence a request presents about a receipt the receiver already holds; the
outbound one gates the response, never the dispatch.

\paragraph{Admission binding.}
\emph{If a receiving kernel dispatches under cross-organization admission, then
both keys the activated agreement pins signed the pre-authentication bytes of
the statement $S$ the request presented; every identifier and digest the
request presented resolved, in the receiver's own stores, to an artifact whose digest
the binding reference of $S$ names; every other leaf of $S$ the receiver
compares equals the value it computed for this request; two are bound
to a receiver-held set instead, the lease expiry to the instants strictly after
the receiver's clock and the lease issuer to the agreement's two participants;
and the continuation $S$ names was unconsumed when admission began.}
Suppose not. Each equality is byte equality between a digest the receiver
computed and one the statement carries, so a difference that passed means two
distinct objects share a SHA-256 image or a canonical encoding, contradicting
ASSUME-SHA256 or the injectivity of the encoder under ASSUME-CANONICAL-JSON. A
difference in a signature contradicts ASSUME-ED25519, and a continuation
consumed twice contradicts ASSUME-SQLITE-ATOMICITY. What remains is completeness
of the comparison set, which is the leaf enumeration of
Section~\ref{sec:formal}, not an assumption.

The property is over the hook, which decides live calls: its receipt binding
runs through the lineage bundle and the invocation record, not the statement's
subject, and a deployment that wants the subject digest checked before dispatch
runs the conforming verifier of Section~\ref{sec:cross} too.

\paragraph{Receiver locality.}
\emph{The roots, pins, agreements, action-class tables, and registries used to
decide a request are a function of the receiver's state before the request
arrived, and are independent of the request's content.}
Extraction reads a fixed set of key names and ignores the rest, and what it
reads are identifiers, each the argument of a total lookup over receiver-owned
state; the refused names of Section~\ref{sec:cross} make smuggled trust fail
loudly.

\paragraph{Single use.}
\emph{For a continuation identifier $c$, at most one admission ever reaches
dispatch with $c$ bound to it.}
Under ASSUME-SQLITE-ATOMICITY exactly one of any set of concurrent inserts on a
primary key creates the row; every other denies. Release deletes only the row
keyed by both $c$ and the admission that took it, and runs only before
dispatch, on the ordering of Section~\ref{sec:admission}. And $c$ is minted by
the receiver before the request and named by $S$, so the receiver, not the
signer, decides how many authorizations exist.

\paragraph{Audience binding.}
\emph{A statement accepted by receiver $R$ is not accepted by a different
receiver $R'$ unless $R'$ activated an agreement of the same identifier and
content, resolved the same intersection, and holds the same continuation
unconsumed.}
The receiver's identity enters through the continuation rather than the
statement's name for it: the continuation $R'$ resolved names $R'$ as its target
and both its kernels as participants of the agreement $R'$ activated, which has
exactly two, so $R'$ admits only as the second of them, under the key that
agreement pins.

\noindent
The whole-statement attack, another validly co-signed statement from the same
pair of kernels, is stopped by the continuation rather than by any digest: it
names one the receiver either does not know or has already consumed.

The report digest is not the only leaf compared against nothing the receiver
holds. The others are the statement's subject digest and timestamp, its
consistency anchor, both parties' policy identifiers and versions, and the
governance record's kernel identifier, digest, and digest algorithm. Each is
still held to a declared shape, and the qualification is part of the claim:
substituting one with a value of its declared shape moves no decision, while a
non-hexadecimal report digest and an empty policy identifier are denied. The
residual is additive as well: the optional halves of the lease scope digest and
the two policy rationale codes are permitted by the strict validator, never
validated and never read, so an adversary holding both keys adds them and the
receiver admits.

The window in which a statement can be presented is the intersection of the
lease, governance, and continuation intervals the receiver itself resolved, each
revocable and re-scoped per counterparty between calls rather than one constant
applied to every authorization, and after the first dispatch it is zero.

\paragraph{Revocation.}
Revocation is the only part of this protocol that depends on something
arriving. Each origin publishes a signed root carrying a monotone epoch counter
and an issue time, and a kernel installs a snapshot only if its epoch strictly
exceeds the installed one, by compare-and-swap, so a replayed frame cannot take
effect and a concurrent install cannot be lost; it then applies its own
freshness window to the issue time before trusting it. Safety holds
unconditionally, in every partition, because both halves are local predicates
that never wait for a message: no call is allowed against a revocation the
kernel has observed, and a call evaluated against a stale snapshot is denied.

Liveness holds only under ASSUME-GOSSIP-FAIRNESS-PARTITION-BOUND, and it bounds
the time before a revocation is observed, not the number of evaluations, which
is unbounded. Let $F$ be the freshness window, $T$ the origin's control-poll
period, $L$ the latency of one admitted call, and $k$ the number of calls made
before one is decided against the newer snapshot. A still-connected receiver
denies no later than $T + kL$ after publication, and a cut receiver no later
than $F + T + kL$, because its snapshot must first age past $F$. With
$F = \PSFreshnessMs$\,ms, $T = \PSEpochTickMs$\,ms, $k = 1$, and the median $L$
of Section~\ref{sec:eval}, those are
\fpeval{round(\PSEpochTickMs + \PSFedAllowPFiftyMs, 1)}\,ms connected and
\fpeval{round(\PSFreshnessMs + \PSEpochTickMs + \PSFedAllowPFiftyMs, 1)}\,ms
cut.
