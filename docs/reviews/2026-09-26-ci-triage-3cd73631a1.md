## Regression A: caller-return-context schema left at v4 in two pinning tests (steps 2 and 5)

Commit `3cd73631a1` edited
`crates/kernel/chio-kernel/src/kernel/admission_coordinator/return_context/caller.rs`:

```
-const SCHEMA: &str = "chio.kernel-caller-return-context.v4";
+const CUSTODY_SCHEMA: &str = "chio.kernel-caller-return-context.v4";
+const SCHEMA: &str = "chio.kernel-caller-return-context.v6";
```

The write path (`:245`) emits `SCHEMA` (v6); the validation ladder (`:372`) still
accepts `CUSTODY_SCHEMA` (v4) as a legacy variant. That part is internally
consistent and reads as intentional: v5 is reserved for the separate
`NATIVE_CALLER_CONTEXT_SCHEMA` native-custody path, so skipping to v6 avoids a
collision. What the commit did not touch: two write-then-read round-trip tests
that pin the literal, unchanged since `2c5188e8ada` (2026-09-12):

- `crates/kernel/chio-runtime-core/tests/runtime_admission/operation_owned/caller.rs:91`
- `crates/platform/chio-store-sqlite/tests/execution_nonce_caller_execution/dispatch_context.rs:68`

A third literal at
`crates/platform/chio-control-plane/src/security/adapters/native_flow_caller_tests.rs:355`
is a deliberate tamper fixture asserting that a payload carrying the old tag is
rejected; it is unaffected.

**Reproduced locally on aarch64**, identical panic, values and exit code 101:

```
export CARGO_TARGET_DIR=/home/connor/chio-lanes-target CARGO_INCREMENTAL=0; umask 022
cargo test -p chio-store-sqlite --test execution_nonce_caller_execution -- dispatch_context::caller_report_retains_typed_private_context_with_capture_and_exact_restart_replay --exact
cargo test -p chio-runtime-core --test runtime_admission -- operation_owned::caller::caller_context_retains_exact_runtime_episode_and_released_predecessor_after_restart --exact
```

**Disposition.** These are pinning tests and they did their job: an intentional
wire-format change must be acknowledged where it is tested. The fix is to update
both literals to v6 deliberately, and to add one test in `chio-kernel` beside the
constants asserting `SCHEMA` is v6 and `CUSTODY_SCHEMA` is v4, so the bump and
the reserved v5 are recorded where the change was made. The lane's suggestion to
assert against an exported constant would make the pinning tests tautological for
the value they exist to pin, so it is not adopted.

## Regression B: racy process-identity test (step 1)

`integrations/required-agents/` is new relative to `main`. The gate line entered
`ci.yml`'s structural-gates step in `f6c95de3513` (2026-09-10). The test at
`test_prepare_session_readiness.py:198-211` spawns `/bin/sleep 10`, sleeps a fixed
50 ms (`:205`, from `3fee66e397d`), then calls `check_process()` expecting success
at `:206` before a deliberately wrong-argv call at `:208` is checked with
`assertRaises`. CI's traceback is at `:206`, the success path.

**Reproduction.** 40 single-test runs and one full 65-test run under `umask 022`
on this host: 41 of 41 passed. Not reproduced deterministically.

**Disposition.** The most defensible read is a scheduler-timing race: if the
`/proc` read lands between `fork` and the child's `execve` completing, `exe` still
points at the parent and the identity comparison legitimately fails. Replace the
fixed sleep with a bounded poll (retry `check_process` for up to about one second
with a short interval), and add a unit test of the poll that injects a probe which
fails a fixed number of times before succeeding, so the retry path is exercised
rather than hoped for.

## Step 6, corrected on a second read

The step's displayed source shows GitHub Actions' pre-resolved `${{ needs.X.result }}`
values as literal `test 'failure' = success` lines for steps 1 to 5, which reads
as a pure cascade. That block is the source preview, not the execution trace. The
first executable statement is
`[[ "${COMMITTED_LINUX_EVIDENCE_SHA}" =~ ^[0-9a-f]{40}$ ]]`, sourced from
`vars.CHIO_COMMITTED_LINUX_EVIDENCE_SHA`. An empty value aborts the script under
`set -e` before any `test` line runs (confirmed by local shell test), and the
variable is not configured on the repository (a user account, so no organization
scope to fall back to; the job has no `environment:` key). The whole
`security-contract-required` job is new to this branch (`8be503269eaf`).

Classified as a Packet 5 prerequisite rather than a third regression because the
variable name and the PR's own "Remaining gates" text point at the same
not-yet-operational trusted-capture and evidence pipeline that blocks step 4,
tracked by #1167 and #1168. That is an inference. Whoever owns Packet 5 should
state whether the variable is meant to be populated now or later.
