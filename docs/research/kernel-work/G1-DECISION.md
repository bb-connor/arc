## Primary metric and acceptance bar, fixed before measurement

Primary endpoint: median paired ratio of hands-on repeated integration time
(Chio / strongest equally provisioned reusable alternative) across the existing
six paired exercises spanning support/publication and confined-research/bounded-
return families. Required important effect: ratio <= 0.50. Preserve at least
95% of scheduled recoverable incidents resolved without database edits or bespoke
repair code. These thresholds are unchanged from G0/H3.

Safety, allowed progress, work quality, provider semantics, administrative
independence and trust must match. Record initial platform effort separately;
include adapter work, assistance, training, failed attempts, porting, repair and
amortized baseline libraries. Counterbalance arm order. Report all six pairs and
uncertainty; six trials do not alone establish broad statistical generality.
No lines-of-code, predicate count or local runtime benchmark substitutes for this
primary endpoint. No time measurements from authoring this lab qualify.

H2 remains verification/production cost median <= 0.10 and p90 <= 0.25, with
the lower 95% success-difference bound >= -5 percentage points. H4 remains the
original useful-purchasing comparison with direct/fixed-supplier controls in
[the existing trial](../../market/open-agent-work/06-independent-trial.md).
They are not measured or closed by Task 4. No new favorable threshold may be
chosen after results. Native/second-family/independent work belongs to Tasks 5-6.

## Task 4 experiment specification

Purpose: determine whether the proposed reusable rule frontier actually preserves
the specified safety and useful progress on KW1 and whether B1 attains the same
outcomes. A parity result is expected and must be reported. This is prerequisite
mechanism evidence for R3, not a claim that parity establishes a breakthrough.

- Inputs: the exact [52 variants](fixtures.json), owner-authenticated environment
  updates, command proposals and separately injected transport faults. Numeric
  identities are uninterpreted symbols; no cryptographic implementation claim.
- State: three owner-local operation records, exact approval basis, monotone
  knowledge, typed dependencies, disjoint 10-unit execution partitions and
  independently backed obligations. An external oracle holds physical counts.
- Outputs: decisions, advisory statuses and public state. Oracle counts are
  inspected by assertions only, never by candidate or baseline decision APIs.
- Candidate: assemble named obligations per command, returning all failed rules;
  execute through the shared native-specification port only after admission.
- B1: conventional direct service guards, independently written decision logic,
  with the same original-identity, IFC, dependency and funding facts. No disabled
  mechanism, no shared candidate decision function, no artificial global freeze.
- Shared trusted adapter: deterministic state updates after permitted commands,
  custody/readback, nonce consumption, append-only observations, qualified
  transport response and monetary ledger operations. Sharing these supplied
  axioms avoids pretending to rebuild PR #1172. It also limits differential
  evidence: a shared reducer bug can affect both, so fixture and oracle assertions
  are independently specified and checked. This is not two native deployments.
- Controls: deny effectful commands (must lose F01 useful completion); retry a
  captured unknown operation (must produce two effects in F05's applied history).
- Removal experiments: candidate-only loss of all-owner coverage, one-send memory,
  backing disjointness, typed dependency lifetime, or historical-settlement
  separation. Each must fail a named fixture while its intact positive case passes.
- Exploration: all words of length <= 5 over explicit finite command alphabets
  for concurrent funding/admission, crash/reopen, stale epochs, duplicate sends
  and contradictory evidence. Longer directed fixtures cover the full workflow.
  Preserve alphabets, exact counts, first concrete failing trace, source hashes
  and terminal exit codes. No randomized search disguised as exhaustive checking.
- Assertions: all F01-F16 final expectations and per-command decisions; every
  accepted effect must have preceding captured authority, physical count <= 1,
  retained knowledge, exposure <= 10, backing <= wallet and earned claims retained.
  Compare both arms' visible states after each explored transition, not just totals.
- Costs: report bounded predicate work and retained state/history size for context.
  Report paired safety/progress/uncertainty outcomes together. These are diagnostic
  counts, not economic or performance superiority evidence.
- Proof scope: execute finite trace checking and the explicit indistinguishability
  pair; no arbitrary-trace theorem is central or asserted, so no ornamental Lean
  arithmetic proof. No production Rust correspondence is claimed.
