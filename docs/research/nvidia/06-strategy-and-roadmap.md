# Strategy and roadmap

This document sets Chio's strategy toward NVIDIA's agent safety stack and turns it into a dated plan. It gives the verdict on the positioning thesis, the positioning itself, and what to integrate, evolve, compete on and build alongside. It then names the target customers and the standards work, and lays out a phased roadmap with acceptance and exit criteria. The later sections cover documentation changes, ADR candidates, risks, decisions for the founder, claim-boundary cautions and open questions. It is written for Chio maintainers and stands on its own.

## Conventions

### Status labels

Statements about NVIDIA, OpenShell, ODIS, partners, competitors or standards carry one label the first time they appear in a section.

| Label | Meaning |
|---|---|
| VERIFIED | Primary source read on 2026-09-28 to 2026-09-29; some repository states are dated 2026-09-29 UTC. A vendor's statement about its own product is VERIFIED as a statement. Behavior observed in the local test of OpenShell v0.1.2 on 2026-09-29 is marked VERIFIED, local test. |
| REPORTED | Secondary source, not independently confirmed. |
| INFERRED | Our reasoning from cited evidence. Ratings, predictions and estimates are INFERRED. |
| PROPOSED | A design, draft, reference design, roadmap item or announced plan that is not built. Future release dates a vendor announces are PROPOSED. |

Statements about Chio carry the repository's four claim-boundary labels.

| Label | Meaning |
|---|---|
| qualified | Named in `docs/release/QUALIFICATION.md` or approved with scope in `docs/reference/CLAIM_REGISTRY.md`. |
| shipped | Code on `main` that builds and has tests, outside the qualified boundary. |
| design doc | A design, proposal, specification draft or paper with no implementation. |
| roadmap | Stated direction in a document, with no design behind it. |

Two narrower forms of shipped are also used. **test only** marks code on `main` whose only callers are tests, fixtures or offline tools. **branch only** marks code on an unmerged branch, not on `main`. [02-chio-today.md](02-chio-today.md), [04-integration-design.md](04-integration-design.md) and [07-ideas-backlog.md](07-ideas-backlog.md) spell these test-only and unmerged.

Every task, demo, ADR candidate, date and estimate in the plan is roadmap unless a row says otherwise. Code in the separate `backbay-labs` plugin repositories is described in words (merged, released, accepted), not with these labels. Quotations of repository wording carry no label. "Not documented" means the sources read say nothing on the point.

## 1. Executive summary

- Chio should enter NVIDIA's stack as the delegated-authority and evidence layer behind OpenShell's two extension seams, not as a kernel above the runtime (INFERRED). The seams are supervisor middleware and gateway interceptors. Both RFCs are accepted, but NVIDIA labels middleware a research preview (VERIFIED, OpenShell@acbac9c [`rfc/0009-supervisor-middleware/README.md:4`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/rfc/0009-supervisor-middleware/README.md?plain=1#L4), [`rfc/0010-gateway-interceptors/README.md:4`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/rfc/0010-gateway-interceptors/README.md?plain=1#L4), [`examples/supervisor-middleware-content-guard/README.md:9`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/examples/supervisor-middleware-content-guard/README.md?plain=1#L9)). Issue [#3307 (2026-09-14)](https://github.com/NVIDIA/OpenShell/issues/3307) proposes replacing the middleware's unary request call without an adapter (VERIFIED as the issue's text; the change is PROPOSED).
- The planned Chio middleware checks each request to a Chio-bound endpoint against a sandbox-bound capability's argument constraints, invocation counts and expiry (roadmap). It fails closed and signs a receipt with three outcome states. The planned Chio interceptor binds each sandbox to that capability inside OpenShell's own policy hash (roadmap). It refuses widening on every mutating control-plane call it can intercept.
- Argument checks are the delivery vehicle and the week-one demo, not the priced product. OpenShell does not match MCP tool arguments (VERIFIED, OpenShell@acbac9c [`docs/how-it-works/policies/schema.mdx:347`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/how-it-works/policies/schema.mdx?plain=1#L347)). ## 2. Thesis verdict

### Why the kernel tagline fails

The tagline "the authority kernel for autonomous systems" does not hold, for three reasons.

1. NVIDIA's Secure Agent Workspace (SAW) reference design says the agent's authority is a policy-defined subset of the sponsor's permissions, "never a separate authority", evaluated "centrally at the runtime layer" (VERIFIED, [SAW enterprise tool access model, last updated 2026-06-28](https://docs.nvidia.com/enterprise-reference-architectures/secure-agent-workspace-reference-design/latest/enterprise-tool-access-model.html)).
2. Microsoft's launch blog for its Agent Governance Toolkit (AGT) calls the toolkit's Agent OS policy engine "the kernel for AI agents" (VERIFIED, [Microsoft open source blog, 2026-04-02](https://opensource.microsoft.com/blog/2026/04/02/introducing-the-agent-governance-toolkit-open-source-runtime-security-for-ai-agents/)).
3. NVIDIA is staffing an Agent Policy Fabric (APF) whose planned scope covers most of a single-organization authority kernel (VERIFIED as the text of [NVIDIA job post JR2019848, posted 2026-06-22](https://jobs.nvidia.com/careers/job/893395763513); the scope is PROPOSED). The post lists signed policy bundles, a Runtime Policy Verifier, revocation checks, subject binding to attested runtime context and projection into OpenShell policy. A prototype issuer, `apf-bundle-issuer`, is public in the ODIS contract harness (VERIFIED, ODIS@148dc41 [`contract-harness/README.md:163`](https://github.com/cosai-oasis/ws4-odis/blob/148dc4187139a41325e3c6d6e7533d956bd33144/contract-harness/README.md?plain=1#L163)). NemoClaw ships an experimental `--apf-interceptor` mode (VERIFIED, [NemoClaw external components, main, 2026-09-28](https://github.com/NVIDIA/NemoClaw/blob/main/docs/deployment/register-external-component.mdx)).

The narrowed positioning claims only what Chio can show at a runtime's own extension points. It names the part none of the three occupies today: authority that can only narrow, carried with receipts that a party who does not run the gateway can verify (INFERRED). "Kernel" stays as the name of a Chio component. It is not used as the category in NVIDIA, SAW or ODIS contexts.

### The narrowed thesis and five corrections

The narrowed thesis: Chio carries portable, offline-verifiable authority lineage, budgets and receipts across runtimes and organizations. It does so on an ODIS-compatible carrier, behind OpenShell's chokepoints. It does not sell per-call policy evaluation and does not issue identities (INFERRED). It holds only with five corrections.

|---|---|---|---|

### Where the moat is, and is not yet

Budgets that survive delegation hops, and verification by a counterparty, are where Chio's position would become a moat (INFERRED). Both are destinations, not current differentiators. The claim that no shipped competitor combines them does not hold:

- AGT combines cost budgets with JWKS-based cross-organization federation, though its budgets are partly warn-only (VERIFIED, [microsoft/agent-governance-toolkit, read 2026-09-28](https://github.com/microsoft/agent-governance-toolkit)).
- Microsoft's unsupported Azure `kars` reference stack wires token budgets to a cross-organization A2A surface (VERIFIED, [Azure/kars, read 2026-09-29](https://github.com/Azure/kars)).

Chio ships neither half today:

- Budget stores report only `SingleNodeAtomic` or `AdvisoryPosthoc`. No backend returns `HaLinearizable` or `PartitionEscrowed` (shipped, [`budget_store/model.rs:387-392`](../../../crates/kernel/chio-kernel/src/budget_store/model.rs), [`service_runtime/budget.rs:137-160`](../../../crates/platform/chio-control-plane/src/trust_control/service_runtime/budget.rs)).
- `budget_share_bps` is a reference-counted lease over in-flight evaluations, not a cumulative partition (shipped, [`validation.rs:395-431`](../../../crates/kernel/chio-kernel/src/kernel/validation.rs)).
- Receiver-owned admission is installed only by the loopback harness (test only, [`chio-runtime-harness/src/kernel.rs:422`](../../../crates/kernel/chio-runtime-harness/src/kernel.rs)).
- The programmable-sovereignty paper lists as not established: "Two configured keys do not prove two independent organizations" ([`CLAIM_LEDGER.md:36`](../../../docs/papers/programmable-sovereignty/CLAIM_LEDGER.md)).

The kill-or-continue review on 2027-03-26 decides whether the relying-party and cross-organization seats stay funded (Q2-12).

## 3. Positioning

### Category sentence

> Chio is the delegated-authority and evidence layer for agent runtimes. It carries authority your organization grants as a capability that can only narrow. It checks each request to an endpoint bound to Chio against that capability's arguments, call counts, expiry and budget, at the runtime's own enforcement point. It signs a receipt that an auditor, and in the cross-organization tier a counterparty, can verify later against a published key. It does not isolate agents, hold their credentials, issue identities or watch the model path.

Each clause becomes true at a different point (table below). From the phase 1 exit until Q2, public copy uses this interim form:

> Chio is the delegated-authority and evidence layer for agent runtimes. It carries capabilities, issued under operator policy, that can only narrow. It checks each request to an endpoint bound to Chio against a capability's call counts and expiry, and against its arguments for the tools the capability names. It signs a receipt that an auditor can verify later. It does not isolate agents, hold their credentials, issue identities or watch the model path.

The qualifier "for the tools the capability names" drops once D60-05 ships the full matcher set.

### Narrative

NVIDIA's platform enforces in three places, and Chio belongs in none of them (INFERRED). OpenShell contains the workload with Landlock and seccomp, and every outbound connection goes through its proxy (VERIFIED, OpenShell@acbac9c [`docs/security/best-practices.mdx:31-42`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/security/best-practices.mdx?plain=1#L31-L42)). Credential placeholders resolve only at profile-bound endpoints, and MCP rules match method and tool name only (VERIFIED, [`best-practices.mdx:247-252`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/security/best-practices.mdx?plain=1#L247-L252), [`schema.mdx:347`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/how-it-works/policies/schema.mdx?plain=1#L347)). Sentry is an optional reference design meant to watch the node's path to the model (VERIFIED as NVIDIA's description, [NVIDIA developer blog, 2026-09-28](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring/); the capability is PROPOSED). Enterprise identity providers issue identities, and the NVIDIA-authored ODIS draft specifies where delegated authority comes from (VERIFIED, ODIS@148dc41 [`RFCs/ODIS.md:2-4`](https://github.com/cosai-oasis/ws4-odis/blob/148dc4187139a41325e3c6d6e7533d956bd33144/RFCs/ODIS.md?plain=1#L2-L4), [`:626`](https://github.com/cosai-oasis/ws4-odis/blob/148dc4187139a41325e3c6d6e7533d956bd33144/RFCs/ODIS.md?plain=1#L626)). SAW says agent authority is a subset of the sponsor's (VERIFIED, [SAW enterprise tool access model, last updated 2026-06-28](https://docs.nvidia.com/enterprise-reference-architectures/secure-agent-workspace-reference-design/latest/enterprise-tool-access-model.html)).

None of them carries authority as a signed artifact that can only narrow, is checked against each request's arguments and counts, and leaves evidence that a party who does not run the gateway can verify (INFERRED). The gaps are specific:

- OpenShell's MCP rules ignore arguments (VERIFIED, `schema.mdx:347`).
- Its approved grants cannot expire or be single-use ([#2881, opened 2026-08-21](https://github.com/NVIDIA/OpenShell/issues/2881)), and its approval audit omits the approver ([Slack admin bridge README, 2026-09-24](https://github.com/slack-samples/openshell-slack-admin-bridge)) (VERIFIED).
- Its record is unsigned OCSF that rotates after three daily files (VERIFIED, OpenShell@acbac9c [`docs/observability/ocsf-json-export.mdx:60-63`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/observability/ocsf-json-export.mdx?plain=1#L60-L63)).
- The draft RFC 0011 lists cross-gateway federation as a non-goal (VERIFIED as the draft's text, OpenShell@acbac9c [`rfc/0011-multi-player-design/README.md:4`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/rfc/0011-multi-player-design/README.md?plain=1#L4), [`:55-58`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/rfc/0011-multi-player-design/README.md?plain=1#L55-L58); the design is PROPOSED).
- SAW names a signed per-engagement delegation record (VERIFIED, [SAW overview, last updated 2026-06-28](https://docs.nvidia.com/enterprise-reference-architectures/secure-agent-workspace-reference-design/latest/what-is-secure-agent-workspace.html)). It gives the record no wire format, signature algorithm or named issuer component; the only hint is "the control plane" (VERIFIED, same page).
- ODIS mandates no carrier, signature or decision record. It defers portable credentials (FW-01) and the economic layer (FW-04) (VERIFIED, ODIS@148dc41 [`RFCs/ODIS.md:1153-1156`](https://github.com/cosai-oasis/ws4-odis/blob/148dc4187139a41325e3c6d6e7533d956bd33144/RFCs/ODIS.md?plain=1#L1153-L1156)).

Chio fills that seam and stops there (roadmap). At the control plane, a gateway interceptor binds each sandbox to a capability. It projects the capability's ceiling into OpenShell policy with an explicit loss report, refuses widening and receipts approvals. On the data plane, the supervisor middleware evaluates each mediated request between OpenShell's policy check and credential injection. It fails closed and signs a receipt with three outcome states. The receipt carries the gateway, sandbox, request and policy-binding identifiers. Receipts land in OCSF 1.9 beside OpenShell's events, and a join verifier reports what OpenShell forwarded without a Chio decision. The same decision core sits behind Envoy, and in front of a counterparty's own API it verifies a presented chain offline. Chio never isolates, never holds upstream secrets, never issues identities and never replaces OpenShell's policy language. The OpenShell adapter tracks a research-preview contract and ships as a preview. The formats it carries are Chio's, and they get a written stability policy (backlog I-037) before partners integrate.

### Design rules for the OpenShell adapters

- Bind in the policy, not in a registry keyed on `sandbox_id`. MODIFY_OPERATION and VALIDATE see the raw CreateSandbox request before the gateway assigns the sandbox id (INFERRED from the interceptor contract). POST_COMMIT bindings must be fail_open (VERIFIED, OpenShell@acbac9c [`proto/gateway_interceptor.proto:83-95`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/proto/gateway_interceptor.proto#L83-L95), [`:133-135`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/proto/gateway_interceptor.proto#L133-L135)). OpenShell's canonical policy bytes include middleware `config`, so a `binding_revision` there sits inside the deterministic policy hash (VERIFIED, [`crates/openshell-core/src/policy_identity.rs:134-177`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/crates/openshell-core/src/policy_identity.rs#L134-L177)). The sandbox-keyed registry in backlog I-015 is not used.
- Present capabilities by reference. A request header block is capped at 16 KiB (VERIFIED, [`architecture/sandbox-limits.md:98`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/architecture/sandbox-limits.md?plain=1#L98)). A 40-link chain token measured 20.8 KB, and under fail_open a custom capability header reached the upstream (VERIFIED, local test). An optional `x-chio-capability-ref` selects an already-bound narrower child and is always stripped.
- Enforce fail_closed from the interceptor. `ValidateConfigRequest` carries only `config` and `middleware_name` (VERIFIED, [`proto/supervisor_middleware.proto:92-97`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/proto/supervisor_middleware.proto#L92-L97)), so middleware cannot see or refuse `on_error: fail_open` (INFERRED).
- Cover every widening RPC. The interceptable list has 25 unary methods, including the provider-profile RPCs and six draft-chunk RPCs (VERIFIED, [`crates/openshell-gateway-interceptors/src/routes.rs:17-43`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/crates/openshell-gateway-interceptors/src/routes.rs#L17-L43)). StartSandbox, StopSandbox, ExecSandbox, ListSandboxes and WatchSandbox are not on it, so the invariants name the gateway administrator as trusted. `current_state` is not populated, so merge operations Chio cannot recompute are denied (VERIFIED, [`docs/extensibility/gateway-interceptors.mdx:171`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/extensibility/gateway-interceptors.mdx?plain=1#L171)).
- Carry the receipt reference where OpenShell keeps it. OpenShell logs only a deny `reason_code` of at most 64 bytes matching `^[a-z][a-z0-9_]*$`, and replaces operator-supplied finding text (VERIFIED, [`proto/supervisor_middleware.proto:705-719`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/proto/supervisor_middleware.proto#L705-L719)). Deny codes are `chio_` plus 59 lowercase hex characters of the receipt id. Allow receipts go in `x-openshell-middleware-chio-receipt` on the response. That is the namespace RFC 0009 reserves for external writes (VERIFIED, [`rfc/0009-supervisor-middleware/README.md:528`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/rfc/0009-supervisor-middleware/README.md?plain=1#L528)).
- State the outage behavior. An unreachable registered extension stops the gateway from starting, and registration changes need a restart (VERIFIED, [`docs/extensibility/supervisor-middleware/configure.mdx:63`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/extensibility/supervisor-middleware/configure.mdx?plain=1#L63), [`gateway-interceptors.mdx:102`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/extensibility/gateway-interceptors.mdx?plain=1#L102)). A fail_closed interceptor blocks UpdateConfig during a Chio outage, so no tighter policy can be pushed (INFERRED). Of the containment actions, only StopSandbox, which is not interceptable, and DeleteSandbox, if Chio leaves it unbound, still work (INFERRED). Each governed tenant gets a dedicated gateway and a tested break-glass configuration with no Chio registrations.
- Keep deciders co-located and single-writer. Remote budget stores report `AdvisoryPosthoc` and refuse family limits (shipped, [`service_runtime/budget.rs:137-160`](../../../crates/platform/chio-control-plane/src/trust_control/service_runtime/budget.rs)). `chio trust serve` therefore runs as a single replica on a block volume until a PostgreSQL store exists. SQLite WAL is unsafe on NFS, EFS and Azure Files.

It shows the fail_closed interceptor rejecting `tls: skip` on an authority host, and an allow event with no receipt landing in the join verifier's report. Loss is reported as a lower bound of detected gaps. The gateway's log buffer is not persisted, the push channel drops events under load, and OpenShell OCSF carries no sequence number (VERIFIED, OpenShell@acbac9c [`docs/observability/accessing-logs.mdx:38`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/observability/accessing-logs.mdx?plain=1#L38), [`:79`](https://github.com/NVIDIA/OpenShell/blob/acbac9cb795094986cbab016bfd0352d980b17f6/docs/observability/accessing-logs.mdx?plain=1#L79); [#3817, 2026-09-29](https://github.com/NVIDIA/OpenShell/issues/3817)).

The counterparty scenario runs `chio api protect --treaty-store` in front of one MCP server. In-scope calls return a receipt id, and out-of-scope arguments are denied before dispatch. A revoked epoch denies the next call without contacting the sender. The chain still roots in the operator's issuer key, and the epoch is operator-signed. The demo therefore claims verification "without trusting the operator's runtime, gateway or logs", not without trusting the operator. A bilateral co-signed receipt appears only if a real second operator holds its own keys. Otherwise it is labeled "two configured keys under one custodian".

The regulatory walk-through presents these obligations as bars a firm chooses to exceed, and notes that WORM retention belongs to the enterprise:

Full Demo B runs in eight steps:

1. The sponsor signs in through OIDC, and trust-control issues the coordinator capability with a signed companion.
2. The spawn broker requests 20 workers.
3. The interceptor binds each one-hop grant and refuses a 21st. Each grant covers one directory, a per-worker `max_invocations` that sums to at most the family budget, and one hour.
4. Prover results appear for the REST-only part. "Unsupported" appears for the MCP part, which Chio's attenuation proof covers.
5. A worker that writes outside its directory is denied with a receipt.
6. A merge needs an IdP-authenticated approver.
7. The sponsor revokes the coordinator through the operator route, and the revoke-to-deny time is measured.
8. Lineage and OCSF 1.9 events go to a SIEM.

## 15. Claim-boundary cautions

These rules govern new claims as work lands. The stop list in section 3 covers existing surfaces. Facts in this section carry labels where they are first stated in sections 1 to 11.

- Integration status: call the OpenShell work "preview integration; receipts carry the OpenShell sandbox id asserted by the authenticated gateway caller", and only after the D60-01 rows exist. Never call it stable while the middleware is a research preview and #3307 is open. Claim no "NVIDIA partner", Inception or "Works with OpenShell" status.
- Coverage: say "every call to endpoints bound to Chio middleware" and publish what it cannot see. Harness hooks for Claude Code and Codex fail open, so ship them as coverage paired with a chokepoint.
- Evidence: say "tamper-evident after signing, correlated with OpenShell events by sandbox and time, linked exactly on denials by reason code". Reserve "without trusting the operator's runtime, gateway or logs" for the relying-party verifier. Reserve "without trusting the operator" for deployments where the root grant belongs to the relying party. Report OCSF loss as a lower bound. Claim no OCSF 1.9 conformance until the goldens validate. Say "exporter-key record_integrity attestation; the kernel signature travels in raw_data".
- Delegation: say "single-hop portable, deeper chains hosted" until L-01, and "capabilities issued for a sponsor's engagement under operator policy" until Q2-01. Say that Chio accepts `odis.bundle.v1` harness grants as evidence-only inputs. Never say "APF-compatible", because the APF Core schema is not public.
- Budgets: caps travel in tokens and ledgers do not. Stores report `single_node_atomic` or `advisory_posthoc`, `budget_share_bps` is an in-flight lease, and no code debits an ancestor. Never say "portable budgets".
- Keys and approvals: no HSM-, KMS- or TEE-backed keys, no non-exportable keys and no non-repudiation. After Q2-03 the most that can be said is "custodied by Vault transit". Approvals are not "human-signed". After Q2-02 they are "IdP-authenticated principal, attested by the Chio approval service", and Slack bridge approvals are "bridge-attested".
- Formal verification: use the boundary text in `CLAIM_REGISTRY.md`. All 15 lane gates in `releases.toml`, the formal lanes included, are advisory. The new constraint variants sit outside P1 until the Lean model covers them.
- Hardware and attestation: never say "ran on attested NVIDIA hardware". Chio has no NVIDIA verifier family, and its attestation bridges are not invoked at admission. The bounded release excludes runtime assurance as the sole admission boundary ([`QUALIFICATION.md:80`](../../../docs/release/QUALIFICATION.md)).
- Work off `main`: active defense, quarantine, cage, secret broker and keyring are branch only. The six-host launchers are merged in the plugin repositories but unreleased, and PR #1156 records zero of six hosts accepted. `emergency_stop` is an in-memory flag behind a static admin token with no engage or resume receipt. There is therefore no governed kill switch and no millisecond containment.
- Cross-organization: a receipt co-signed by two keys under one custodian is "two distinct configured keys signed the same predicate", never evidence of two organizations.
- Regulation: EU AI Act Annex III logging applies from 2027-12-02 and Annex I from 2028-08-02. Coding agents are not presented as Annex III systems. Make no claim that receipts satisfy DORA RTS Art 12(2)(d), Art 21(c) or SEC Rule 17a-4(f) until auditors say so. WORM retention belongs to the enterprise. Never say "HIPAA-ready" or "GDPR-compliant".
- Numbers: the prototype's latencies came from a Python prototype on same-host plaintext gRPC and are not product numbers. Publish the D60-01 Rust numbers, with TLS and JWT validation, first.
- Describing NVIDIA: the OpenShell repository was created on 2026-02-24, and public 0.0.x builds date back to March 2026. Release v0.1.0, published on 2026-09-25, marks the alpha-exit compatibility contract rather than the first public release. Release v0.1.2 was the latest on 2026-09-28 (VERIFIED, [OpenShell releases, 2026-09-25 to 2026-09-28](https://github.com/NVIDIA/OpenShell/releases)). The Open Secure AI Alliance launched on 2026-07-27 with 37 inaugural partners (VERIFIED, [Linux Foundation blog, 2026-07-27](https://www.linuxfoundation.org/blog/open-models-and-open-weights-are-foundational-to-secure-ai)). Say "OpenShell has not committed a signed-evidence design", not "OpenShell declined".
