# Genesis schema stubs (Proposed, unregistered)

Spec-shaped drafts for the Genesis Coverage Program artifact family, kept in
the research tree DELIBERATELY: nothing here is registered, so the canonical
`spec/schemas/` manifest and `registry.json` stay untouched by a research
proposal (and clear of the pre-#974 registry freeze, PLAN.md section 0).
Registration happens at each schema's owning milestone
([GENESIS-PLAN.md](../GENESIS-PLAN.md): procurement-list at G1b, royalty-right
at G2, reliability-epoch at G3, operator-seat-roster at G4), via the standard
four-place registration (ARCHITECTURE 7.1).

Contents:

- `royalty-right.schema.json` - the make-or-break Q2 artifact (ADR-0018 D2):
  a signed, non-transferable, forward-flowing claim on a fraction of the D7
  clearing fee. Inline signature per the chio-finding convention (no
  `SignedExportEnvelope` wrapper; ADR-0018 D1).
- `negative-fixtures/royalty-right.v999.json` - a JSON-Schema-level
  unsupported-version fixture. Its shape follows v1 and the schema id is v999.
  At G2, the semantic golden is generated and signed first, then copied with
  only its schema id mutated so the fail-closed validator test isolates the
  unsupported-schema rejection.

The signature and id values in fixtures are placeholder zeros; real goldens
are generated by the G1a crate's fixture generator, mirroring the M0/M1
finding-family pattern.

JSON Schema proves shape only. The G2 Rust validator must also prove the
content-addressed `right_id`, authorized signer, settlement identity binding,
`expires_at > issued_at`, strictly increasing schedule times, non-increasing
shares, first schedule time equal to `issued_at`, every schedule time before
`expires_at`, and maximum share within the royalty ceiling referenced by
`carve_out_policy_ref`. The joint royalty-plus-seat cap is transaction-local
and belongs in the settlement validator, which has the current roster and
service evidence; this artifact alone cannot prove it.
