# Swarm v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the swarm v2 mechanics from spec section 14:
- `submitted` lanes verified together by check trains, with failures attributed by changed path;
- integrator landing;
- digest wakeups;
- session rotation;
- `chio-builder-1` as the train host.

**Architecture:** All code lives on the orphan `swarm` branch (worktree `/Users/connor/backbay/arc-swarm`):
- **`swarmlib/train.py`** composes every submitted lane onto the integration tip in a throwaway worktree, runs one `cargo check`, one Clippy and per-crate tests through the build scheduler, then blames failures by file, then by crate.
- **`swarm check-train`** reruns itself on `config.train_host` over SSH, so trains build on the 48-vCPU builder while agents stay where they are.
- **`swarm wait --digest`** and runner session rotation keep the conductor's context small.

**Tech Stack:** Python 3.11+ standard library, git, `gh`, cargo's `--message-format=json`, the `swarm build` scheduler, SSH.

**Spec:** `docs/superpowers/specs/2026-10-06-agent-swarm-design.md` section 14 (branch `docs/agent-swarm-design`). Earlier plan: `docs/superpowers/plans/2026-10-06-agent-swarm.md` (Tasks 1-15 done; this plan amends its pilot, Tasks 18-19).

## Global Constraints

- No em dashes (U+2014) in any file, message or commit.
- The `swarm` branch stays orphan and standard-library only; no `.github/` directory.
- Lean process (spec 14.3): one commit per fix with its regression test; no separate RED commits, per-item reviews or mutation campaigns.
- Defaults (spec 14): `digest_seconds` 1200, `session_max_turns` 40, `train_max_lanes` 12, `train_host` "" (set to `builder` in Task 8).
- Only the integrator lands a train (`swarm check-train --land`), never while CI runs on the base branch, never with a red or unattributed failure, never by force.
- Trains build through `swarm build` (integrator class); the builder's settings are 4 slots x 12 jobs, sccache on, 40 GB floor.
- A failure that no lane can own changes no lane's status and alerts the conductor.
- Commits: conventional (`feat(swarm): ...`), with the `Co-Authored-By` trailer the session requires.

## Review Focus

Each of these is pinned by a named test in the owning task.

1. **A failure no lane can own** (for example a linker crash with no diagnostics) must not promote or punish anyone; the conductor is told. Pinned by `test_unattributable_failure_changes_no_lane_and_alerts_the_conductor` (Task 3).
2. **The base branch moves while a train builds**: landing must be refused rather than rewriting history, and green lanes stay `ready`. Pinned by `test_base_moving_mid_train_refuses_the_push_and_keeps_lanes_ready` (Task 3).
3. **The scheduler refuses a train build** (disk floor): nothing changes and the throwaway worktree is removed. Pinned by `test_refused_build_changes_nothing_and_cleans_up` (Task 3).
4. **Odd or hostile arguments** to the remote rerun stay shell-quoted on the train host. Pinned by `test_hostile_arguments_stay_quoted` (Task 4).
5. **A blocker or URGENT message** must wake the conductor at once even in digest mode. Pinned by `test_blockers_and_urgent_subjects_wake_immediately` (Task 5).
