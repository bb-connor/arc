## Chio resource fit and missing host work

The coding candidate has nine tools: `read_range`, `search`, `repo_status`, `repo_diff`, `apply_patch`, `test_recipe`, `publish_artifact`, `repo_context`, `read_many`. Schemas close unknown properties and the publication destination enum contains only `review`. Repository changes create immutable generations. The ledger commits the current generation and original terminal result together; incomplete intent fences new work. Recipes use pinned executables and platform confinement. These are suitable primitives for a recoverable project task.

The candidate requires prepared private directories, regular single-link files and private modes, excludes `.git`, and refuses symlinks/hardlinks/special files. It does not implement dirty-checkout intake, Git ignore interpretation, submodule handling or writeback to a developer's checkout. The workbench/resource owners must therefore supply qualified intake that inventories without altering originals and prepares a selected private copy. The candidate's all-or-none resource generation cannot be represented as all-or-none host checkout publication.

Candidate operation exports are explicitly unsigned. A resource ledger cannot clear kernel uncertainty. The [implementation inventory](https://github.com/backbay-labs/chio-pi-plugin/blob/4214a5a8ddec776a5ff9ec78007442683fd8df03/docs/ROADMAP-IMPLEMENTATION.md) distinguishes callback/transport fixtures from actual native kernel acceptance. Its selected Linux arm64 disposable privileged-container evidence does not qualify an ordinary Omarchy x86-64 session. Sealed-work qualification remains blocked until the exact native combination and protected recipe execute the required independent tests. The original P2 importer proposal is now owner work in the workbench/resource program, not a desktop-private intake subsystem.

## Historical IPC and configuration implications (outside the current program)

Hyprland exposes a request socket and an event socket under the runtime directory and instance signature. Requests are synchronous; the inspected wiki warns that an unclosed request connection can freeze the compositor until its five-second timeout. A broker needs one short-lived serialized request connection, bounded responses and event invalidation instead of aggressive polling. `configerrors` reports the current compositor state; it is not a side-effect-free offline validator. Socket events are observations and can be missed across disconnects.

A client address plus PID and initial title is better than a title match but does not supply a stable, generation-checked compositor handle. Read-then-dispatch leaves an address-reuse interval. The retired desktop-tools proposal selected numbered workspace selection and bounded metadata while gating targeted mutations on a qualified compositor-side identity check. The consolidated desktop program exposes neither. Post-dispatch observation can detect some mistakes; it cannot prevent them.

Omarchy v4 loads user Lua overrides after packaged defaults. `looknfeel.lua` contains examples for appearance scalars. Arbitrary Lua may execute commands, so a repair preview must not load proposed Lua into the live compositor as validation. The retired repair proposal selected a strict literal subset and sealed-copy validation. It is no longer an implementation domain of this desktop program.

The [snapshot guide](https://github.com/omacom/omarchy/blob/0f8af9be307d5d4f12cc0f6394892cac651ed5e6/manual/47-system-snapshots.md) explicitly excludes `/home` and leaves `~/.config` unchanged. [Snapshot implementation](https://github.com/omacom/omarchy/blob/0f8af9be307d5d4f12cc0f6394892cac651ed5e6/bin/omarchy-snapshot) uses privileged Snapper/Limine operations. [Configuration refresh](https://github.com/omacom/omarchy/blob/0f8af9be307d5d4f12cc0f6394892cac651ed5e6/bin/omarchy-refresh-config) copies defaults and makes timestamped backups; [Hyprland refresh](https://github.com/omacom/omarchy/blob/0f8af9be307d5d4f12cc0f6394892cac651ed5e6/bin/omarchy-refresh-hyprland) affects several files. Neither is the proposed exact-patch transaction. The default Chio repair profile excludes both broad refresh and privileged snapshot operations.
