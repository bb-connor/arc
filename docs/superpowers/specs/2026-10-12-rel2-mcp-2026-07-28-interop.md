# REL-2: MCP 2026-07-28 interop at the edge

Roadmap rung REL-2 ("the MCP door"). Exit: current Claude Code and Codex
connect to `chio mcp serve-http` through ordinary remote MCP, with no plugin.

## The delta (2025-11-25 to 2026-07-28)

Source: modelcontextprotocol.io/specification/2026-07-28 (changelog,
versioning, streamable-http, server/discover).

- No `initialize` / `notifications/initialized` handshake. Every request
  carries `_meta["io.modelcontextprotocol/protocolVersion"]` and
  `_meta["io.modelcontextprotocol/clientCapabilities"]` (SEP-2575).
- No protocol sessions on Streamable HTTP: no `Mcp-Session-Id`, no GET
  stream, no `Last-Event-ID` resumption. Each POST is self-contained.
- Every POST carries `MCP-Protocol-Version` (must equal the `_meta` version),
  `Mcp-Method` (must equal `method`) and, for `tools/call`, `resources/read`
  and `prompts/get`, `Mcp-Name` (must equal `params.name` / `params.uri`,
  `=?base64?...?=` sentinel decoded first). Missing or mismatched headers are
  `400` with JSON-RPC `-32020` (HeaderMismatch).
- An unsupported version is `400` with `-32022` and
  `data: {supported: [...], requested}`. Unknown methods are `404` with
  `-32601`.
- `server/discover` is mandatory: `supportedVersions`, `capabilities`,
  `_meta[serverInfo]`, `instructions?`, plus `ttlMs` / `cacheScope`.
- Every result carries `resultType` (`"complete"` here). List results and
  `resources/read` carry `ttlMs` and `cacheScope`.
- Removed: `ping`, `logging/setLevel`, `resources/subscribe|unsubscribe`
  (replaced by `subscriptions/listen`), core `tasks/*` (now an extension),
  server-initiated requests (replaced by MRTR `input_required` results).
- Dual-era servers are explicitly allowed: a request with modern `_meta` is
  served statelessly, `initialize` selects 2025-11-25 semantics for that session.
  Dual-era clients probe modern first and fall back to `initialize` only when
  a `400` body is not a recognized modern error.

## Where the edge negotiates today

- `chio-mcp-edge/src/runtime.rs`: `MCP_PROTOCOL_VERSION = "2025-11-25"`,
  `SUPPORTED_MCP_PROTOCOL_VERSIONS = [that]`.
- `chio-mcp-edge/src/runtime/jsonrpc.rs` `negotiate_protocol_version`: exact
  match on `initialize.params.protocolVersion`, else Chio code 1000.
- `chio-mcp-edge/src/runtime/requests.rs`: every method except `initialize`
  and `ping` requires `EdgeState::Ready`.
- `chio-mcp-remote/src/remote_mcp/http_service.rs` `handle_post`: no
  `Mcp-Session-Id` means the body must be `initialize`; otherwise the request
  is refused with "request requires MCP-Session-Id". `validate_protocol_version`
  compares the header to the session's negotiated version only.

## What changes

Edge (`chio-mcp-edge`, new `runtime/stateless.rs`, public `stateless` module):

- The edge is dual-era. `2025-11-25` stays the only `initialize` version;
  `2026-07-28` is accepted only through per-request `_meta`.
- A request with a modern `_meta` version on an uninitialized edge opens the
  kernel session implicitly, with the same auth context, capabilities and
  authorization-profile negotiation as `initialize` (fed from
  `clientCapabilities`). Peer capabilities are pinned to none for roots,
  sampling and elicitation, so the edge never issues a server-initiated
  request the stateless client cannot answer.
- `server/discover` answers without opening a session.
- Modern results gain `resultType: "complete"` and `_meta[serverInfo]`; list
  results and `resources/read` gain `ttlMs: 0` and `cacheScope: "private"`
  (nothing is cacheable across principals).

Remote (`chio-mcp-remote`, new `remote_mcp/stateless_http.rs`):

- A sessionless POST whose body carries modern `_meta` takes the stateless
  path: header validation, then an ephemeral session from the existing
  `RemoteSessionFactory::spawn_session` (same auth context snapshot, policy,
  kernel, receipts), one request, a single `application/json` response, then
  upstream shutdown. The ephemeral session is never inserted into the ledger,
  persisted or resumable.
- 2025-11-25 traffic (`initialize`, `Mcp-Session-Id`) is unchanged.
- `RemoteSession::check_enqueue_lifecycle` admits a request carrying a
  stateless `_meta` version into an `Initializing` session, beside the
  existing `initialize` case; the ephemeral session never becomes `Ready`.

## What stays fail-closed

- Authentication, origin, Accept and Content-Type checks run before the
  stateless branch, exactly as for 2025-11-25 POSTs.
- Unknown or mixed versions refuse: an unsupported `_meta` version is `-32022`
  with the supported list; `initialize` with `2026-07-28` is refused; a modern
  request on an edge opened by `initialize` is refused; a modern body that
  also names an `Mcp-Session-Id` is refused.
- Header mismatch or absence is `-32020`, never a silent body-wins.
- Methods removed by 2026-07-28 are `-32601` on the modern path.
- Session-bound `chio-session` bearer credentials authenticate only against
  an active `Mcp-Session-Id`, so they never reach the stateless path; they
  keep working over `2025-11-25`.
- Any worker failure, lag or deadline yields a JSON-RPC `-32603` with
  "effect is uncertain", as on the 2025-11-25 stream.

## Test plan

- Edge unit tests (`runtime/runtime_tests/stateless_revision.rs`): `server/discover` lists both
  versions; a modern `tools/list` and `tools/call` succeed without
  `initialize` and carry `resultType`; unsupported `_meta` version yields
  `-32022` with `supported`; `initialize` with `2026-07-28` is refused; a
  modern request after `initialize` is refused; `initialize`
  still selects `2025-11-25`.
- Remote hosted tests (`hosted_tests/stateless_http.rs`): modern
  `server/discover`, `tools/list`, `tools/call` over real HTTP with no
  `Mcp-Session-Id` in either direction; header absence or mismatch
  (`MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`) yields `400`/`-32020`;
  a base64-sentinel `Mcp-Name` is decoded; unsupported version yields
  `400`/`-32022`; a removed method yields `404`/`-32601`; a handshake session
  keeps working beside stateless requests; the existing suite stays green.

## Not in this slice

- `subscriptions/listen`, MRTR `input_required`, the tasks extension,
  `x-mcp-header` / `Mcp-Param-*` validation, per-request `logLevel`, and the
  `-32002` to `-32602` resource-not-found renumbering.
- Pooling: each stateless request builds a kernel session and, without
  `--shared-hosted-owner`, an upstream process. Operators serving modern
  clients should run with the shared hosted owner.
- Live Claude Code and Codex connection checks (the REL-2 exit evidence).
