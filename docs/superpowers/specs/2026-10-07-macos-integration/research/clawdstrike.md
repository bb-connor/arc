### Contradictions requiring precise wording

1. CLW-06's module comment says durable identities are checked against the live PID. The inspected function never reads the live PID version. A matching numeric PID and successful signal-zero probe cannot rule out reuse. This is a source-contract gap, not a runtime exploit demonstrated here.
2. An ES client that can deny AUTH_OPEN is not necessarily configured to deny in its observer tool. Describing the observer as complete task enforcement would contradict its default decision handler.
3. The NE provider is substantive enforcement code. Calling it merely a mock would be false. Calling its tested decision function a proven deployed, task-scoped filter would also exceed the evidence.
4. The release workflow consumes a prebuilt signed extension. Successful app packaging alone cannot connect that extension's binary to the reviewed Swift files or demonstrate its effective OS activation.
5. HushSpec names and version strings do not prove identical dialects. At MAC-BASE, `crates/guards/chio-policy/src/models.rs` has a closed Chio schema and `compiler.rs` resolves threshold approvers through an authenticated directory. An imported Clawdstrike policy must not remove those bindings or bypass Chio's native approval and integrity rules.

## Host ecosystem observations relevant to reuse

The [public Pi manifest](https://github.com/backbay-labs/chio-pi-plugin/blob/4214a5a8ddec776a5ff9ec78007442683fd8df03/package.json) identifies adapter `0.2.0`, exact Pi `1.0.2`, optional Durable `1.0.2`, and Node `>=22.19.0`. That Node range is a compatibility declaration, not an exact qualified runtime. The ordinary local Pi checkout at `b24b14e9c4d69261ab39eb9507db45bc07cba96f` still declares adapter `0.1.0` and Pi `0.85.1`; it must not be relabeled as the current public tuple.

The public [governance composition contract](https://github.com/backbay-labs/chio-pi-plugin/blob/4214a5a8ddec776a5ff9ec78007442683fd8df03/src/governance.ts) explicitly assigns model submission and knowledge custody to native ports. Branded JavaScript handles provide owner association, not native authority. The [child facade](https://github.com/backbay-labs/chio-pi-plugin/blob/4214a5a8ddec776a5ff9ec78007442683fd8df03/src/delegation.ts) requires an installed child port and uses a process-local submitted-ID set; it is not a durable launch ledger. The [CLI](https://github.com/backbay-labs/chio-pi-plugin/blob/4214a5a8ddec776a5ff9ec78007442683fd8df03/src/protected-cli.ts) accepts `--prompt` and refuses required governance before credential access. Neither an argv prompt nor the CLI's sandbox profile is adopted as the proposed Mac VM qualification.

At MAC-BASE, the LangChain wrapper in `sdks/python/chio-langchain/src/chio_langchain/tool.py` explicitly returns non-authorizing advisory outcomes. CrewAI, AutoGen and LlamaIndex wrappers contain in-process callable paths and reject non-authorizing receipts; their hooks still do not eliminate arbitrary Python, shell, direct SDK or network bypass outside the wrapper. Their declared dependency ranges are not exact host qualification. Protocol crates such as `chio-mcp-adapter` and `chio-openai-adapter` contain real kernel routing and protocol conversion, but that does not confine the calling host. See the six-host boundary and qualification ladder in the [macOS annex](../ANNEX.md).

## Reuse experiment ownership

The Chio policy owner supplies semantic projection and independently checks approval-directory binding. The Mac ES/NE owners supply scoped restrictions, identity, callback and lifecycle proofs. The process host owner supplies incarnation-bound termination and native custody. The distribution owner supplies source-to-signed-bundle provenance. The release verifier joins those artifacts on the exact [shared qualification tuple](../../2026-10-07-desktop-integration/QUALIFICATION.md). None of these responsibilities is discharged by copying a Clawdstrike daemon or approval queue.

The accepted reuse boundary is in the [macOS annex](../ANNEX.md). ES/NE is a separate managed-endpoint track; retired `native-descendant-v1` cannot inherit Seatbelt or VM results. Clawdstrike may independently impose stricter administrator policy. Chio must report its observations as external evidence with a separate signer and clock; it cannot claim atomic shared stop, rollback or authority with that product.
