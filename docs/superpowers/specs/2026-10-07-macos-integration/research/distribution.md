# Distribution, operational privacy, and qualification research

Research date: 2026-10-07. Status: source research and proposed decisions, aligned with the accepted native-services amendment. [The annex](../ANNEX.md) and [native-host research](native-host-services.md) supersede earlier controller-first or graphical-app-first packaging assumptions; source findings below do not make optional ES/NE providers universal requirements. No signing identity, entitlement grant, provisioning profile, notarization submission, installed extension, runtime enforcement, battery result, or supported Mac release was verified by this research.

Confidence: high for the cited Apple API contracts; moderate for the proposed composition; unknown for Chio's entitlement access and installed behavior until the named experiments run. Dynamic Apple documentation can change. Save the retrieved pages, retrieval time, digest, SDK headers, and final OS build alongside the eventual qualification evidence.

## Primary-source findings

| Source | Finding supported by the source | Design consequence, which is a Chio proposal |
| --- | --- | --- |
| [System Extensions](https://developer.apple.com/documentation/systemextensions) | Extensions ship inside an app; activated extensions are available to all users. App and extension normally share a signing Team ID, with a documented redistributable-entitlement exception. | Use one publisher team initially, isolate users in the global provider, and do not equate app launch with provider activation. |
| [Installing System Extensions and Drivers](https://developer.apple.com/documentation/systemextensions/installing-system-extensions-and-drivers) | Embedding is under `Contents/Library/SystemExtensions`; activation checks bundle location, signatures, entitlements, and identifiers. Updates use activation and a replacement delegate. | Keep activation in the containing app; a downloaded standalone CLI cannot substitute for this lifecycle. |
| [Endpoint Security entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.endpoint-security.client) | Apple must grant the requested entitlement; missing entitlement causes ES client creation failure. | Team entitlement access is an early feasibility gate, independent of source compilation. |
| [Network Extensions entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.networkextension) | Directly distributed macOS apps require the Developer ID capability, corresponding provisioning profile, and entitlement values. | Verify the exact extension point and direct-distribution values in the final profile; no broad entitlement plist copied from an App Store build. |
| [Notarizing macOS software](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) | Apple describes valid Developer ID signatures, Hardened Runtime, timestamp requirements, and the exclusion of enabled `get-task-allow` for notarization. | Scan every executable and nested bundle; notarization is a distribution gate, not an enforcement proof. |
| [Customizing the notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow) | Apple documents command-line notarization and stapling workflows. | Preserve submission logs, ticket validation, and final bytes, then test online and offline consumer launch. |
| [System-extension replacement delegate](https://developer.apple.com/documentation/systemextensions/ossystemextensionrequestdelegate/request%28_%3Aactionforreplacingextension%3Awithextension%3A%29) | The delegate receives existing/new version properties and chooses replacement or cancellation. | The updater must compare active provider identity as well as files in the new app. Version strings alone cannot prove a safe handover. |
| [Deactivation request](https://developer.apple.com/documentation/systemextensions/ossystemextensionrequest/deactivationrequest%28forextensionwithidentifier%3Aqueue%3A%29) | Deactivation may require restart; successful request completion can precede actual removal. | Keep removal pending until independent provider-state inspection confirms it; never label a request acknowledgment as effective removal. |
| [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) | macOS 13 and later provides registration of bundled login items, agents, and daemons; registration is subject to approval and exposes status. | Register the selected user-session native service as a bundled LaunchAgent; qualify a system-domain LaunchDaemon separately for the service-host profile. Measure actual lifecycle and expose permission denial without repeated prompts. An optional controller is a consumer, not the mandatory service. |
| [System extensions deployment](https://support.apple.com/guide/deployment/depa5fb8376f/web) | Management can control extension approval. Apple's page also describes managed removability for specified apps. | Managed installation receives its own matrix and removal test; it is not a prerequisite for consumer use. |
| [Privacy Preferences Policy Control](https://support.apple.com/guide/deployment/dep38df53c2a/web) | Device management configures supported privacy services through a distinct payload. | Do not collapse extension approval, privacy approval, background service approval, and Chio authority into one Boolean. |
| [TN3137: Mac keychains](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains) | macOS has file-based and data protection keychains with different access models. The data protection keychain is available in a user context. | Keep end-user provider secrets in a properly signed per-user broker; do not assume a root provider can use a logged-out user's data protection keychain. |
| [kSecUseDataProtectionKeychain](https://developer.apple.com/documentation/security/ksecusedataprotectionkeychain) | The attribute selects the data protection keychain without requiring iCloud synchronization. | Explicitly select the implementation, disable synchronization, and test every supported locked/unlocked state. |
| [kSecAttrAccessible](https://developer.apple.com/documentation/security/ksecattraccessible) | Accessibility attributes have documented macOS applicability conditions and restrictions on synchronizable items. | Proposed broker items use the narrowest tested accessibility class; a legacy keychain must not silently replace an unavailable class. |
| [Keychain data protection](https://support.apple.com/guide/security/secb0694df1a/web) | Apple explicitly distinguishes macOS enforcement of protection-class guarantees from iOS-family Data Protection. | Verify Mac behavior directly; do not import an iOS lock or backup claim. Keychain storage does not establish a monotonic authority counter. |
| [Logging](https://developer.apple.com/documentation/os/logging), [OSLogPrivacy](https://developer.apple.com/documentation/os/oslogprivacy) | Unified logging has persistent system storage and configurable privacy of interpolated values. | Omit sensitive values before persistence and use private annotations as additional protection; the app cannot promise to erase every OS-managed log. |
| [Generating log messages](https://developer.apple.com/documentation/os/generating-log-messages-from-your-code) | Apple's guidance includes minimizing dynamic sensitive content and explicit privacy annotations; numerical values are not automatically private. | Review identifiers, counts, and timestamps for disclosure as well as strings; secret canary tests cover OS logs, crashes, argv, and archives. |
| [Reducing battery use](https://developer.apple.com/documentation/xcode/reducing-your-app-s-battery-use) | Apple recommends reducing work, improving efficiency, and avoiding API misuse. | Coalesce observation, stop idle collection, bound queues, and measure paired energy workloads on the release tuple. |
| [Descendant ES client](https://developer.apple.com/documentation/endpointsecurity/es_new_descendants_client%28_%3A_%3A%29), [Endpoint Security](https://developer.apple.com/documentation/endpointsecurity) | Retrieved rendered pages label descendant and deadline APIs Beta and describe descendant-scoped behavior. The parallel DocC inspection reported `beta:false` metadata. | Record this metadata disagreement. Descendant APIs remain research for a separately gated managed-endpoint experiment. The accepted consolidation retires `native-descendant-v1`; final headers, OS behavior and entitlement access cannot alone qualify a replacement. |

The first three Apple pages required their linked Markdown representations for full text during this inspection. These were read directly, not inferred from a JavaScript shell. The older Omarchy distribution and observability specifications were read as design precedent only. They do not establish Mac behavior or supply Mac acceptance results.

## Proposed distribution decisions

1. Begin with Developer ID signed and notarized native-service artifacts: a GUI-less bundle and/or signed installer package for the exact selected deployment mode. The inventory contains actual native owner executables and reviewed helpers; a menu app, controller and disk image are optional delivery choices. A service bundle may use an `.app` layout for registration/provisioning without a graphical target. Provider bundles belong only to the separately selected managed-endpoint delivery. No kernel extension is proposed. Apple supplies a [GUI-less service/package example](https://developer.apple.com/documentation/servicemanagement/updating-your-app-package-installer-to-use-the-new-service-management-api).
2. Propose `MACOSX_DEPLOYMENT_TARGET=15.0` and Apple silicon arm64 for the first native-service build experiment. This is a product scope choice, not an Apple API minimum or support claim. Compile and run on exact final 15.x and the selected current stable OS build before selecting the supported matrix. Intel/x86_64, Rosetta execution, and earlier macOS are separate unavailable rows until tested. Backend minima are separate: the currently inspected Apple Containerization source requires macOS 26 and Xcode 26. Descendant ES research does not raise the native-service minimum or revive the retired profile.
3. Register the selected user-session native service through the supported per-user `SMAppService` LaunchAgent path. Separately qualify a system-domain LaunchDaemon for a least-privileged service principal, with explicit machine enrollment, credential policy and authority; use either the supported bundled installation or an independently qualified managed package, with one lifecycle owner. Bundled `SMAppService` registration uses `BundleProgram`; traditional installed launchd plists use `Program`/`ProgramArguments`. A controller, if delivered, remains an optional consumer outside the TCB. A no-UI login-session run cannot qualify boot/login independence, and a machine daemon cannot inherit human-session credentials or approvals. See [Apple registration](https://developer.apple.com/documentation/servicemanagement/smappservice/register()) and [managed daemon guidance](https://developer.apple.com/forums/thread/771162). ES/NE providers remain separately selected; their source availability cannot require host-wide permissions for native observation or VM work.
4. Release metadata binds the unsigned build closure, final signed bytes, installed identities, any selected active providers, schemas, allowed profile manifest, and the exact acceptance artifacts. Byte-identical reproducibility can be claimed only for the measured build layer, since signing and notarization introduce independent metadata.
5. Stage updates, fence affected admission, reconcile actual native lifecycle and selected in-flight work, activate compatible components, remeasure the active generation, and retain existing custody. A selected OS provider update cannot be promised atomic; it must keep affected profiles unavailable across a non-atomic transition.

## Experiments required before a release decision

| Experiment | Controlled comparison and independent measurement | Decision it can close |
| --- | --- | --- |
| Clean signed installation | Download the exact release candidate on a clean standard-user Mac with SIP and normal security settings, no developer-mode exception; separately deny every requested approval. Observe Gatekeeper and installed component identities externally. | Available packaging path and truthful permission UX for that exact tuple. |
| Selected managed-endpoint entitlement/provisioning probe | Compare signed eligible and missing-entitlement fixtures. Capture actual ES/NE initialization errors and active bundle state without broad permission changes. | Whether the selected team and provider type are eligible; not whether their policy is correct. |
| Update interruption | Crash each native-service updater stage, hold old owners active, deny component replacement and restart mid-migration. Probe protected reads and inspect writer generations; count external effects for selected mutation capabilities. Add old-extension activation/replacement trials only when that provider is selected. | Compatibility and safe refusal of mixed installed generations. |
| Shared-Mac custody | Two users independently enroll native services, read scoped synthetic records, switch sessions, lock and log out. Probe wrong-user/service-principal access; add project/work mutations or global-provider queries only when those profiles are delivered. | Per-user confidentiality and effect fencing across native service lifetimes, without requiring a task runner or ES/NE provider for Observe. |
| Service-host without graphical login | After legitimate OS/protected-storage availability, cold-start the enrolled machine service without any graphical user; deny or delay its broker, storage, clock/freshness and network dependencies. Compare authenticated native reads and, only for selected mutation profiles, independent effects. | Exact service-principal installation, credential/authority and lifecycle behavior; user-session evidence cannot discharge it. |
| Backup rollback | Snapshot native app and synthetic credential state before expiry/revocation; add grant spending only for exposed mutating authority. Expire/revoke/fence it, restore the exact selected credential closure and app state, then remove freshness access. Independent native authority retains the newer state; Observe uses its actual read/session credentials without task execution. | Restore cannot prove its own freshness; unavailable authority remains fenced. |
| Energy baseline | Randomized paired baseline/candidate sessions under the same hardware, power mode, thermal state, workload, display, and network conditions. Collect external process/energy traces with measurement overhead recorded. | Measured cost for the tested profile, not a universal battery promise. |
| Enterprise descendant-API research | Pin final SDK headers and OS build; test client termination, deadline misses, pre-existing children, reparenting, delegated services, open handles, and network flows separately. | Input to a new managed-endpoint decision only. `native-descendant-v1` is retired and cannot be opened by this experiment. |
