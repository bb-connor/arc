# Apple platform evidence and execution decisions

Inspected 2026-10-07. This is source and documentation research, not installed-runtime evidence. Confidence: high in the retrieved source facts; moderate in the proposed architecture; unknown in entitlement availability, final SDK compatibility, and effective protection on a signed installed system.

## Decisions requiring installed experiments

The accepted first product reuses the restricted session and coding-resource owners. The higher-assurance VM experiment evaluates existing runtimes for Linux tools and direct-egress denial before any bespoke VZ supervisor. Xcode, Simulator and Darwin-specific build scripts require an independently qualified remote Mac executor, a qualified macOS VM design, a bounded trusted native build broker, or a separately qualified native backend. The retired `native-descendant-v1` is not a candidate. A native build broker accepting arbitrary build phases is itself an arbitrary-code runner and needs containment; calling it trusted does not solve that boundary. A signing broker accepts only the exact artifact, identity, entitlement set and output commitment authorized by the kernel, and never exports reusable signing keys.

The selected local VM, native Seatbelt, remote execution, and managed-endpoint tracks each need a fresh clean-machine record for their own OS, architecture, component hashes, permissions, identity, failure modes and workloads. Source compilation, a mock provider, a signed bundle, an activated extension and effective installed enforcement are different evidence classes. None has been qualified by this research.
