## Decisions requiring installed experiments

The initial local worker uses Linux tools and zero direct network devices. Xcode, Simulator and Darwin-specific build scripts require an independently qualified remote Mac executor, a qualified macOS VM design, a bounded trusted native build broker, or native-descendant qualification. A native build broker accepting arbitrary build phases is itself an arbitrary-code runner and needs containment; calling it trusted does not solve that boundary. A signing broker accepts only the exact artifact, identity, entitlement set and output commitment authorized by the kernel, and never exports reusable signing keys.

Local Linux VM, remote project, native descendant, and managed endpoint each need a fresh clean-machine record for their own OS, architecture, component hashes, permissions, identity, failure modes and workloads. Source compilation, a mock provider, a signed bundle, an activated extension and effective installed enforcement are different evidence classes. None has been qualified by this research.
