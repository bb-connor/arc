# Mac workflow and resource API research

> Historical research snapshot retained for provenance. [ADR-0038](../../../../adr/ADR-0038-native-host-program.md), the [program map](../../../../architecture/PROGRAM-MAP.md) and [macOS annex](../ANNEX.md) supersede this document's former implementation choices. Old NK identifiers and platform methods below are historical proposal labels, not current APIs or blanket desktop prerequisites. The shared program retains the needed admission, crossing and ABI safety properties through their owning contracts; it does not require all three redesign keystones before the first product.

Inspected 2026-10-07. This file supplements the approved [decision record](decision-record.md) with primary API findings for the product, native experience and resource contracts. Apple references describe API behavior, not a qualified Chio implementation. Confidence is high in the documentation findings below, moderate in applying them to the proposed architecture, and unknown for untested installed behavior. The specification's macOS 15 arm64 candidate is a product qualification choice, not an inference from individual API availability.

The referenced Markdown content of Apple's documentation was retrieved directly after the web renderer returned JavaScript shells. No complete Apple source or documentation copy is redistributed here. Findings distinguish documented semantics from design inference.

The candidate object reader uses the primary [libgit2 object-database API](https://libgit2.org/docs/reference/main/odb/git_odb_open.html), which documents loose/packed object backends and SHA-1-only behavior for `git_odb_open`. The resource plan therefore rejects unsupported formats, stages only admitted regular object-store files, and requires independent graph/content validation. This API finding does not qualify the parser, collision handling, memory bounds or malicious-object isolation.

## Decisions derived from the research

The first native experience uses SwiftUI/AppKit, Finder Services, an ordinary app window and a menu extra. Services passes only a selection proposal. Native resource intake creates a verified resource generation and returns an opaque reference before `task.create`. The closed `chio.desktop.operator.v1` contract does not gain a path or shell method.

The first source is a committed Git tree, with dirty state explicitly excluded. A committed tree gives a stable content graph when every object is verified; a working-directory copy does not. Raw Git object import must disable unsupported external stores, promisor fetch, replacement/filters and link-following and bound every decompressed object. An importer may reject an unsupported repository instead of guessing. A trusted Git reader is not automatically safe merely because the subcommand is read-only.

The first output is a sealed local artifact; a separately reviewed no-replace local export is the first publication candidate. A branch push or app send needs an independent exact-effect and recovery contract. Git working-tree patch application is not included in a file-export claim.

## Required experiments, not resolved facts

| Experiment | Pass oracle | Owner |

| Installed Services handoff | Signed app receives exactly one selected file URL, handles denied scope, and produces no authority before preflight/native admission. | Native operator plan. |
| Scope across app/helper process boundary | The actual sandbox/signing arrangement acquires and balances only selected-resource access after restart without broad parent access or path-string substitution. | Resources and host architecture plans. |
| Lock/session review behavior | Current native session requirement rejects stale endorsements even when UI notifications are delayed, while sensitive UI redacts on the tested matrix. | Native operator and authority plans. |
| APFS materialization and export races | No case/normalization alias, FD/rename/symlink substitution or crash creates an unintended generation, overwrite or false success. | Resources plan. |
| Dirty snapshot feasibility | Each accepted capture has a coherent whole-generation oracle under hostile pre-opened writers and mmap, not merely stable per-file hashes. | Explicit deferred resource qualification gate. |
| Capture/privacy claims | Presenter-mode screenshots and accessibility trees contain no sensitive values. Documentation makes no claim of universal capture prevention. | Native operator and privacy plans. |
