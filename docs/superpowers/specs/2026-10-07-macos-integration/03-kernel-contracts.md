# Kernel contracts and crossing ownership

Status: proposed normative design. Confidence: high in ownership and refusal rules; unknown in installed conformance until qualification. The implementation baseline and missing-contract evidence are [recorded here](research/chio-readiness.md). This design requires the native kernel program. It does not declare those requirements implemented by writing an IPC adapter.

Chio is the Rust authority kernel for an agentic operating system. macOS supplies processes, memory isolation and native facilities. One kernel decides whether an agent operation can release authority, bytes or effects. Swift presents facts and requests actions; Rust drives native contracts; ES/NE and VM mechanisms enforce the separately declared execution boundary.

## Contract and type ownership

| Type or operation | Owning layer | Current or proposed status |
| --- | --- | --- |
| `AdmissionOperationBindingV1`, `AdmissionOperationId`, `AdmissionReplayKey`, `StoreMutationFence` | Existing kernel admission/core owner | Current CHIO-MAIN types; adapters retain opaque references and do not derive authority from transport IDs |
| `AdmissionState`, `AdmissionEvent`, `Transition`, `EffectList` | Proposed `chio-kernel-core` pure admission module | CHIO-NORTHSTAR NK-01; no IO, wall clock, signing, random IDs or native OS handles in transition |
| `KernelOp`, `KERNEL_ABI_VERSION`, layer registry | Proposed `chio-kernel-core` ABI owner | NK-03; numeric values and wire publication remain native owner decisions based on actual exported inventory |
| `CrossingKind`, `CrossingCheck`, `CrossingResult`, `CrossingOrder` | Proposed native crossing owner and SQLite serving writer | NK-02; controller cannot deserialize a caller assertion into `Committed` |
| `StopEpochV1`, `StopEpochId` | Proposed native stop owner | NK-04; chain generation and epoch are both required; transport event sequence is unrelated |
| `VerifiedEndorsementFactV1` | Native integrity adapter inside crossing transaction | NK-05; never caller-deserialized, stored as an authority input, or manufactured by Swift |
| `MacQualificationCaptureV1` | Proposed native resource intake/read/capture and serving-owner extension | NK-03/NK-05 prerequisite for M8 artifact custody; enrollment, sealing, authenticated child binding and one-use current read verification remain native-owned; not an execution grant or qualification result |
| Desktop requests, errors and task projections | Shared desktop controller and versioned operator contract | Newly proposed [operator protocol](06-operator-protocol.md); not a second kernel ABI |
| Audit tokens, process incarnation, VM/extension connection | macOS adapter | Platform evidence and routing only; native binding selects tenant, principal, session, run, isolation and policy generations |

The pure transition computes a next state and planned effects. Drivers gather authenticated facts and execute effects through native ports. A planned commit carries its expected operation version. The writer returns `Committed`, `Refused`, `OutcomeUnknown`, `Retry` or `StoreUnavailable` with the north-star meanings. A failed commit or required post-commit anchor sync poisons the owner and is unknown; a known not-committed store outage retains the member for recovery. Neither permits compensating an effect that may have crossed. `Retry` is an internal lost-batch requeue, never a fresh desktop intent.

Capability issuance is a distinct authority-store operation, not silently an NK-02 crossing in the admission writer. If any predicate lives outside the chosen writer, the evidence marks it `early_only`; the selected profile must either supply a qualified coordination contract or remain unavailable where atomic enforcement is required. Do not claim same-writer coverage from adjacent SQLite files.

Trusted resource intake and publication preparation are explicit native prerequisites, with authenticated bridge peers and closed census entries under the existing resource, NK-03 and NK-05 owners. They cannot be satisfied by controller-generated resource/operation references or a shim approval ledger. The exact native interface is delivered and qualified through [M0](../../plans/2026-10-07-macos-integration/00-kernel-prerequisites.md); the first no-replace local publication is defined in [resources](10-project-resources.md) and its [M4 implementation plan](../../plans/2026-10-07-macos-integration/04-resources-publication.md).

The proposed `MacQualificationCaptureV1` extends that same intake/read/capture ownership for the [qualification verifier](17-qualification.md#semantic-verifier-algorithm). The signed LabCurator enrolls its private root before candidate ingestion and seals the inventory and input commitments. The native owner binds an attestation to the enrolled root resource/generation and OS identity, authenticated user/session/boot, curator identity, actual pinned verifier child incarnation and native-issued challenge, run nonce, candidate/applied-manifest/trusted-policy digests, monotonic validity and a one-use record. Only the authenticated native consume path can produce a verified read context after checking current scope; inherited `rootFD`/`proofFD`, code identity, hashes or caller-supplied fields alone cannot. Missing delivery returns `native_capture_contract_unavailable`. This establishes provenance and bounded read permission, never trusted candidate claims, an execution grant or a qualification verdict. [M0 Task 3](../../plans/2026-10-07-macos-integration/00-kernel-prerequisites.md#task-3-issue-precise-native-owner-handoffs) owns the native contract, source gate and adversarial acceptance; M8 owns the trusted launch wrapper and verifier integration.

## Ordering and commit discipline

The writer checks stop, closure fence, revocation, knowledge integrity, reservations and then writes the crossing record. Participant-local setup/authority checks remain mandatory inside the same savepoint. The crossing transaction implements a planned effect; it does not become a second state classifier.

Written crossing order is `(store_uuid, commit_sequence, member_ordinal)`. It is comparable only within one store. Check-only order uses the north-star discriminated position, including owner epoch and a per-owner check counter; it cannot reuse a written-position tuple. A sensor timestamp, UI row number, XPC request ID or subscription event cursor never substitutes.

The proposed normal side-effect path is intent commit, durable return record, outcome commit. Only eligible durable reads with qualified bounded redispatch use two commits. An integrity-tracked call cannot become check-only merely because its tool declares read-only. The Mac profile initially requires durable coverage for every agent invocation. Commit-count optimization is a later native performance gate, with no Mac latency target inferred from historical Linux measurements.

## Disposition of north-star contracts

NK-01, NK-02 and NK-03 are adopted as native prerequisites. NK-04 semantics are preserved in [recovery](11-state-recovery.md), including durable intent versus process-only stop. NK-05 is specialized to Mac input surfaces in [authority and integrity](04-authority-integrity.md). NK-06/NK-07 stay native owners; [delegation](16-delegation.md) adds host evidence, not new authority. NK-08 supplies notification semantics. Public witnessed logs, proof-carrying verdicts, generic live migration and resource-capability consolidation remain later native work, not implied by the first Mac profile.

Implementation acceptance is assigned to [M0 kernel prerequisites](../../plans/2026-10-07-macos-integration/00-kernel-prerequisites.md), then [M6 recovery and evidence](../../plans/2026-10-07-macos-integration/06-recovery-evidence.md). M1 may independently build read-only unavailable-state UX. M2 mutations wait for M0; execution waits for M6 and the relevant platform gate.
