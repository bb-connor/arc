The original finding descriptions and original line references below are retained as review history, not assertions about the corrected current schema.

1. **P2: Stop replies cannot report the required durability class.** Location: `contracts/common.schema.json:121-190`, especially the closed property set at line 190. `11-state-recovery.md:23` and MAC-REC-004 require distinguishing process-only restriction, durable intent latch and anchored stop. The complete stop reply has admission, worker, network, cleanup, external outcome and an opaque stop locator, but no durability field. `requested` or `fenced` cannot distinguish a process latch lost at host crash from an anchored stop; a digest-bearing opaque reference is not a documented durability discriminator. A conforming implementation therefore cannot expose the required fact through this closed wire contract. A read-only probe adding `durability: process_only` to the valid stop response is rejected by the current schema.

   Remedy: add a closed native-derived durability/result projection, including unknown/unavailable where necessary, to the common stop contract. Specify its mapping to NK-04 acknowledgement outcomes without deriving it from IPC success or local persistence. Add vectors for failed journal write, retained journal-only stop, anchored stop and uncertain commit; make the UI and M2/M6 tests consume that shared field.

2. **P2: A reconnecting client has no read-only method that returns current stop dimensions.** Location: `contracts/operator-response.schema.json:455-456` and `contracts/common.schema.json:70-119`; related operation read shape at `contracts/operator-response.schema.json:711-769`. `task.get` returns only task ID, operation reference, profile, coarse state and revision. `operation.get` returns only operation reference, coarse state and evidence reference. The sole stop-dimension response is the mutating `task.stop` reply. Consequently, when a stop progresses after its first reply or the app loses its local retry cache, the M1 read-only snapshot client cannot recover admission/worker/network/cleanup/external-outcome facts as required by `02-native-experience.md:13`, MAC-ARC-012 and MAC-REC-001. Reissuing a new stop changes authority; replaying an original stop is not specified as a current-state read. An opaque evidence reference has no wire resolver in this closed method set. Adding current stop facts to the checked-in `task.get` result is schema-invalid.

   Remedy: extend the existing `task.get` detail response with bounded current stop/closure facts and native state identity, preserving a compact list summary if desired. Define the current-fact versus retained-intent distinction explicitly. Add a disconnect/reconnect case where worker termination and external finality change after the initial stop response, then demonstrate a read-only refresh showing those facts without a fresh stop intent. Update the M1/M2/M6 mappings together.

3. **P2: Native subscription ends cannot be delivered before their required acknowledgement.** Location: `06-operator-protocol.md:53-55` and the closed union in `contracts/operator-event.schema.json:4-233`. The event vocabulary permits only `task.changed`, `coverage.changed`, `review.invalidated` and `stream.gap`. Yet MAC-IPC-019, M2 Task 5 and M6 Task 7 adopt the native retained-end acknowledgement protocol. The north-star unified-event-queue design H5a, line 582, requires the client to observe `SubscriptionEnded` before ACK, rejects ACK for a live entry, and retains the terminal marker/capacity until acknowledged; lines 585-590 require replay across reconnect/restore. No Mac event or read method tells the client that the subscription ended. An expired subscription can therefore silently stop producing hints and retain its native slot, while a conforming client cannot distinguish it from an idle live subscription or form the prescribed acknowledgement. A synthetic `subscription.ended` event is rejected by the current schema.

   Remedy: add an explicit hint-only terminal subscription variant with stable `subscription_id` and a closed safe reason. Specify native mapping, at-least-once replay, deduplication, owner-scoped acknowledgement and live-ACK refusal. Keep transport cursors outside acknowledgement identity. Include positive terminal/rebase vectors and negative live-ACK/wrong-session cases, plus a quiet-expiry native integration case. Define how native session terminal maps to transport termination separately.

4. **P2: The controller retry-cache key omits the protocol's method namespace.** Location: `../../plans/2026-10-07-macos-integration/06-recovery-evidence.md:140-150`. The proposed SQL primary key is `(owner_binding_digest, client_intent_id)`, and the owner binding is described as authenticated native owner/generation. Protocol section 06 line 45 scopes native idempotency by principal, method and intent ID. Valid `task.create` and `task.stop` requests from the same principal may reuse the same intent string in different method namespaces, but the prescribed cache collides and its digest comparison returns conflict before native dispatch. A SQLite reproduction with the proposed schema produces a unique-key violation for those two valid method-scoped intents. This is an availability/correctness defect, including possible rejection of a legitimate stop, rather than an authority bypass.

   Remedy: persist the closed method discriminator and include it in the primary key and every lookup/update/conflict query; alternatively define and test a method-bound key derivation explicitly. Hash only the canonical semantic parameters, with request IDs excluded, and preserve native ownership of final idempotency. Add cases for equal intent across distinct methods, same-method changed parameters, changed transport request IDs, wrong principal/generation and post-commit reply loss. The root reviewer has assigned this fix to the plan owner.
