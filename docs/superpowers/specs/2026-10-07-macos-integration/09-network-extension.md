# Network Extension restrictions and flow lifecycle

Status: Proposed normative design. Confidence: high in Apple API distinctions and inspected provider plumbing; moderate in the proposed derived-state design; unknown in installed per-task attribution and failure closure. Sources and immutable reuse evidence are in [Apple platform research](research/apple-platform.md). No Mac network profile is qualified by this document.

## Boundary and provider choice

The kernel authorizes a concrete model request, repository action, upload or message through a typed resource owner. Network Extension restricts transport and reports observations. A permitted host/port or an ES/NE process token does not authorize the application effect. Encrypted traffic, HTTP/2 multiplexing, custom protocols and broker-delegated networking make that distinction necessary.

The initial `vm-project-v1` has no network device and exports only through host brokers. It does not need global NE traffic interception to establish that configuration. `native-descendant-v1` needs independently qualified network containment and attribution. `managed-endpoint-v1` has a separate administrator-approved host-wide policy. A content filter system extension is the initial native restrictive candidate; [TN3134](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment) governs packaging and supported macOS rows. DNS proxy, transparent proxy and URL filter each have different coverage and failure behavior. No automatic provider substitution is permitted.

[Flow copying documentation](https://developer.apple.com/documentation/networkextension/handling-flow-copying) makes a crucial distinction: returning false from a transparent proxy hands the connection back to the operating system; it is not denial. A native profile relying on that provider must claim and explicitly close managed traffic on failure. A DNS-only rule does not mediate direct IP, encrypted DNS or cached destinations. [URL filters](https://developer.apple.com/documentation/networkextension/url-filters) integrate WebKit/URLSession; other stacks must participate voluntarily, so URL-filter evidence cannot cover arbitrary guest or native agent networking. Do not use a packet tunnel merely as a local filter or PF scripts as product policy: [TN3120](https://developer.apple.com/documentation/technotes/tn3120-expected-use-cases-for-network-extension-packet-tunnel-providers) and [TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api) define supported alternatives.

## Attribution contract

For each flow retain the provider/boot epoch, native flow handle, first-seen time, protocol/direction, OS-provided destination representation, source app audit token, source process audit token, UID and the host-enrolled process-incarnation mapping. Both audit tokens are optional. [App token](https://developer.apple.com/documentation/networkextension/nefilterflow/sourceappaudittoken) identifies the originating application; [process token](https://developer.apple.com/documentation/networkextension/nefilterflow/sourceprocessaudittoken) identifies the actual creator and may differ when a system process connects on an app's behalf. Record missing, conflicting, stale and delegated attribution as typed states, not empty strings that match all traffic.

Only a verified mapping to the frozen run/launch binding lets the provider label a flow `managed_task`. A bundle ID, signing Team ID, PID, port, DNS name or executable path alone is insufficient. Broker connections are attributed to the broker and linked to the native operation by the broker's own record; they are not falsely relabelled as worker-created flows. Shared broker pools cannot provide per-task transport closure unless separate connection custody proves which work each connection carries. Initial broker routes must use per-run pools or close a shared pool conservatively with all affected operations explicitly reconciled.

`unrelated_host` traffic follows explicit pass-through unless a separately installed managed-endpoint policy restricts it. `ambiguous` traffic never receives a task permit. If ambiguity can let a selected worker bypass containment, native execution is unavailable and the worker is stopped through the independently qualified containment owner. Blanket blocking unrelated Mac traffic is not an acceptable way to hide a missing mapping. Rules for DNS, loopback, link-local and helper-created flows must be demonstrated rather than inferred from a bundle identity.

## Derived restriction and convergence model

The extension receives authenticated native-derived restrictions through the controller's trusted provider channel, separate from [operator IPC](06-operator-protocol.md). The proposed internal snapshot includes installation/authority identity, user, provider epoch, scoped run/launch bindings, monotonic generation, canonical content digest, policy digest, durable stop-generation reference, restrictive rule set, authority absolute expiry and bounded local elapsed lifetime. Native objects remain opaque references validated by their owner. Local receipt/signature validation of a snapshot establishes provenance only; it does not mint new execution authority.

Rules are deny constraints over a declared scope. Initial state for a selected native worker is blocked until a qualified externally established boundary and current restrictions exist. `not_denied_here` means this layer adds no restriction; semantic admission still occurs at the native writer. Older generation is rejected. Equal generation/equal digest is an idempotent repeat. Equal generation/different digest quarantines the binding and closes selected flows. New generations install atomically, with restrictive merge during overlap. Independent administrator restrictions intersect task restrictions and may further deny. An extension cannot widen a capability, invent positive allow leases or renew itself offline.

An expired snapshot closes selected managed-task flows and rejects new ones. It does not silently remove a deny rule and allow the task. Expiry is the earlier of native authority expiry and non-extending local elapsed validity. Backwards wall-clock movement, sleep/wake, provider restart, loss of trusted time or inability to establish freshness requires reconciliation, never a fresh local TTL. A known current native denial must take effect immediately; TTL is only a stale-state bound and cannot establish current crossing authority.

The state machine is `unconfigured -> synchronizing -> restricting -> degraded/closing -> stopped`; transitions carry actual generation and flow counts. `restricting` requires successful local installation and existing-flow reconciliation. Stop reports native admission fence, desired restriction generation, observed provider generation, last flow-close attempt, remaining/unknown flows and last independently measured convergence separately. No API return or heartbeat alone proves all existing flows are closed.

[Updating a flow verdict](https://developer.apple.com/documentation/networkextension/nefilterdataprovider/update(_:using:for:)) is an available mechanism, not a universal proof. The implementation retains each eligible socket-flow handle until terminal observation, updates it to drop on revocation and denies new matching flows. TCP keep-alive, HTTP/2 streams, UDP/QUIC, changing DNS answers, inbound/listener connections, queued buffers and both directions need explicit tests. Bytes already delivered cannot be recalled; remote side effects stay completed or unknown according to native reconciliation. A content-filter allow that removes future interception cannot be assumed revocable unless the exact OS behavior is demonstrated. Failure to retain effective revocation control leaves that native profile unavailable.

The checked [Clawdstrike provider](https://github.com/backbay-labs/clawdstrike/blob/b9515321f4a20bd676dfef88bdf3ba4d015bc6e9/apps/agent/src-tauri/macos/system-extension/network-extension/Sources/ClawdStrikeNetworkExtension/ContentFilterProvider.swift#L659-L829) supplies real allow/drop and reload plumbing. Its [policy input](https://github.com/backbay-labs/clawdstrike/blob/b9515321f4a20bd676dfef88bdf3ba4d015bc6e9/apps/agent/src-tauri/macos/system-extension/network-extension/Sources/ClawdStrikeNetworkExtension/EgressPolicy.swift#L1-L106) matches normalized host/port restrictions and TTL. Reuse requires replacing that insufficient task identity and testing active-flow revocation; it is not already a Chio run authority layer.
