# Shared desktop operator protocol and Mac transport

Status: proposed contract, 2026-10-07. `chio.desktop.operator.v1` is a new shared operator proposal. It is not the installed kernel ABI, a replacement native approval format, or an alias for `chio.omarchy.operator.v1`.

## Transport and identity

The Mac app uses an authenticated XPC service carrying bounded JSON bytes in fixed request/reply methods and a fixed event delivery callback. A CLI reaches the same authenticated service through a signed bridge. The public protocol does not expose a localhost HTTP listener. Before decoding sensitive data, validate service/caller designated signing requirements, UID, audit session and the registered endpoint identity. Associate the connection with the current native principal using the delivered kernel binding contract.

Decode UTF-8 strictly; reject duplicate keys, invalid Unicode, nonfinite numbers, unsafe integer values, unknown fields and unknown methods. Limit each envelope to 65,536 bytes and nesting to 16; limits apply before buffering an entire attacker-controlled stream. The byte codec uses RFC 8785 canonical JSON when it commits or hashes an envelope. Native signed objects are opaque references, verified using their own registered native encoding and verifier. Do not reserialize signed native payloads through Swift's generic dictionaries.

Allow at most 16 in-flight requests per connection, 64 queued events per subscription and 100 items per page. A request times out at the operator transport after 30 seconds; timeout does not cancel or undo an admitted effect. Native work duration uses a separately admitted limit. Queue overflow emits a gap and requires snapshot reread. Event payloads contain no document bodies or reusable credentials.

## Envelopes and native references

The [schemas](contracts/README.md) are authoritative for proposed JSON field shapes. Requests have `version`, `request_id`, `method`, and `params`. Responses repeat version, request ID and method, with exactly one success result or classified error. `request_id` is a transport correlation value. A mutating `intent_id` is stable over retries by the same authenticated principal/method and parameter commitment; neither is a native operation identity.

Native references contain `kind`, `issuer`, `native_id`, `generation`, and `digest`. They are locators into a registered authority owner, never arbitrary URLs to fetch. Only the native verifier establishes ownership, subject binding, freshness and content. Decimal generation and budget fields use canonical nonnegative decimal strings. Monetary units are explicit; the initial operator example uses USD minor units, not floating-point dollars or arbitrary token pricing.

Every successful `task.create`, `task.stop`, `approval.submit` and `evidence.export` response requires `result.request_binding`, using the same closed per-method parameter definition as its initiating request. The client compares that whole typed object with the validated request's `params`; omitted, extra or changed fields fail correlation even if the individual response is shape-valid. Native reference equality includes all five fields, not only a display label, native ID or digest. Canonical decimal values, limits, scope and selected profile are compared without coercion. Existing result echoes, including stop `task_id`/`scope` and approval `operation_ref`/`decision`, must also agree with the request and its binding.

| Mutation | Complete `request_binding` fields |
| --- | --- |
| `task.create` | `intent_id`, `template_id`, `resource_ref`, `input_ref`, `grant_ref`, `execution_profile`, `limits` including `max_cost_minor`, `currency` and `max_wall_seconds` |
| `task.stop` | `intent_id`, `task_id`, `scope` |
| `approval.submit` | `intent_id`, `operation_ref`, `review_ref`, `endorsement_ref`, `decision` |
| `evidence.export` | `intent_id`, `task_id`, `format`, `destination_ref`, `grant_ref` |

The binding is structural correlation, not signed authority. A server echoing attacker-selected parameters does not establish a grant, approve an export or prove an effect. The authenticated native owner must separately bind the returned original operation and evidence to the same principal/method/intent/parameter tuple and current read/release scope. Export therefore cannot accept another task's evidence, destination generation or grant merely because the returned operation/evidence reference has the right shape. A mutation error with a nonnull `error.operation_ref` requires `error.request_binding` equal to the entire initiating `params`, as well as native verification of that original operation. An error without an operation reference may omit that binding, allowing invalid requests to fail before a complete parameter tuple exists. A lost response preserves the original tuple rather than allocating replacement authority.

The controller's hello/session identity authenticates a connection and binds its selected wire version. It does not mint agent authority. A connection must complete hello once before other methods. Repeated hello with a different nonce/version on the same connection closes it; reconnect creates a new transport session without creating a new native operation or grant.

## Closed method set

| Method | Meaning and native boundary |
| --- | --- |
| `hello` | Negotiate exactly one supported operator version and establish the transport session |
| `health.get` | Read redacted feature prerequisites; no credentials or arbitrary filesystem probing |
| `tasks.list`, `task.get` | Read principal-scoped native projections, including full current stop state, with bounded pagination |
| `task.create` | Request fixed `project-change-v1` template using native workspace, sealed task-input and grant references, selected qualified execution profile and attenuated limits |
| `operation.get` | Reconcile the original native operation reference, including unresolved outcome |
| `task.stop` | Request task or task-and-descendants stop through the native owner; return separate stop dimensions |
| `review.open` | Read the complete bounded native exact-review projection for an existing operation into the trusted app; no caller-provided URL or file lookup |
| `approval.submit` | Forward native review and endorsement references plus the exact decision to the native approval owner |
| `events.subscribe` | Allocate a stable subscription ID and bounded hint cursor; mark rebase explicitly |
| `events.ack` | Acknowledge an observed native-ended subscription for this authenticated session using its stable ID; a live subscription refuses acknowledgement |
| `evidence.export` | Request a redacted evidence bundle into an enrolled destination resource under native export authority |

The trusted review component obtains a native decision record through the delivered approval-owner interface. `approval.submit` checks decision equality and consumes/records it under that native contract. It does not transform a UI boolean, biometric success, browser event, or message arrival into endorsement. If the native review or decision-binding interface is missing, review and submission are unavailable.

Selecting a new source or destination is a trusted enrollment interaction, governed by [resource contracts](10-project-resources.md), before those references are used here. This version intentionally has no generic path-open, shell, settings-write, provider-secret, arbitrary app automation, or task-resume method. Recovery uses original native operation reconciliation and an explicit later typed contract if continuation needs new authority.

The trusted native publication-preparation bridge similarly returns a retained native operation before `review.open`. It accepts only a sealed artifact and enrolled destination under the closed owner contract; it binds exact content, parent identity/generation, filename, absent-target condition and current policy/influence. It cannot publish before native approval/admission. This is an M0 resource/approval prerequisite, registered in the same census, not an unlisted public operator mutation or a reuse of evidence export.

`input_ref` identifies a sealed task-input resource containing the user's task objective. It is distinct from the project `resource_ref`; neither can substitute for the other even though both use the native resource reference shape. The native owner verifies each resource's registered type and generation. Bootstrap influence joins before agent readiness; authentic operator input requires the native assertion contract if it is to carry an endorsed integrity level. Raw prompts and their potential secrets stay outside operator event/diagnostic payloads.

## Aged operational health

`health.get` returns its descriptive summary (`state`, `available_profiles`, `missing_prerequisites`, `policy_generation`), required `observation_scope`, and a required closed `observations` object. The scope contains `kind: authenticated_session`, the current hello `session_id`, and `evaluated_profiles`, a unique array of at most six named profiles. `available_profiles` must be a subset of that declared set. The native adapter verifies the complete evaluated scope; a caller cannot omit a configured profile to improve health. The client binds `session_id` to its current authenticated hello/transport context and invalidates cached health on session or principal change. An empty evaluated set has no available profiles and establishes no profile readiness.

The observations conservatively aggregate all ten dimensions below across that declared authenticated-session scope, matching [operations](14-operations.md#at-mac-ops-012-multidimensional-health). They are not per-profile verdicts. In particular, VM-only provider inapplicability cannot establish native-profile health, and one profile's success cannot hide another evaluated profile's missing required mechanism. A dimension cannot be omitted because its provider is absent. Compatibility is an independent observation in addition to the nine operational dimensions; a working connection cannot establish any of them.

| Observation key | Required `source` | Meaning of an observed satisfied state |
| --- | --- | --- |
| `connectivity` | `transport` | The scoped service transport is currently reachable |
| `authentication` | `peer_authenticator` | The actual peer, user and audit-session binding has been authenticated |
| `compatibility` | `compatibility_verifier` | The installed native/component tuple satisfies the scoped compatibility checks |
| `permission` | `platform_permission` | Required OS permissions for the declared scope have current observations |
| `activation` | `platform_activation` | Required services/providers are actually activated |
| `convergence` | `restriction_owner` | Applicable restrictive generations are observed as converged |
| `coverage` | `coverage_observer` | Required observation coverage has no undisclosed gap in the stated scope |
| `storage` | `native_store` | The native store reports the required current storage/durability readiness |
| `authority` | `native_authority` | The native owner reports its current authority readiness, without authorizing a particular operation |
| `closure` | `closure_owner` | The scoped native/worker/provider closure obligations have been reconciled |

Each observation requires `state` (`satisfied`, `unsatisfied`, `unknown`, `not_applicable`), `freshness` (`fresh`, `stale`, `unknown`), the fixed `source`, `source_instance_id` (bounded identity or null), `age_ms` (integer 0 through 2,147,483,647 or null), and `max_age_ms` (integer 1 through 300,000). `fresh` requires an identified source instance and known age no greater than `max_age_ms`. A stale or unknown observation has `state: unknown`. Stale requires a known source instance and numeric bounded age; missing source or age requires unknown freshness, with null age. When no sample is available, `source_instance_id` may be null and freshness must be unknown. The owner supplies a policy-bounded maximum age; a client cannot renew an old observation by choosing a larger limit. Age derives from a supported clock mapping for the same source incarnation; reboot, lost mapping or an unverifiable source makes freshness unknown, and age beyond the freshness bound makes it stale while its numeric age remains representable.

`age_ms` is a snapshot, not a renewable cache lifetime. Before presenting a fresh cached observation, the client adds a conservative qualified bound for response transit and local monotonic elapsed time since receipt to the reported age. Crossing `max_age_ms` makes it stale/unknown without waiting for an event. An unsupported source-clock/transit mapping, sleep or reboot that invalidates the elapsed-time bound, or a source-incarnation change makes freshness unknown until an authenticated reread. A schema-valid old response cannot remain fresh indefinitely, even if its transport ID once correlated correctly.

`not_applicable` requires a fresh native-owner observation that no profile in the entire evaluated set requires that dimension; absence, denied permission or an uncontactable owner is unknown or unsatisfied. Top-level `state: ready` requires a nonnull current native `policy_generation`, no missing prerequisites and every dimension fresh with state satisfied or explicitly not applicable. Unknown/unavailable diagnosis may retain a null policy generation; a missing generation cannot become ready. A stale provider heartbeat cannot satisfy convergence or coverage, and a healthy store cannot imply fenced admission or external closure. Even ready health, listed profiles and complete schema validation confer no grant, per-profile verdict or qualification: each mutation still requires current native qualification, authenticated scope and per-operation admission. Unknown/degraded health retains bounded read-only diagnosis without exposing another user's state.

## Exact review content delivery

A successful `review.open` returns the initiating `operation_ref`, the native `review_ref`, `presentation: trusted_native_review`, an informational `expires_in_seconds`, and a required inline `projection`. The response's operation reference must equal the initiating request. The projection is delivered over the authenticated peer/session-bound channel after the native review owner resolves that exact prepared operation and verifies the caller's review authority. Releasing sealed bytes to the reviewer is itself a registered native resource-read/release route with current read scope, policy and declared stop disposition; an operation locator alone does not authorize this disclosure. The app obtains all security-relevant review content from this response; no hidden content-fetch method, arbitrary filesystem path, URL or app-created content store supplies missing fields.

The initial closed projection is `local_artifact_publication_v1`, covering creation of one new small UTF-8 text file, including a patch file, under `publication-v1`. It does not apply the patch or publish an artifact directory. Binary files, directory manifests requiring multi-file inspection, remote effects and other native operation kinds return `prerequisite_unavailable` until a separately reviewed projection is delivered. A general resource reference never enables an undocumented reader or permits the app to read the referenced object directly.

| Projection fields | Native source and exact presentation |
| --- | --- |
| `operation_state: prepared`, outer `operation_ref` and `review_ref` | One native materialization for the existing operation; another operation, consumed review or unresolved original cannot supply an actionable projection |
| `binding.native_action_digest` | Digest of the native canonical action under its native encoding/domain; the adapter verifies the projected action fields against that materialization, not against a hash of arbitrary JSON display text |
| `binding.policy_digest`, `policy_generation`, `deployment_digest`, `influence_commitment`, `deciding_principal` | Current native policy/deployment, knowledge-journal commitment and authorized deciding principal from the same native review record; generation changes invalidate the review |
| `binding.valid_from`, `expires_at` | Absolute native validity interval; native authority time must be inside it. The relative expiry is an informational countdown no greater than the remaining native interval, capped at 300 seconds; reread or reconnect cannot extend the original interval |
| `artifact.resource_ref`, `manifest_digest`, `content_sha256`, `byte_length`, `content_encoding: utf8`, `content_utf8` | Exact sealed single-file artifact and manifest. The complete inline text encodes to precisely the sealed UTF-8 bytes; byte length and SHA-256 are verified against native custody before delivery. A patch is shown as the exact patch bytes that will be saved |
| `destination.resource_ref`, `directory_display`, `filename_hex` | Enrolled directory identity/generation, native-resolved human-readable location and exact final filename bytes encoded as lowercase hex. The location label is inert presentation, not a path to resolve. Decode the filename solely for escaped display and Copy Exact; the broker uses the native bound bytes and directory handle |
| `effect: create_file_no_replace`, `expected_target: absent` | Create exactly that file and refuse an existing target; no overwrite, alternate filename, hook, execution, upload or patch application |
| `cost.max_cost_minor`, `currency: USD` | Native-approved maximum charge for this publication operation in explicit minor units, including zero; the bound must agree with the canonical action and native reservation |

The native adapter verifies every projected field against the same frozen review record, including both resource identities/generations, artifact manifest and bytes, exact filename, action, cost, deciding principal, policy/deployment, current influence and validity. It never marks a caller-provided dictionary verified or synthesizes a positive review from display labels. Native signed bytes and digest domains remain native; neither the schema nor a self-consistent content hash establishes native authenticity. A field mismatch fails before the content becomes actionable. The trusted decision component retains the unchanged operation and review references and uses the native decision-binding interface; `approval.submit` and the eventual crossing recheck the same exact native materialization and all current predicates.

The schema bounds `content_utf8` to 8,192 Unicode scalar values, the location label to 1,024, and the filename to 255 decoded bytes. The native adapter additionally limits the full artifact to 32,768 UTF-8 bytes and the encoded response to the existing 65,536-byte/depth limits. It validates filename bytes under the resource contract. This pilot returns the complete file or refuses review; it must not truncate, substitute a summary, return an ellipsis as content, or offer approval while hidden bytes require another retrieval. The app uses an inert scrollable full-content view with selectable escaped identities and no executable markup, preview subprocess, network fetch or automatic file open.

`review.invalidated`, expiry, a peer/session change, a transport gap, or a known change in any bound native fact makes the cached projection stale and removes its submission control until an authorized `review.open` supplies current content. The absence of an invalidation hint is not evidence of freshness: native decision retention and crossing always revalidate. Unsupported or oversized content remains explicitly unavailable for publication; separate artifact inspection does not silently qualify this review contract.

## Mutation, ordering and recovery

For each mutating request, the native owner binds authenticated principal, method, intent ID and canonical parameter commitment atomically before dispatch. Equal retries resolve the original operation; unequal reuse is conflict. The controller may cache the mapping only as a projection. A crash between dispatch and response must be resolved through native original lookup before any repeated dispatch. If that contract is absent, the method is unavailable rather than locally journaled as a new authority engine.

The serving writer serializes crossing authorization with stop, revocation, integrity state and reservations. Two controller connections cannot bypass that serialization. A stop response may say requested while worker, network and external outcome remain unknown. A prior committed intent may still take effect; post-return release is independently checked. `internal_unavailable` and `outcome_unknown` must never be translated into a fresh create intent.

Stop responses and authoritative task rereads include `durability` as `unknown`, `process_only`, `latch_only`, or `durable`, using the native meanings in spec 11. `admission: restricted` reports a partial/local restriction; `fenced` requires durable native stop evidence, and `durable` requires a native stop reference. Schema checks only those structural implications; the native verifier establishes the actual evidence. Every task projection includes `stop_state`: null means the native owner confirms no stop request for that task generation at the observed revision, not an unknown stop outcome. If that fact cannot be established, return an unavailable/error or explicit unknown stop state. `task.get` and `tasks.list` therefore recover progress after reconnect without issuing a second stop mutation.

Every nonnull `stop_state` retains `scope` as `task` or `task_and_descendants`. All admission, worker, network, cleanup and external-outcome facts apply to that retained scope, verified against the native stop record and current task generation. Task-only closure never implies descendant closure. Rereads preserve scope even after the original `task.stop` response is lost; for the same retained native stop, the response's flattened `scope`, its `request_binding.scope` and the task snapshot's `stop_state.scope` must agree. A later native stop may change the current reference and scope only through its own authorized record.

Task `state: stopping` and `state: stopped` require a nonnull `stop_state`; active `created`, `running` and `awaiting_review` task states require null stop state. Stopping preserves pending or unknown closure observations. Stopped requires `admission: fenced`, `durability: durable`, a verified native `stop_ref`, `worker: terminated` or explicitly `not_applicable`, and `network: closed` or explicitly `not_applicable`, all for the retained scope. Not-applicable dimensions require native profile applicability proof, never a default for a missing observer. Process-only/latch-only restriction, an unknown worker or open/unknown network cannot project stopped. Cleanup and external finality remain independent: a stopped task may truthfully have pending/unknown cleanup and an unresolved original external effect, both visibly retained. It must not become completed, harmless cancellation or known outcome from worker exit. Completed with nonnull stop state additionally requires all applicable stop closure, cleanup, external outcomes and releases accounted for, including `cleanup: complete` and `external_outcome: known`. These rules apply to `task.get` and every `tasks.list` entry, independently of the last transport reply. `task.create` returns identifiers and a disposition rather than task state; its acknowledgement cannot substitute for an authoritative task reread.

Successful `task.stop` replies echo both the exact requested task and scope (`task` or `task_and_descendants`); clients reject missing or substituted scope even when task identity agrees. This binds the requested operation, not a claim that all stop dimensions succeeded: native evidence must still establish the reported scope/dispositions, and requested/unknown values remain distinct from durable fencing.

Errors use a closed code and a safe `message_key`, not a raw exception or secret path. `retry` is `never` or `reread` for methods without an `intent_id`. Only `task.create`, `task.stop`, `approval.submit` and `evidence.export` may additionally return `same_intent`, which requires retaining the original principal/method/intent/parameter tuple. A retry hint cannot enlarge native permission; no client invents an intent for a read, handshake or event method. Authentication failure, stale references, conflicting intent reuse and unmet prerequisites are distinguishable. Native operation references in errors are included only if authorized for the caller.

## Events and shared-platform migration

Events are `task.changed`, `coverage.changed`, `review.invalidated`, `stream.gap`, or `subscription.ended`; every event has `hint_only: true`. Consumers reread the relevant native state. The cursor is controller transport state, not a kernel crossing order, ES sequence number, provider generation or evidence completeness proof.

Stable `subscription_id` values are never reused within the authenticated native session and are retained with their acknowledgement disposition according to the delivered native event contract. Rebase and acknowledgement serialize through that owner. A prior subscription cannot be resurrected by a stale publisher; an acknowledgement for another session is rejected. Controller restart either restores the native subscription binding or reports a new transport subscription with an explicit gap. It never acknowledges a native subscription based only on a local transport sequence.

`subscription.ended` projects the native retained terminal for that exact stable subscription. The native owner retains and replays it across dropped delivery/reconnect until an authorized acknowledgement succeeds. A client attempts `events.ack` only after observing this terminal; the owner independently checks ended state and refuses acknowledgement of a live entry. A terminal hint does not itself grant authority or prove that every preceding event was received. Gaps still require reread, and a local transport gap/closure must not fabricate a native terminal. An already acknowledged tombstone returns `already_acknowledged` only to the owning authenticated session and is never reused as a new subscription.

The reason mapping is total over the pinned NK-08 owner: `Revoked -> revoked`, `Expired -> expired`, `AuthorityTimeUnavailable -> authority_time_unavailable`, `AuthRotated -> auth_rotated`, and `SubjectGone -> subject_gone`. A newly introduced owner reason requires an explicit compatible contract update; unknown variants close the adapter's compatibility gate rather than being mislabeled. Transport overflow is `stream.gap`, not a fabricated native terminal. All five native reasons have synthetic contract fixtures, including quiet expiry.

The Omarchy adapter continues to support its existing version. M2 introduces a compatibility map for shared method semantics, identity, bounds, errors and stable subscription behavior. Migration requires explicit negotiation and fixture evidence in both adapters. Mac wire-contract acceptance cannot qualify Linux or change the old ABI in place.
