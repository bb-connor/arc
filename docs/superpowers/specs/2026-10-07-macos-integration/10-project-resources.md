# Project generations, typed resources, and exact publication

Status: proposed normative design, 2026-10-07. This is a resource contract and qualification target, not a claim that an importer, broker, native app adapter or publication path exists. Confidence: high in the need for immutable inputs and separate authority; moderate in the candidate implementation; unknown until race and crash qualification passes.

Dependencies: [kernel contracts](03-kernel-contracts.md), [authority and integrity](04-authority-integrity.md), [operator protocol](06-operator-protocol.md), [VM execution](07-vm-execution.md), [recovery](11-state-recovery.md), [privacy](13-privacy-performance.md), and [workflow research](research/macos-workflow.md). The protocol owns wire fields and opaque reference types. This document defines semantic obligations; its inventory tables are not an alternate wire schema.

## Foundation before worker integration

This resource track has two implementation slices. The foundation is native selected-resource/task-input capture, committed-tree import, path/materialization validation and model-resource export/budget mediation. It can be implemented and tested after M0/M2/M6 without M3, and supplies the resources needed by the first useful VM task. In the [resource plan](../../plans/2026-10-07-macos-integration/04-resources-publication.md), execute Tasks 1, 3, 2 and 5 in that dependency order.

Worker/output and publication integration consumes the available M3 backend, then adds Task 4 external-oracle output sealing and Tasks 6-8 exact publication and combined qualification. The VM plan's backend Tasks 1-7 precede actual-worker Task 4; VM qualification Task 8 and the resource plan's integrated acceptance follow. Final installed-profile qualification is a release gate after these integrated tests, not a prerequisite for implementing the foundation or exercising the candidate backend in the controlled qualification harness. The first sealed local result does not require publication to be enabled.

## Resource and authority boundaries

The worker receives task-scoped references to resources, not ambient filesystem paths, account tokens, security-scoped bookmarks, Keychain credentials or unrestricted host file descriptors. The selected host broker resolves a reference only for its native owner, principal/run, permitted action, immutable generation, expiry, budget and current stop/policy state. The native kernel issues and verifies that authority. An app selection bridge can convey a bounded security-scoped URL or descriptor to a trusted importer through the host architecture's authenticated native intake; it cannot add raw paths to `task.create` or mint the opaque resource reference returned by native authority.

| Resource | Permitted first operation | What the reference does not imply |
| --- | --- | --- |
| Task objective | Capture bounded user instructions into a separate immutable task-input resource and join bootstrap influence. | Shell execution, replacement of the project resource, or trusted integrity merely because text came from the operator UI. |
| Selected project | Capture one explicitly selected committed tree. | Live checkout writes, dirty-directory snapshot, arbitrary `.git` configuration execution or access outside selection. |
| Sealed source generation | Read bounded immutable content inside one worker. | Host path access, submodule fetch, Git LFS resolution, credential delegation or future repository revisions. |
| Provider/model route | Export admitted request bytes and consume bounded economic resources through the broker. | Raw provider bearer token, arbitrary endpoint, silent provider failover or unrestricted model context. |
| Worker output | Transfer bounded files to host quarantine for sealing and review. | Automatic release, opening executable content or trusting worker-supplied test success. |
| Publication destination | Propose creation of one exact artifact at one chosen destination. | Overwrite, append, adjacent-directory writes, remote publish or reusable endorsement. |
| Native app capture | Later: obtain a specific selected immutable representation. | Mailbox-wide reads, background surveillance, draft or send authority. |
| Native app draft | Later: create or update a specific draft under its own contract. | External delivery, sharing, calendar invitation, or arbitrary GUI operations. |

OS file consent permits platform access to a selected location. A Chio resource grant permits a principal to use a typed resource. An exact endorsement authorizes a bound concrete consequential effect under the native contract. Revoking one does not rewrite the historical truth of the others. Scope acquisition is balanced, cancellation releases it, stale bookmarks produce a reselect flow, and sharing bookmarks across processes is qualified for the exact sandbox/signing arrangement rather than assumed.

## Committed Git generation

The first generation consists of the full selected commit and tree object identities plus a canonical manifest of bounded regular-file content, modes and exact path bytes. Import reads objects, not the working tree, index, filters or checkout output. A cryptographic content store additionally commits each blob using the kernel-selected digest. The Git object identity alone is not an approval or a trust label. An annotated tag is resolved to a displayed commit before review; a moving branch name never remains the input identity.

The first importer rejects submodules/gitlinks, symbolic links, non-UTF-8 names, unsupported object formats, LFS pointer-only inputs when the template requires actual content, missing objects, promisor/lazy fetch and external object-store alternates. These are explicit unsupported cases, not silently skipped files. It supports regular modes 100644 and 100755 with the executable bit recorded. Repository hooks, smudge/clean filters, textconv, replace refs, arbitrary Git aliases, global/system configuration and credential helpers do not execute during import. Sparse working-tree state does not redefine the selected commit. Linked worktrees need a separately validated common-object-store selection; the pilot may reject them with an explicit message rather than follow a `.git` text pointer outside authority.

Import first captures and verifies the selected commit object, then traverses its immutable tree references, validating every returned object and bound before insertion into host-owned storage. Concurrent `HEAD` changes cannot change that selected identity. Corruption, deletion by garbage collection, truncated reads or digest mismatch abort the incomplete generation. Nothing becomes visible to a worker until the complete manifest and all objects are durable and verified. Successful import therefore represents one Git generation even if files change concurrently; it makes no snapshot claim about the working tree.

Git paths are byte identities. Display normalization, Unicode normalization and case folding cannot identify a file. The importer validates components before materialization: no absolute path, empty component, dot/dot-dot, NUL, embedded slash, excessive depth or length, duplicate exact name, or protected metadata path. The candidate pilot rejects case-insensitive and Unicode-normalization collisions conservatively even when its Linux guest could represent them. It verifies the actual target filesystem mapping and fails if two source names resolve to one target object. Include composed/decomposed accents, Turkish I, sharp S, bidi controls, trailing dots/spaces, names differing only by case, newline/tab and leading hyphen in qualification. Escaped UI display does not alter manifest bytes.

APFS case-sensitive and case-insensitive volumes are separate test cells. APFS clones are acceptable storage optimizations only after the immutable generation is established; individual clones do not prove a coherent whole-tree snapshot. Materialized files have normalized ownership and permissions, no inherited ACLs, extended attributes, resource forks, Finder aliases, quarantine changes or hard-link relationships imported implicitly from the source checkout. The output format records the intentional executable bit. Source metadata needed by a future template requires an explicit typed contract. Any bounded raw object-store staging used by the reader is private intake scratch, not a resource exposed to the worker; only the selected verified graph enters the sealed generation. Delete raw intake scratch after sealing or failure according to the retention policy.

## Dirty input is a gated feature

Dirty imports remain unavailable in the first profile. The UI can use the selected committed revision while clearly excluding dirty changes, or let the user create a commit outside the task. A later dirty-input gate requires either a qualified coherent snapshot containing the whole resource set or enforced writer exclusion that covers existing writable descriptors, memory mappings, coordinated and uncoordinated processes, rename/unlink, hard links and external provider updates. Pre/post hashes, FSEvents, advisory file coordination, denying new opens, or sequential cloning do not establish that property. A stable-looking mixture of two moments is a failure even when each file hashes correctly.

## Output, tests and sealing

Worker output arrives through a bounded protocol into a host-owned quarantine generation. The host does not follow links, preserve hard links, accept devices/sockets/FIFOs, execute postprocessing chosen by the worker, or open content in another app automatically. A manifest identifies every regular file, original input generation, artifact type and length, content digest, fixed external-oracle/case identities and exact candidate-invocation/result references. Files missing from the manifest or added after sealing invalidate the candidate.

The host independently checks edit allowlists, output byte/count/depth limits and test-evidence bindings. The trusted fixed test oracle is a data-only evaluator outside the candidate worker and guest. Candidate code executes only in the qualified worker. The oracle consumes bounded captured data, compares it against fixed expected observations and never imports candidate code, evaluates worker-supplied expressions, loads repository plugins or executes repository test scripts. Keeping an immutable unittest file inside the candidate Python process is insufficient: candidate imports can monkeypatch assertions or terminate that process with exit code zero.

Before each test invocation, the trusted supervisory lane binds the exact sealed candidate artifact generation/content, executable/runtime, fixed argv and inputs, case identity and fresh invocation identity. It exclusively attributes bounded stdout/stderr and completion evidence to that invocation and preserves the binding through native custody. The oracle's verdict and case-set identity bind to the same artifact later reviewed/published. Worker-supplied digest strings, reported PASS, framed guest messages or an authenticated VM connection alone do not prove code identity, output attribution or completion. The VM/supervisory qualification must establish these properties independently of candidate control; if a compromised guest can forge them, the result is unverified and the profile cannot claim verified tests. Reuse of a result for a changed artifact or another invocation is rejected.

Success requires every fixed case to have exact expected bounded output, the specified completion disposition and valid supervisory attribution. Exit code zero alone is insufficient. Monkeypatching unittest while returning wrong output, os._exit(0), forged PASS/verdict text, empty output, missing cases, early exit, truncated streams, missing completion and source substitution each fail or remain unverified. Crashes and exceeded limits cannot become passed tests. These tests establish the specified observable behavior only; they do not prove every behavior of arbitrary code. Native kernel output-release admission joins the worker-derived influence and checks current policy, stop state, budget and requested destination. An intent committed before a stop can have a distinct outcome, while later artifact release still requires its own current crossing.

The sealed artifact is immutable and reviewable locally. Inert diff rendering is the default. The first `publication-v1` review selects or derives a separately sealed single UTF-8 text/patch file from the output, retaining its output-generation provenance and influence. Its complete bytes must fit the [inline exact-review contract](06-operator-protocol.md#exact-review-content-delivery). A multi-file output can remain sealed for local inspection, but directory, binary, oversized and ambiguous-name publication is blocked in this pilot; no hidden content-fetch interface fills that gap. A preview generator is a constrained renderer with no scripts, host credentials, external network or live filesystem traversal.

## Local publication transaction

The first publication target is a new artifact or patch file under an explicitly selected existing directory on the qualified local filesystem. It is a separate operation under `publication-v1`. A narrow trusted native publication-preparation interface binds the selected sealed artifact and enrolled destination and obtains the native operation; the operator then uses `review.open` and `approval.submit`. This prerequisite belongs to the native resource/authority owner. It is not a new public operator method, a path-bearing `task.create`, or a misuse of `evidence.export` to export arbitrary artifacts. If the native preparation contract is absent, publication stays unavailable. The native proposal binds the exact sealed bytes/manifest, selected destination directory identity and generation, final filename bytes, no-replace semantics, effect kind, principal, relevant influence, policy state and budget. Exact field encoding belongs to the operator/native contract. A filename change, destination substitution, artifact change or changed relevant authority invalidates the review.

The broker holds a validated directory descriptor, creates a same-volume unique staging file with exclusive/no-follow creation, writes bounded verified bytes, durably seals it, and performs a qualified no-replace atomic installation to the reviewed name. It records a native operation-to-effect association durably for recovery. It refuses a pre-existing destination, symlink substitution, alias to another directory, moved/invalidated selected destination identity, unqualified network/file-provider volume or changed authority. It never silently chooses a different name or overwrite mode. Visibility can precede durable outcome recording; a crash in that gap is a recovery case, not license to repeat.

Recovery uses the original native operation and retained staging/effect identity to establish whether its exact install occurred. Finding an unrelated file with equal bytes is insufficient to prove this operation succeeded. If the filesystem/recovery mechanism cannot prove original effect association after a crash or user tampering, retain unresolved outcome and block retry. Successful local publication is not remote upload, commit creation, push, mail delivery or application of the patch.

Git branch publication is a subsequent broker gate. It binds repository/account/remote endpoint, exact commit/tree and parent identities, ref name, and expected old ref. Compare-and-swap applies at the authority that owns the actual ref; merely re-reading a branch before `push` is not atomic exclusion. Lost replies query/reconcile the original effect using the qualified provider contract, and observing the desired commit alone cannot establish that this operation caused it. Credentials stay in the broker. Force push, hook execution, signing, submodule recursion and new destinations need separate capability scope. Automatic writes into a live checkout remain unavailable until a transactional conflict/rollback contract covers concurrent editors, open descriptors and paths.

## Browser, clipboard and app resources

These are later, independently gated resource contracts. Explicit capture records source identity, capture time, exact representation/digest, native resource generation and origin labels before bytes reach the worker. Clipboard content may originate on another device via Universal Clipboard; a paste action does not prove authorship or trust. Browser URLs, redirects, selected ranges, retrieval account and fetched content are captured as provenance, not permission to follow every link. App signatures authenticate software identity and never endorse document text.

Capture, draft, modification and publication are distinct operations. Saving a draft may already synchronize remotely or notify collaborators; that actual effect must be disclosed and admitted. A mail draft broker must bind account, recipients, subject, body and attachments independently of later send. Calendar operations must distinguish private local draft from server event/invitation. Generic Apple Events/Accessibility access is OS consent, never a typed effect grant. An opaque native resource reference, an opaque review reference and an opaque endorsement reference are independent and cannot be substituted for one another.

General GUI actions remain gated until each consequential route can bind the meaningful effect and reconcile its original outcome. A screenshot, an accessibility label and a click coordinate are not a stable remote transaction identity. Unknown outcome after a send click remains unknown; automation must not click Send again to obtain a screenshot of success. Summaries, OCR and transformed captures preserve joined source influence under the kernel integrity contract.
