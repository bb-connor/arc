# Endpoint Security and native descendant execution

Status: Proposed normative design. Confidence: high in source/API distinctions; moderate in bounded gate design; unknown in final SDK, entitlement access and signed installed enforcement. This document does not declare native execution available. [Apple platform research](research/apple-platform.md) records exact source and documentation metadata, including the earlier beta label and current macOS 27 DocC metadata drift.

## Three uses, three claims

`observe-v1` records selected OS observations. `native-descendant-v1` is a proposed task execution boundary requiring supported containment plus ES/NE restrictions and complete channel qualification. `managed-endpoint-v1` supplies administrator-selected global restrictions/observations with separate privacy and operational policy. An ES event, an ES allow response and a Chio kernel crossing are different records. Only the original native writer owns positive authority, exact approvals, integrity, budgets and durable stop. A local provider can further deny a previously admitted operation. It cannot turn an executable allowlist or a cached rule into arbitrary future tool authority.

The baseline has no Chio Mac ES provider. The independently checked [Clawdstrike monitor](https://github.com/backbay-labs/clawdstrike/blob/b9515321f4a20bd676dfef88bdf3ba4d015bc6e9/apps/agent/src-tauri/macos/system-extension/endpoint-security/Sources/EndpointSecurityExtension/Monitor.swift#L1055-L1129) is a real `AUTH_OPEN` client with a default allow handler, not a delivered `AUTH_EXEC` or complete task boundary. Reuse follows [Clawdstrike reuse](18-clawdstrike-reuse.md), not an assumption of equivalent authority.

## Scope and launch isolation

Apple's [descendant client](https://developer.apple.com/documentation/endpointsecurity/es_new_descendants_client(_:_:)) is documented for macOS 27. The trusted calling launcher receives notifications; descendants receive authorization and notification events. Existing descendants as well as subsequently created descendants are in scope. Non-descendants are invisible. It needs the restricted ES entitlement, but not root or TCC. Non-root setuid/setgid execution is blocked before execution and produces exit observation instead of an exec event. The [established client](https://developer.apple.com/documentation/endpointsecurity/client) has different entitlement, privilege and TCC requirements.

The research/beta gate remains closed until final SDK headers, runtime behavior, entitlement provisioning and the exact installed OS build are verified. Fresh metadata saying `beta:false` is not that qualification. Compile-time availability, runtime availability, successful client creation, subscribed event coverage and effective denial are separate facts. Preexisting-descendant coverage is not an atomic retroactive sandbox: effects already performed before subscription cannot be recalled. The launcher creates and configures the client before any untrusted child executes, then establishes containment and channel inventory before releasing its start barrier.

The minimal launcher is trusted because caller AUTH coverage is absent. It must not execute task-supplied plugins, constructors, shell commands or build scripts in its own process. It starts a clean environment, closes inherited FDs except a declared private pipe set, removes inherited socket/memory-map access, and excludes task-unrelated Mach/bootstrap/XPC/launchd capabilities. A valid ES subscription does not itself close these channels. Native profile feasibility must demonstrate a supported containment mechanism for each channel; if it cannot, this profile is unavailable. App Sandbox is a candidate for a packaged helper, not proof that arbitrary native CLI execution is safe; [Apple's configuration guidance](https://developer.apple.com/documentation/xcode/configuring-the-macos-app-sandbox) is the supported starting point.

## Coverage inventory

The implementation must compile the following manifest against its exact SDK and record actual subscriptions, mutes and available message fields. An unavailable event or ineffective response refuses any guarantee depending on it.

| Effect family | Candidate ES mechanisms to verify | Independent boundary still required |
| --- | --- | --- |
| Launch/exec | `AUTH_EXEC`, `NOTIFY_EXEC`, `NOTIFY_FORK`, `NOTIFY_EXIT`; exact caller/descendant distinction | Trusted launcher, start barrier, lineage/incarnation binding, injection/service escape tests |
| Acquire file access | `AUTH_OPEN` with flags response; read versus write rights | Existing FD/mmap access, coherent file/resource generation, symlink/rename substitution |
| File mutation | `AUTH_CREATE`, `AUTH_RENAME`, `AUTH_UNLINK`, `AUTH_LINK`, `AUTH_TRUNCATE` where supported | `NOTIFY_WRITE`/close observations are not per-write authorization; preexisting writable handles need containment |
| Executable mappings | `AUTH_MMAP`, `AUTH_MPROTECT` where supported | Shared memory, inherited mappings, runtime code and injection coverage |
| IPC/delegated work | Events actually submitted/instigated by descendants as documented | Mach rights, XPC/launchd services, Apple Events and remote services are not assumed covered by ancestry |
| Network | Selected observations only | [NE transport](09-network-extension.md) and typed effect broker; ES is not universal network semantic mediation |

No semantic operation name is inferred solely from a low-level event. File path, code identity, PID and audit token are observations used with a host-enrolled launch binding, not a capability. Preserve audit token, process incarnation, relevant responsible/parent information, UID and boot/extension epoch. Reparenting never expands positive authority; ambiguous ancestry closes the native task route. For a managed host, unrelated processes follow the separately configured administrator policy.

## Callback, derived restriction and evidence rules

AUTH callbacks use bounded precomputed restrictive state, respond once using the correct flags/auth function, and check the returned response result. No human review, model request, database transaction or unbounded IPC runs in the deadline path. Denial on unavailable/stale/mismatched state must finish inside a qualified safety margin to the message deadline. Asynchronous work retains/releases ES messages correctly and cannot exceed the fixed queue bound. Initial application response caching is off. Clearing OS caches is verified; it is shared across ES clients and can fail or affect neighbors. Muting is explicit coverage loss, not a performance optimization that preserves a complete claim.

[Deadline documentation](https://developer.apple.com/documentation/endpointsecurity/es_message_t/deadline) and the new [deadline mode setter](https://developer.apple.com/documentation/endpointsecurity/es_set_deadline_miss_mode(_:_:)) require distinct tests for ordinary response, late response, queue overflow and client death. Fail-closed mode covers missed authorization and queue-full authorization behavior when successfully configured. It does not document an everlasting gate after the client disconnects. Native execution must retain an independently effective boundary after gate loss or stop before any unguarded effect; a delayed watchdog alone is not proof. The profile is unavailable if this cannot be demonstrated.

Restriction snapshots are authenticated, scoped to installed authority/boot/launch generations, monotonically versioned, policy-bound and bounded by an absolute authority-derived expiry plus a non-extending local elapsed deadline. Older versions cannot replace newer ones; same version with different digest quarantines the task/provider binding. Missing/stale/conflicting state denies selected managed tasks; unrelated host traffic/processes do not inherit a new global policy. All positive semantic admission stays with the current native serving writer. Offline task permits would require a separately specified native delegated authority and are excluded here.

Sensor records carry `sensor_epoch`, OS message version/type, available per-type/global sequence values, time observation, process identity, attempted response/result and explicit gaps. Their event ID is neither kernel crossing order, native operation ID, operator cursor nor stable subscription ID. [Sequence counters](https://developer.apple.com/documentation/endpointsecurity/es_message_t/global_seq_num) detect selected drops, not absolute completeness. [Sync callbacks](https://developer.apple.com/documentation/endpointsecurity/es_sync_client(_:_:)) also run during destruction/null-client cases; they cannot independently prove live drain or effect completion.

| --- | --- | --- |
| AT-MAC-ES-001 | Run the same file probe with observe, descendant candidate and managed mode; remove ES permission where required. | UI/evidence state names exact profile and available controls; observations never receive a confinement verdict; no extra permission is requested for unrelated VM/read-only work. |
| AT-MAC-ES-002 | Compile against pinned final and earlier SDKs, inspect headers and signed entitlements, create client on the exact clean-machine OS; compare archived metadata fetches. | Unsupported tuple refuses before task start; record actual entitlement/client result and API availability separately. Metadata `beta:false` alone never sets qualified. |
| AT-MAC-ES-003 | Insert a task payload before/after the launch barrier, exercise caller and child opens, and create a child before subscription in a lab control. | External file counter shows no untrusted pre-gate effects in product path; caller's NOTIFY-only status is explicit; preexisting child control is not claimed retroactively protected. |
| AT-MAC-ES-004 | Fork, exec, orphan/reparent and rapidly reuse a PID; launch identical Node executables for two runs; invoke an XPC helper on behalf of one. | Incarnation-aware trace keeps runs distinct; no signal or policy reaches reused PID; ambiguous helper causes closed/unqualified result with independent helper effect counter. |
| AT-MAC-ES-005 | Pass preopened file/socket, shared writable map and Mach send right to child; invoke launchd/XPC, Apple Events and Accessibility probes. | Target files/receivers show zero forbidden effects under the proposed native boundary. Any surviving channel explicitly fails qualification even if ES records it. |
| AT-MAC-ES-006 | Execute every manifest operation plus writes via preexisting FD/mmap, symlink/rename substitution and unsupported event/SDK. | Actual file/device state matches each enforcement claim; NOTIFY-only paths are labelled observed and cannot satisfy a veto requirement. |
| AT-MAC-ES-007 | Inject slow UI/model/DB/XPC services while saturating allowed callback rate; attempt duplicate and wrong-function replies. | Monotonic deadline trace and OS return codes show one timely correct response per AUTH; fixed queue/memory bounds hold; slow services never block callback. |
| AT-MAC-ES-008 | Miss a deadline, fill OS/client queues, kill/disconnect/delete client, lose subscription and withdraw permission separately while child probes continuously. | External writes/connects measure actual allowed/denied effects in each window. | AT-MAC-ES-009 | Change rule after a prior allowed open, inject failed cache-clear, mute a required event, and run a second ES client. | Uncached reply records and repeated target operations show current restriction; failed invalidation/muting downgrades coverage; neighboring client behavior is recorded. |
| AT-MAC-ES-010 | Replay older generation, same-version different digest, wrong user/run, expired view, clock rollback and sleep past expiry. | All selected-task probes deny; expiry never extends; unrelated host control continues under its own policy; no approval/budget authority is issued by extension. |
| AT-MAC-ES-011 | Stop during precommitted native effect and after open while keeping writable FD alive; hold restrictive update delivery. | Authority fence, provider convergence and target modification are independent fields. Post-stop release denies; already held write access cannot be falsely reported revoked. |
| AT-MAC-ES-012 | Drop known events, restart client, vary message versions and replay sensor IDs as operation references. | Per-type/global gap counts and unavailable counters are explicit; new epoch prevents continuity fabrication; independent verifier rejects sensor-as-crossing substitution. |
| AT-MAC-ES-013 | Insert sync marker, then destroy client; also pass null client and induce sequence loss before marker. | Callback fires but coverage state stays incomplete/dead as appropriate; only live epoch plus independently checked gaps can establish bounded drain. |

| AT-MAC-ES-015 | Present ES cached/uncached allow without native effect intent; change tool arguments, scope, approval or budget after preflight. | Broker receives no unauthorized effect; extension evidence remains restrictive/sensor class; exact native original operation alone supports authorized dispatch. |
| AT-MAC-ES-016 | Update policy and binaries with active tasks; crash between install/activation; roll back snapshot and sleep/wake. | New native starts wait for fresh compatibility/convergence evidence; old stop/grant state cannot resume work; uncertain in-flight outcomes are retained. |
| AT-MAC-ES-017 | On a clean signed installation, deny a harmless canary read/write/exec, remove the test restriction, and rerun; repeat all native escape/failure cases per tuple. | Independent canary state and process outcomes demonstrate both effective denial and restored allowed operation; no mocked or disabled-security run qualifies a release. |
