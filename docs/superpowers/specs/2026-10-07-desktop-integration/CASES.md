# Cases

Single source for every acceptance case in the native host program. Flows are
defined in [NORTH-STAR-FLOWS](NORTH-STAR-FLOWS.md). A case is executable only
when its owner gate exists; status terms are defined in
[STATUS-GLOSSARY](STATUS-GLOSSARY.md).

Each row condenses the definition in QUALIFICATION (Q), CONSUMERS (C) or
FIRST-CLASS-INTEGRATIONS (H) at commit `620c703d8`; that full text stays the
acceptance detail until the owner's executable case manifest replaces it.
Milestones are HOST-M1 to HOST-M3 (NORTH-STAR-FLOWS sections 3 to 5) and
Platform (section 6). macOS cells of HOST-M2 rows come after the success test
(unified roadmap section 11).

Rules for every row:

- A case is a test obligation in the named owner, not a claim that it passes.
- Pair every negative with a useful positive control; denial-only fails.
- Observe negatives independently of client status and signed claims: the
  real resource, effect counter, private-byte canary, ledger or process census.
- "Applicable" never omits a case silently: the manifest names each
  owner-approved exclusion, and an unclassified case fails.
- C09 and Q24 apply when passports are advertised or required by peer policy,
  C10 and Q25 when recursive authority is exposed, C11 and Q26 when runtime
  swarm admission is exposed, and Q31 wherever time-bounded authority or
  evidence is consumed.
