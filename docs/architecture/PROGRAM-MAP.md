# Native host and kernel program ownership map

Internal design reference, amended 2026-10-08 UTC. Governed by [ADR-0038](../adr/ADR-0038-native-host-program.md) and the [native host contract](../superpowers/specs/2026-10-07-desktop-integration/HOST-CONTRACT.md). Chio is a Rust kernel for agentic operating systems that coordinate work, share resources, and cooperate across organizational boundaries. Applications and agent harnesses consume the existing native owners directly; graphical clients and the optional operator projection are independent consumers. Current composed runtime qualification is not established. Consumer projections are `advisory_only`; `planning_status: ready_after_adr` grants no runtime authority or public release status.

## Deployment, layer and consumer placement

| Profile or layer | Native ownership and acceptance boundary |
| --- | --- |
| Embedded host | Public Rust library/FFI integration at a declared trusted host boundary. P:`src/app/docs/reference/sdk/rust/page.tsx` distinguishes portable decisions, pure evidence verification and host-supplied effects/state. Qualify the chosen ports; portable evaluation is not complete runtime enforcement. |
| User-session host | Existing process/control/resource services bound to one enrolled native user session. Qualify peer/code identity, credential custody, lock/logout, incarnation and restart independently of any graphical client. |
| Service host | Separately enrolled service principal, explicit scopes, persistent state, boot/restart and credential context. Unattended continuation requires its own owner contract. Linger, root, a detached host or launch registration cannot stand in for authorization; platform service/credential gaps remain unavailable until qualified. |
| L0 | S1 closed registry for kernel admission, authority, sessions, receipts and lifecycle; S9/S10 extend native admission/crossing owners. No application plan or dialect-specific workflow becomes a new kernel operation when R11 can lower it to a native tool. |
| L1 | Process identity, operation binding, worker credential, journal and child custody belong to `chio-process` and its host. Its six-op worker protocol is existing candidate source; reconcile the incompatible historical `PROCESS_ABI` v3 definitions before freezing an integrated client tuple. |
| L2 | W1's planned Prepare/Submit/Query facade composes existing D1/S1/native/recovery owners. It cannot create a parallel authority, resource ledger or scheduler. |
| L3 and trusted components | R's implemented seven-command recovery profile and custody/fact-source components remain TCB. A component outside the kernel crate is not necessarily outside the TCB. Planned profile 1.1 and successor retirement are not present in R's inspected enum. |
| Applications and agent harnesses | Planning, assignment strategy, domain acceptance procedure, model/context management and UX stay external. W3's planned installed LangGraph acceptance retains framework-owned planning/checkpoints. Consumers submit proposals; native owners enforce rights and outcomes. |
| Optional operator projection | A bounded C-layer composition for clients that need shared operator views, outside the TCB. It is not L0-L3, a mandatory daemon, a prerequisite for the CLI/SDK or a general harness binding. No frontend may be required for an advertised systems capability unless the selected approval policy independently requires a user interaction. |

S1 sections 4 and 6 require R11 lowering, R12 declared layer descent and explicit seam polarity. `custody` and `fact_source` ports remain in assurance scope regardless of process placement. The foundation, native platform and installed consumer gates apply to each selected profile separately; one profile does not qualify the others.
