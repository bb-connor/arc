## Minimal ordered prerequisites

1. Freeze the ownership map, shared desktop ADR and R1 layer decision now. Record proposed owner amendments beside their source pins, preserving the accepted Rust-kernel positioning. This is planning acceptance, not implementation qualification.
2. Land the selected foundation slice and reconcile actual recovery/process ABIs through the existing owners. Require its exact-source/native/trusted/hosted acceptance. No desktop behavior inherits uncommitted recovery W: assumptions from K.
3. Land the required bug-fix lane: S8 phase 1, S5 Part A, S3 phase 1, and the M20 retry-disposition delta at the existing admission/receipt owners. The last is an owner amendment needed to sequence the review's request without requiring all of S9.
4. Land the operator-contract delta: S4 phases 1-2, S5 Part B (desktop is the second consumer), S28 identity, live process cancel/revoke, deny-clears-approval fix in the host approval owner, and production passkey/approver attribution. Darwin IPC is an additional macOS gate.
5. Qualify recovery's relevant current repairs; implement W1, including W1.0 source reconciliation, W1.5 acceptance and W1.6 original-operation lookup. Pure contract/UI work may proceed while ports remain pending; dependent runtime behavior remains unaccepted.
6. Amend and qualify the selected S7 backend/profile. Start from the existing mini-SWE Docker and Pi restricted session owners; establish launch evidence and effect boundaries before labeling a desktop profile confined.
7. Implement the common controller as an outside-TCB client and adapt the workbench first. Qualify the workbench's inherited findings and existing UI/test suite. Add the Omarchy and macOS presentation clients after the shared client contract works.
8. Deliver sealed work as the first execution product: single-owner unpaid work commitment, fixed recipe, existing kernel-owned execution, review artifact and original acceptance contract. Observe can precede execution; approve/stop needs its operator gates. Protected and boundary interactive profiles follow with their distinct doc 19/S7 gates.

Not mandatory for the first desktop product: NK-01 through NK-03 as complete keystones, all of S9/S10/S1, W2-W4, foundation M11, witness topology, or S11 injection-safety claims. Their absence must remain visible where a later feature depends on them. This is the accepted dependency order for desktop planning, not evidence that the predecessors have passed.
