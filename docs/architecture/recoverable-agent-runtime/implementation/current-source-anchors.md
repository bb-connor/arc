# Historical source anchors and current source names

Observed October 7, 2026. This is a source-only correction, not implementation or runtime qualification. This note routes retained phase references to current source and corrects the meaning of specific advisory claims. It preserves the original phase records, source inventories, commands and results. A source correspondence does not transfer a historical pass to the current implementation or establish runtime qualification.

## Advisory explanation claims

The retained [explanation operations record](p2/OPERATIONS.md) describes its historical implementation. Use these current meanings when reading that record or its [coverage anchors](p2/requirements-coverage.json).

| Retained claim | Current meaning and source |
|---|---|
| Membership work is charged | [Search work](../../../../crates/security/chio-recovery/src/evaluation.rs) charges bounded label operations and fact, template and dominance visits. [Projection visibility](../../../../crates/security/chio-recovery/src/projection.rs) and snapshot/registry normalization do not charge every membership to search work. Label cardinality and input validation have separate structural bounds. |
| `mixed_versions_and_all_truth_assignments_preserve_fail_closed_meaning` proves version changes | [That test](../../../../crates/security/chio-recovery/tests/explanations/basis.rs) varies truth assignments. [original_basis_is_required_even_when_changes_leave_the_advice_identical](../../../../crates/security/chio-recovery/tests/explanations/verification.rs) asserts the original versioned basis even when changed advice remains identical. |
| Advisory liveness observation implements live use revalidation | Explanations observe advisory data. [runtime_acquisition.rs](../../../../crates/kernel/chio-kernel/src/kernel/admission_coordinator/runtime_acquisition.rs) calls the native operation-owned revalidation port declared in [admission_hook.rs](../../../../crates/kernel/chio-runtime-core/src/admission_hook.rs). This is a separate execution boundary. |
| Fact/dependency permutation establishes all canonical orderings | [permutations_are_canonical_without_claiming_store_atomicity](../../../../crates/security/chio-recovery/tests/explanations/basis.rs) now checks all six orders of three templates and reverses fact/dependency order. It establishes canonical pure payloads, not store atomicity. |
| Registered explanation domain implies an active producer | The [current contract catalog](../11-contract-catalog.md) distinguishes the four active explanation payload meanings, the influence meaning and both signature domains from the retained `chio.recovery.explanation.v1` registration. Registration alone does not establish an active producer. |

The old `scripts/tests/check-recovery-p0.test.py::effect_dependency` marker has no identical current test. The current [dependency boundary tests](../../../../scripts/tests/check-recovery-boundaries.test.py), `test_effectful_packages_cannot_hide_in_dependency_tables` and `test_renamed_effectful_dependency_is_checked_by_package_identity`, are distinct successors; their names do not reproduce the old result.
