# P3 execution plan

Phase: semantic remedies, architecture revision 3. Preserve the complete P2
working-tree baseline and historical P1/P2 evidence in `source-baseline.json`.
All 15 P3 obligations remain mandatory. The kernel and its physical serving
store retain native execution, effect truth, capability ceilings and release.

| Task | Deliverable | Obligations |
|---|---|---|
| P3-01 | Closed signed package/deployment contracts, typed selectors, complete channel coverage and immutable registry generations | CON-01, CON-02, CON-03, CON-11 |
| P3-02 | Provider/account/resource recipient binding, complete fresh ACL evidence, explicit annotator powers and retained influence | CON-04, CON-05, CON-06, CON-07 |

| P3-07 | Shared vectors, benign/refusal and state-change cases, restart/integrity evidence, portability, full source review and operating contract | All 15 |

Declare limits before implementation: 16 packages/operations per resolved
generation, 16 selectors and 16 selected plan steps, eight dependencies per step,
eight endorsement assertions and eight transformation fields, 32 observed facts,
4096 pure verification work units, existing 64 KiB bounded wire ingress and
256 KiB protected record/output ceilings. Resolver and effectful transport never
retry or follow redirects implicitly. Mutable ACLs require complete identity and
version/freshness evidence; provider-enforced preconditions are explicit.

The first two native connector families are bounded support reads and issue
creation. Field projection is the first deterministic transform. A held
reservation requires current lease ownership and native consumption. Unsupported
channels, selectors, annotation powers, provider profiles and persistent reusable
artifact endorsements refuse. Persistent artifact authority remains P4.

Package activation verifies complete coverage under separately selected publisher
and operator roots. Failed reload preserves the previous complete generation;
new actions must use the current generation, while original captured work retains
its historical binding. Every step requires its own current capability and exact
materialized inputs. No accepted symbolic plan authorizes unknown future bytes.

New schemas use `https://chio.computer/schemas/`. Existing P1/P2 wire meanings,
request derivations, grant domains, effect ownership and historical evidence
remain unchanged. Acceptance must exercise actual native admission/capture and
release, not promote a pure model or permissive fake to runtime qualification.
Resolve all P0/P1 severity findings in the phase changes before completion and
distinguish local evidence from hosted/provider/platform/scale qualification.
