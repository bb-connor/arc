**Status**: in progress, PR1 verifier-structure slice ready. **Owner**: Lane B (mobile / TEE).

**Tickets**: TRJ4-030 through TRJ4-033.

## Scope

Apple App Attest + Google Play Integrity real verifiers replacing today's `AttestationUnavailable` returns; reproducible-build attestation for the Swift xcframework binary; threat-coverage flip for the three mobile-pending threat rows.

## Acceptance

1. **Apple App Attest real verifier** (TRJ4-030):
   - Lives in `chio-custody-hw/src/attestation/app_attest.rs`.
   - CBOR parse of attestation object.
   - Cert-chain validation against the pinned Apple App Attest root (reuse `apple_root.rs`).
   - Counter monotonicity enforced.
   - Server nonce binding enforced.
   - KeyId binding enforced.
   - `chio-kernel-mobile/src/lib.rs:433` no longer returns `AttestationUnavailable`.
2. **Play Integrity real verifier** (TRJ4-031):
   - Lives in `chio-custody-hw/src/attestation/play_integrity.rs`.
   - JWS validation against Google JWKS with rotation.
   - Audience claim check.
   - Server nonce binding enforced.
   - Verdict verification (e.g. `MEETS_DEVICE_INTEGRITY`).
   - `chio-kernel-mobile/src/lib.rs:454` no longer returns `AttestationUnavailable`.
3. **Real `ChioKernel.xcframework` binary** in `Frameworks/` with reproducible-build attestation (TRJ4-032).
4. **Threat-coverage flip** (TRJ4-033): real conformance tests for `mobile_attestation_replay`, `device_key_extraction`, `play_integrity_token_replay` in `crates/chio-conformance/tests/threats/`. JSON `coverage_state` flips `pending` -> `covered`; `deferred_to: trajectory-4.M07.real-attestation` deferral resolves this trajectory.

## Evidence to capture

### PR1 evidence captured

- TRJ4-030 App Attest verifier structure is live in `crates/chio-custody-hw/src/attestation/app_attest.rs`: production path parses WebAuthn-style CBOR `fmt` / `authData` / `attStmt.x5c`, validates the certificate chain against the pinned Apple App Attestation root with `x509-parser` signature verification, enforces app id hash, key id binding, nonce extension binding, and counter monotonicity. The compact synthetic fixture shape now requires `allow_development_fixture = true` and is not accepted by production callers.
- TRJ4-031 Play Integrity verifier structure is live in `crates/chio-custody-hw/src/attestation/play_integrity.rs`: verifier selects a key by JWS `kid` from caller-supplied JWKS, checks token `alg` against the JWK `alg`, verifies the JWS, requires `aud` and `exp`, enforces nonce, package, app recognition verdict, and device integrity verdict.
- `crates/chio-kernel-mobile/src/lib.rs` no longer returns `AttestationUnavailable` from `attest_app_attest`, `attest_play_integrity`, or `verify_mobile_receipt`. It returns bound challenge envelopes, exposes explicit `verify_app_attest_evidence` and `verify_play_integrity_evidence` FFI entry points, and delegates receipt shape validation to `chio-custody-hw`.
- Deterministic fail-closed tests cover malformed App Attest CBOR, disabled synthetic fixtures, counter rollback, missing x5c, Play Integrity nonce replay, wrong audience, algorithm downgrade, stale token, app rejection, unknown receipt platform, and mobile FFI error mapping.

### Slips / remaining gaps

- Real-device App Attest fixtures from an internal iOS test fleet are not present in-repo. PR1 documents this gap and keeps the production verifier fail-closed on missing x5c / missing nonce extension rather than accepting fixture-only evidence as production.
- Real-device Play Integrity fixtures from Android devices are not present in-repo. PR1 uses deterministic JWKS/JWS fixtures for parser, claim, algorithm, audience, nonce, package, and verdict failures.
- Full `scripts/build-ios-framework.sh` did not complete: the aarch64 iOS cross build failed in `openssl-sys` because no iOS OpenSSL sysroot or `OPENSSL_DIR` / target-specific OpenSSL env vars are configured. The test-only script path passed, but `ChioKernel.xcframework` and reproducible `.intoto.jsonl` remain open for TRJ4-032.
- `cargo test -p chio-kernel-mobile -- --nocapture` still fails before running all mobile tests because `cross_ffi_parity` includes `chio-cpp-kernel-ffi`, whose local match on `CapabilityError` does not handle `CryptoFloorRejected`. This is outside Lane B ownership and was not patched in PR1.
- Threat-model coverage JSON is not flipped in PR1 because TRJ4-033 requires real conformance coverage and the real-device fixture gap remains open.

## Risks / open questions

- Real-device fixtures need real devices; if only one tester has hardware, the negative-conformance suite is bottlenecked.
- Apple App Attest counter rollback semantics need a durable store schema around the now-enforced `previous_counter` input.
- xcframework reproducible build across Xcode toolchain updates is a known fragility; pin Xcode version in CI and provision cross-target OpenSSL or remove the OpenSSL dependency from the mobile staticlib graph.
